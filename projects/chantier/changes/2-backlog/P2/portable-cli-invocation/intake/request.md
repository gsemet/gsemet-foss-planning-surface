# Use a portable shell invocation for the CLI

Owner, 2026-11-13 (from markdown-okf-schema-studio batch-03): « Pour zsh, trouve une syntaxe générique qui marchera partout ». Problem: the cards write $CHANTIER for 'uv run --script "<skill>/scripts/cli/chantier.py"'; agents put that whole command in one shell variable (C="uv run --script <path>"; $C status), which bash splits into words but zsh does not ('command not found'). Seen twice in batch-03 (the Chief of Staff and the release driver's retro). Proposal, tested 2026-11-13 in bash, zsh, sh and dash: keep only the script path in a variable and always quote it: CHANTIER_CLI="<skill>/scripts/cli/chantier.py" then uv run --script "$CHANTIER_CLI" <command> (PowerShell: $CHANTIER_CLI = "…"; uv run --script $CHANTIER_CLI <command>, not tested here). The cards, the take/round/handoff 'cli:' line and the prompts give that form; never a whole command in one variable. Note: each Bash tool call is a fresh shell, so the variable is set in the same call.
