# Redefine the factory mode: running batch or next batch

The user, 2026-11-21, while grilling park-live-cr (answer park-live-Q8), verbatim: "Le mode factory doit prendre les 1-pending automatiquement. Et donc quand on a un batch en mode factory, on peut passer une CR prête directement dans 1-pending, et donc 3-ready reste toujours pour le prochain batch. Il faut donc cette possibilité dans les règles du grill quand le batch est en factory, prochain batch ou batch en cours. Aussi dans la UI, dans la page backlog, il faut une division horizontale de la dernière colonne (comme Jira) pour pouvoir dire soit dans le batch en cours ou dans le prochain (met ça tout le temps, même en mode séries ou parallel on peut avoir envie de mettre dans le batch en cours). En fait ça a des impacts sur la définition du mode factory, reprenons la définition à zéro, stp."

In English: a factory batch takes the CRs of `4-batch/1-pending/` on its own; a CR made ready can go straight to `1-pending` (the running batch) or to `3-ready` (always the next batch); the grill offers both; the board's backlog page splits its last column into "running batch" and "next batch", in every mode. Redefine the factory mode from zero.
