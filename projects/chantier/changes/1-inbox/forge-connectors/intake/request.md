# Forge connectors as plugins, polling only what is awaited

Forge connectors as plugins: monitoring a forge needs polling, but with a registry of who is interested so the poll reads only what someone waits for (a typed wait is such an interest); events on issues come from an outside poller that writes into the journal; a plugin system makes adding a connector (GitHub, GitLab, Jira, others) easy. The user's words (2026-11-20, in planning-server's grill, answer planning-server-Q24): 'Pour le monitoring sur les forge il faudra nécessairement faire du polling mais il faut une système pour savoir qui est intéressé. Pour les d'événements sur les issues je penses que je ferais un polling extérieur. Il faudra un système de plugin pour facilement rajouter des connecteurs'. Typed waits (1-inbox/typed-waits) depend on it.
