# Change Specification: `chantier board` becomes the web board's server

## Goal

The user's words (2026-11-12): a visualization backend beside the Claude Code mod, which does not
show in remote. Today's `chantier board` "works very well on the same PC as Claude, but not from
another PC or Mac on the same network, nor from the phone".

This CR is **board-server**, CR 1 of the five the user split the work into ("Split into CRs").
At its end, `chantier board` is the web board's server:

- it serves a JSON API that reads the record and the planning folder's files;
- it serves one project, or every project of a multi-project planning surface;
- it is reached on the local network through a URL with a random part, which the CLI prints and
  the Chief of Staff gives in the chat;
- its page refreshes live, and costs are recomputed in memory at worst every 5 minutes while a
  page looks at them;
- it serves the page's frame (sidebar, header, phone bottom bar, the design tokens) as
  hand-written HTML, CSS and native ES modules, on which the next CRs build the views.

`AGENTS.md` changes accordingly: the board may write the backlog through the CLI's role-free
commands, and the server is the CLI's named git exception.

The prototype in this folder (`prototype/`, screenshots `evidence/prototype/v6-*`) is the
reference of all five CRs: "the same thing at the end". This CR keeps it, as it is.

## What changes

### 1. Dependencies

- `skills/chantier/scripts/cli/chantier.py`'s PEP 723 block gains `starlette` and `uvicorn`
  (without extras: pure Python, with `h11`, `anyio`, `click`, `idna`). The lock
  (`chantier.py.lock`) and `pyproject.toml`'s `[project] dependencies` follow, as
  `python-inline-deps` requires; its test that the two lists agree stays green.
- Measured on 2026-11-13, Windows, uv 0.13.6, `UV_NO_BUILD=1`: `starlette` 1.10.0, `uvicorn` 0.54.0,
  `anyio` 4.16.0, `h11` 0.16.0, `click` 8.5.1, `idna` 3.20 install from wheels alone on CPython
  3.15 and 3.11. Importing `starlette.applications`, `starlette.routing`, `starlette.responses` and
  `uvicorn` takes 0.21 to 0.22 s warm on both.
- They are imported only when `board` runs, never by another command, and declared as lazy
  imports the way `python-inline-deps` declares `ruamel.yaml` and `psutil`. `chantier --version`
  and `chantier status` keep their start-up time (evidence E8).
- The interface takes no dependency: no npm package, no CDN, no font download, nothing fetched
  from outside the server.

### 2. The command

`chantier board` keeps its name, its exit codes and its options, with these changes (in its
`register(sub)`, `board/command.py`):

| Option | Today | After |
| --- | --- | --- |
| `--host` | default `chantier.yaml`'s `board.host`, else `127.0.0.1` | default `board.host`, else `0.0.0.0` (the local network) |
| `--port` | 1 to 65535, default `board.port`, else 8765 | the same, and `0`: a free port the system picks, printed in the start line |
| `--seat SESSION` | the board stops when the seat no longer names it | the board follows a set of seats (see "Seats") |
| `--project NAME` | the project's folder of a surface | on a surface, the project of `--seat`, and the project the start URL opens on; the board serves the whole surface |
| `--clock TIMESTAMP` | none | new: the server answers as if it were this instant (UTC, `YYYY-MM-DDTHH:MM:SSZ`), for screenshots and tests; its help says so |
| `--new-key` | none | new: replace the board's key (see "Access"); the old URL stops working |

Its help line becomes: "serve the web board (the record, the planning folder's files, the
backlog) on this machine and the local network, behind a key in its URL".

`chantier.yaml`'s `board:` key keeps `host` and `port` and their messages
(`playbook/config.py`). The planning folder served is found as today (`Repo.find`, so
`CHANTIER_ROOT` or the working folder), except that a surface with several projects is no longer
a `SurfaceChoice` error for `board`: it is served whole.

### 3. Access: the key in the URL

- **The key.** 32 bytes from `secrets.token_urlsafe`, created at the first start and kept in a
  file of the served repository's git folder: `<git common dir>/chantier/board.json`
  (`{"key": "…", "created": "…"}`), written by atomic write. That folder is the planning
  surface's own in external mode, the project's in-project. It is never in a working tree, never
  pushed, shared by the worktrees, and readable by the machine's user. The same key serves every
  later start, so the URL the user saved stays good across sessions; `--new-key` replaces it.
- **The URL.** `http://<address>:<port>/?k=<key>`. The address is the one the user can reach:
  the `--host` given when it is a specific address; for `0.0.0.0` or `::`, the machine's address
  on the network of its default route (found with a UDP socket `connect`, which sends nothing),
  else `127.0.0.1` when the machine has no network.
- **The exchange.** A request with a good `k` gets a cookie `chantier_board` (the key, `HttpOnly`,
  `SameSite=Strict`, `Path=/`, one year) and a `303` to the same path without `k`, so the key
  leaves the address bar. Every route but the probe (below) then needs the cookie, or the header
  `X-Chantier-Board-Key` (for scripts, the scenario and the probe). The compare is
  `hmac.compare_digest`. A request without a good key gets `401` with a one-line plain text:
  "this board needs the link with its key: ask the Chief of Staff for it". No route says whether
  a board exists behind the port without the key.
- **What the key guards.** Every read and every write. The planning folder holds requests,
  grills and logs; the board listens on the local network.
- **Requests that change something** (here only `POST …/costs/recompute`; `board-backlog-edit`
  adds the backlog writes): besides the key, they are refused (`403`) unless `Sec-Fetch-Site` is
  `same-origin` or absent and `Origin`, when present, is the board's own; the body, when there is
  one, is `application/json`. Any other method answers `405`.
- **Headers** on every answer: `Cache-Control: no-store` (except the frame's static files:
  `no-cache` with an `ETag`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
  and on HTML `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self';
  img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors
  'none'`. No inline script or style anywhere: the page sets sizes through the CSSOM
  (`element.style.width = …`), which the policy allows.
- **Plain HTTP.** No TLS: on the LAN the key can be read on the wire; over Tailscale it cannot.
  The docs say so (see "Docs").

### 4. The start lines

The first line keeps its shape, now with the URL and its key:

```
board on http://192.168.1.20:8765/?k=<key> over <served folder>
```

`<served folder>` is the planning folder in-project, the surface's root on a surface. A second
line follows only when the address is beyond this machine:

```
board: listens on the local network (0.0.0.0); the link holds its key: give it to the user only, plain HTTP
```

A run that finds its own board already serving the same folder on the address prints `board
already running at <the same URL>` and exits 0, after it added its seat (see "Seats"). The
refusals keep their words and exit code 4: `error: board not started: <reason>` (a port held by
another program, no planning folder).

The probe of an existing board (today `_probe` on `/api/status`) becomes `GET /api/board` on the
loopback with `X-Chantier-Board-Key` read from the key file: a chantier board over the same
served folder answers it; anything else is "another program holds the port".

### 5. Seats

- `--seat` registers a seat with the board: on a surface, the pair (project of `--project`,
  session); in-project, the session alone.
- A later `board --seat` that finds a board over the same served folder adds its seat to it
  (`POST /api/seats`, `{"project": …, "session": …}`, with the key header) and prints `board
  already running at …`.
- The board stops (exit 0) when none of its seats is still named by its project's `seat.json`
  (`core/seat.py`), checked at least every 10 s and at each request, as today. An unreadable seat
  file counts as held, as today.
- A board started with no `--seat` (by hand) stops only on Ctrl-C.
- Since the key is kept, a board that stopped and starts again has the same URL.

### 6. Projects

- **In-project** (`.agents/changes/` of the repository): one project, named after the
  repository's folder (`project_name` today). `GET /api/board` says `"surface": false`; the frame
  then shows no project picker and no "All projects".
- **A planning surface**: every project of `core/repo.surface_projects`, each read through its own
  `Repo` (built once at start and again when the list of projects changes; `Repo._external` runs
  `git` twice per project), each with its own `seat.json`, batch and backlog. `GET /api/board`
  says `"surface": true` and lists them.
- A project steered on another machine has no `batch.json` here (it is never pushed): its line
  shows its backlog and last merged CRs, no batch and no cost.
- The project's id in every URL is its folder's name under `projects/` (in-project: the
  repository folder's name). A request for an unknown id answers `404`.

### 7. The JSON API

All JSON is UTF-8, `application/json; charset=utf-8`. Every answer carries `"now"`, the
server's instant (`core/clock.now()`, or `--clock`): the page computes every age against it,
never against the device's clock. Times are the record's (`YYYY-MM-DDTHH:MM:SSZ`). The API reads
only; nothing in this section writes a file.

| Route | What it answers |
| --- | --- |
| `GET /api/board` | `board: true`, `version` (the CLI's), `surface`, `served` (the served folder, POSIX), `seats` (count only), and `projects`: one line per project (below) |
| `GET /api/projects/{id}/state` | the project's state (below), with an `ETag` |
| `GET /api/projects/{id}/tree?path=<folder>` | every file under a folder of the planning folder, recursively |
| `GET /api/projects/{id}/file?path=<file>` | one file's bytes |
| `GET /api/projects/{id}/costs` | the recorded figures and the live computation (see "Costs") |
| `POST /api/projects/{id}/costs/recompute` | start a live computation now; `202` |
| `POST /api/seats` | add a seat (see "Seats") |

`/`, `/api/status` and `/file` of today's board go: `/` now serves the frame (see "The frame"),
the rest is above.

**A project's line** (`GET /api/board`), what the picker and "All projects" draw (prototype:
`PROJECTS`, `allProjects`, `pmenu`; screenshots `v6-01`, `v6-03`, `v6-04`, `v6-05`, `v6-16`,
`v6-17`): `id`, `batch` (`id`, `state`, `mode`, `steering`, or `null`), `running` (the dot),
`working`, `blocked`, `to_review` (each `{cr, title, pr}`, as defined below), `merged` and `total`
(the batch's CRs, merged out of all), `spent_usd`, `budget_usd`, `unpriced`, `inbox` and `backlog`
counts (`2-backlog/P1…P4`), and the two honest ages: `cost_at` (the last `cost` event) and
`heartbeat` (with `heartbeat_stopped`). The prototype's "data's age" (the snapshot's age) has no
live meaning: the "Données" column shows `cost_at`'s age in `board-read-views`.

**A project's state** (`GET /api/projects/{id}/state`). It is computed from the record as
`collect()` does today, from `dashboard_view`, `batch_view`, `batch.json` and `events.jsonl`, plus
the fields the views need that are in no view today. Those are added to the board's own data
only, never to `STATUS.json`: the pane's schema and `AGENTS.md`'s screenshot rule are not touched.

- `project`, `surface`, `seat` (`title` and `env` only; no session id).
- `batch` (or `null`): `id`, `state`, `mode`, `steering`, `created`, `default_branch`,
  `max_rounds`, `slots` (`taken`, `total`), `spent_usd`, `budget_usd`, `unpriced`, `priced`,
  `heartbeat`, `heartbeat_stopped`, `asks_unread`, `orders_pending`, `cost_at`.
- `batch.crs`: every CR of the batch, merged and cancelled included (prototype `snapshot.py`
  takes them all from `batch.json`): `cr`, `title` (`subject()` strips "Change Specification: "),
  `folder` (where the folder is now, `3-done/` or `5-archives/` included), `state`, `label`,
  `severity`, `round`, `round_limit` (the CR's own, else the batch's `max_rounds`: never a fixed 3),
  `cost_usd`, `cost_unpriced`, `pr` (only an `http(s)` URL is a link, as `_url_link` today),
  `blocked`, `waits` (a queued CR held by its dependencies "waits", orange), `kind` (`fix`,
  `release` or none), `order`, `stacked`, `after`, `merged_at`, `handed_back_at` (the `t` of its
  last `handback` with `result: "ready"`), `files` (count), `description` (below).
- **Derived by the server, with chantier's meanings ("Semantics fixed")**, so no view computes
  them:
  - `chain_place`: the CR's place in the stack or series, counted from the bottom, from
    `commands/facts.chain` (the release on top; a fix outside, `null`).
  - `base`: the PR's base, `{"on": <CR id or default branch>, "why": "stack" | "series" |
    "dependency" | "default" | "planned"}`: its place in the stack once stacked (else where
    `stack_base(planned=True)` puts it), the previous CR of a series, else its last open
    dependency (`after`), else the default branch.
  - `to_review`: `true` only when the CR is handed back `ready` and its PR's base is the default
    branch. A stack's PRs stay drafts: the server reads nothing from the forge (as `status.py`),
    and no stack-verified flag is recorded (open point 6).
  - `merge_order` for the "PRs to review" column: a stack's chain from its top (the numbers are
    places, not a merge order); a series' order; in parallel, by `handed_back_at`.
- `events`: the last 40 of `events.jsonl` of kinds `open`, `add`, `take`, `round`, `gate`,
  `verdict`, `ship`, `handback`, `ask`, `order`, `pause`, `note`, each with `t`, `actor`, `kind`,
  `cr`, `result`, `pr`, `note`, `order_kind`, `reason`, `command`, `round` when present. A
  hand-back's word is `result`; a merge is an `order` with `order_kind: "merged"`.
- `backlog`: every item of `1-inbox`, `2-backlog/P1…P4` and `3-ready`, keyed by the record's own
  `priority` value (`inbox`, `P1`…`P4`, `3-ready`: never `ready`), each with `item`, `title`,
  `folder`, `files` (count), `depends` (its `depends.json`'s `after`, if any), `description`, and
  `grill`: `raw` (the request only), `grill` (`02-answers.md`, no specification), `specifying`
  (the `work/specifying` marker, `status.spec_state`), `specified` (`03-change-spec.md`) or
  `automatable` (in `3-ready` with no `03-change-spec.md`, the rule of `lifecycle.prepared_cr`).
- `description`: the first paragraph of `03-change-spec.md`, else `01-intent.md`, else the first
  Markdown file, that is not a heading or an `issue:` line, its Markdown marks removed, cut at 300
  characters (prototype `firstPara`). `cr-summaries` later puts its summary beside it.
- `merged` (the last 50, `cr`, `title`, `batch`, `pr`, `cost_usd`, `when`, `path`) and
  `merged_total`; `trashed` and `trashed_total`, as `dashboard_view` gives them.
- `history`: the parsed `5-archives/batches/batch-*.json` files, newest first, passed as they are,
  when that folder exists (`batch-history` writes them); else `[]`. Showing it is a view's.

**Files** (`tree`, `file`). A CR is a folder whose files are not known in advance:

- `tree` lists every file under `path` (a folder of the planning folder), recursively, sorted,
  each `{path, size, kind}`, `kind` being `text` (by extension: the prototype's `TEXT` set, `.md`,
  `.json`, `.jsonl`, `.txt`, `.log`, `.yml`, `.yaml`, `.patch`, `.diff`, `.csv`, `.html`, `.py`,
  `.sh`, `.toml`, `.js`, `.css`, `.ts`, `.tsx`), `image` (`.png`, `.jpg`, `.jpeg`, `.gif`,
  `.webp`) or `other`.
- `file` answers a text file as `text/plain; charset=utf-8` (an `.html`, `.js` or `.svg` file is
  text, never a document or an image that runs), cut at 1 MB with the header `X-Chantier-Cut:
  1`; an image with its own type, up to 5 MB; anything else, or anything larger, as
  `application/octet-stream` with `Content-Disposition: attachment`.
- A path is confined as `_inside` does today: no absolute path, no drive, no NUL, resolved inside
  the project's planning folder, symlinks out refused: `404`. On a surface, a project's routes
  reach its own `changes/` only, never another project's through `..`, nor the code clone.
- The ignored local files of a running batch stay readable, as today (open point 4), except the
  locks (`.lock`, `.lifecycle.lock`, `.long-gate.*`), which `tree` leaves out and `file` refuses.

### 8. Live refresh

- The page asks `GET /api/projects/{id}/state` every 5 s while it is visible (and at once when it
  becomes visible again), with `If-None-Match`. The server answers `304` while the project's
  fingerprint is unchanged.
- The fingerprint is the size and modification time of `batch.json`, `events.jsonl`, each
  `seat.json` and every file under the stage folders the state reads (a `stat` walk, no read), and
  the live cost's time. The server keeps the last state per project with its fingerprint, so a
  `304` reads no file.
- The frame shows when the page last heard from the server. After two failed asks in a row it
  says the board is not answering (stopped, or the network), and keeps the last data on screen.
- Wall times for this repository's planning folder (a `304`, a full state, a `tree` of this CR's
  folder) are measured on the Windows machine and reported in the PR (E7); no threshold is set
  (open point 8).

### 9. Costs

The board never records a cost: recording writes `batch.json`, which is the batch's, and the
board does not edit the batch ("Editing is the backlog only").

- `GET /api/projects/{id}/costs`: `recorded` (`spent_usd`, `budget_usd`, `unpriced`, per-CR
  `cost_usd`, and `at`, the `t` of the last `cost` event, the figure `status --refresh` and
  `pause` record) and `live` (`null`, or `spent_usd`, `unpriced`, `per_cr`, `at`, `computing`,
  `error`).
- The live figure is computed in memory the way `chantier cost --by cr` does
  (`commands/cost/…`: `cost_rows`, then `cost_groups(by="cr")`), in a background thread, one at
  a time per project. The page labels it "computed at HH:MM, not recorded" (`board-read-views`).
- **The 5-minute rule.** When a page asks for a running batch's `state` or `costs` and the live
  figure is missing or older than 5 minutes, the server starts a computation and answers at once
  with what it has (`computing: true`). Nothing is computed while no page looks.
- `POST …/costs/recompute` starts one now ("Recompute", no agent turn); a second while one runs
  changes nothing and answers `202` too.
- With no transcript found (another machine, the docs' demo), or a pricing failure (a Copilot
  batch prices through `uv` and the network), `live.error` says why in one line and the recorded
  figures stand, unchanged.

### 11. The frame (hand-written HTML, CSS, ES modules)

Under `board/web/`, no compiler, no bundler, no framework, loaded by the browser as they are:

- `index.html`: the frame's markup only; one `<script type="module" src="js/main.js">`; no inline
  script, style or event attribute.
- `css/tokens.css` (the palette, the state tints, type, spacing, radii), `css/frame.css`
  (sidebar, header, bottom bar, the PC and phone breakpoints), `css/components.css` (tags,
  buttons, cards' edge-or-shadow rule, tables, the panel's shell). Every colour is a custom
  property of `tokens.css`. The values are the prototype's after the Impeccable pass
  (`prototype/index.html`'s `:root` and rules): secondary text `#666b78`, no text under 12px
  (badges 11px excepted, as the prototype), the platform's UI face (Segoe UI Variable on Windows,
  the system face elsewhere) with tabular figures, the selection, focus ring, thin scrollbars and
  link underlines in the palette, and the state tints of "Card style": blue working, red blocked,

## Open points (defaults taken; the Chief of Staff takes them to the user)

1. **The interface's language.** Default: English, as `AGENTS.md` requires of repository text;
   the prototype is French. The final QA counts the language as an intended difference. The
   alternative is French labels, against the rule.
2. **A JavaScript and CSS linter.** Default: the measurable targets in a Python test, the rest in
   review, no new tool. A real linter (Biome, ESLint) needs Node or a binary outside uv, just and
   git, and CI has no Node.
3. **Listening on the local network by default.** Default: `0.0.0.0` with the key, since the
   user wants the link to work from the phone with no setup; `board.host: 127.0.0.1` keeps it on
   the machine. On Windows the first listen meets the system firewall's prompt. The alternative
   keeps `127.0.0.1` and asks the user to set the address once, as today.
4. **What the key opens.** Default: every route, reads included, and every file of the planning
   folder but the locks, `seat.json` and the gate logs included, as today's board. The
   alternative hides `seat.json` and `work/gates/` from the board.
5. **Where the key lives.** Default: `<git common dir>/chantier/board.json`, kept across starts
   so the link stays good; `--new-key` replaces it. This adds one place chantier writes outside
   the planning folder (an `AGENTS.md` edit). The alternatives: a key new at each start, held in
   memory only (no file, a new link at each session), or an ignored file in the planning folder
   (none exists at a surface's root).
6. **"To review" in a stack.** Default: a stack's PRs stay drafts on the board, because nothing
   records that the stack is verified on the forge and the server reads nothing from it. The
   alternative records the verification (`forge-stack show`) in `batch.json`: a CLI change for
   another CR.
7. **Seats on a surface.** Default: the board follows every seat that registered, and stops when
   none holds. The alternative keeps today's single seat, so a surface board stops when its first
   Chief of Staff leaves, until the next one starts it again.
8. **Wall-time targets.** Default: measured and reported (E7, E8), no threshold.
9. **"The `chantier:board` skill stays beside it" (Scope answers 4).** No skill of that name
   exists; read as the Claude Code mod's pane and `/chantier-board`, unchanged.
10. **The 5-minute rule's trigger.** Default: a page asking for a running batch's state or costs
    starts a computation when the live figure is older than 5 minutes; no page, no computation.
    The alternative computes every 5 minutes while the board runs, whoever looks.
11. **The history route.** Default: `history` passes `5-archives/batches/batch-*.json` through as
    they are, so this CR does not wait for `batch-history`; which view shows it is not decided
    (`board-read-views` is the default).
