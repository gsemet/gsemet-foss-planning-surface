## What changed (tests/ only)
- `stack_world.py` (new, a pytest plugin listed in conftest's `pytest_plugins`): `stack_of(Batch(...), repo, chantier, monkeypatch)`.
  A batch (opened, CRs taken, worktrees added) is built once per run by the first test that asks (shared across xdist
  workers with `shared_state`), copied for the others; the record, STATUS files and git's worktree links
  (`.git/worktrees/*/gitdir`, `<wt>/.git`) are rewritten to the copy's folder (plain, slash and JSON-escaped forms), the
  lease numbers `held` are restored, env `CHANTIER_BATCH` set. The result does not depend on the template folder
  (the builder's own test runs in place, every other one runs on a repaired copy).
- `test_carry_ship.py`: `stack`, `stack3` use it. `test_batch_end.py`: `started` uses it (one template per count/took/flags).
  `test_board_prs.py` `served` (also used by the other board_prs files, test_server_api) and `test_leases.py` `leased` use it
  (no worktrees; leases is frozen at T0 so the template's lease stays valid; the fixture's `lease 1 until 00:10:00` check
  is kept as a check of the record's lease).
- `test_gate_carry.py`: the `shape` repository is built once per run, copied per test (no absolute path in it).
- `test_release_tag.py`: origin, work and other clone built once per run, copied per test with `origin` url re-pointed;
  `test_ff_main` setups went from about 9 git processes to 0 (the test's own commits and push stay real git).
- Not done, with reason: test_surface_writes, test_store_command_table, test_order_drop_to, test_forge_hub(_waits): their
  setups are now small (1 to 7 s summed, the 5.7 s being one worker waiting for the shared `states` build) and they spawn no
  git (the hub runs none); nothing to remove without a weaker test. test_gate_refusals, test_verdict_note,
  test_external_archive each add one worktree per test (1 s setups): left.
