## Left open / notes

- The scenario's Windows `.cmd` wrapper passes `%*` to cmd, which breaks on `&` in an argument: the
  list of open MRs is therefore asked with `-f state=... -f target_branch=...` and `--method GET`
  (glab turns `-f` into a query string on GET), not with `?a=b&c=d` in the path. Unproved on a real glab.
- Check 2 ignores the release's source branch (check 5 reports MRs targeting it), so a foreign MR on the
  release branch gives one `check 5` line, not two.
- On `create`, the read-back lines follow the chain line, so `create` can exit 2 with a check line
  (e.g. a wrong draft state); GitHub's `create` reads nothing back.
- Docs/README/SVG sentences on GitLab stacks are out of scope (as the spec says).
