# CR-491 round 2

## Diagnosis

The refused keys came from `card_names`: a PowerShell call that reads several cards in one command
(`Get-Content <a>,<b>,...`) matched the first `skills/chantier/references/` and its path class
included the comma, so the key swallowed the following comma-joined paths (shape: `<card>,<home
path>/skills/chantier/references/<card>,...`), a home path with it. Globs (`hosts/*.md`) and `$env:`
forms gave raw tails too. Four shapes in all, all from PowerShell calls.

## Changes (evals/kit/behaviour.py, dry_run.py, behaviour-fixture/leak)

1. `CARD` stops at `,`, `*`, `?`. New `safe_card`: a key is kept only as `references/`, `brief`,
   `SKILL.md:<known skill>`, or words of `[A-Za-z0-9._-]` joined by `/`; anything else is
   `other-card`. `card_names` returns only safe keys.
2. Help topic must fit `[a-z][a-z0-9-]*`, else `other`. `template()` (refusals, usage errors) now also:
   replaces the login name by `<user>`; turns any relative path (`a/b`, `a\b`) into `<path>`; keeps only the
   `--flags` of an `unrecognized arguments:` tail (the rest `<v>`, runs collapsed to `<v>...`); masks the
   project list of `this is a planning surface with projects ...:`; cuts a `could not apply <sha>...`
   subject; masks `« ... »` quotes, a UUID and a `<slug> is not ...` subject. Tool names of
   `tool_not_in_list` stay `\w+` (left raw on purpose: the guard still covers them).
3. Fixture: the leak case now leaks through a tool name (`No such tool available: fixtureuser`), since
   templates are scrubbed; it expects `tool_not_in_list` named in the refusal. New dry-run check 5b: a
   comma-joined list, a glob, a plugin-cache path and a `$env:` path give only `a.md`, `other-card`,
   `foreman.md`, `other-card`.

relative CR folder paths with a CR slug (about 130 lines), branch names with a slug, free text of a
