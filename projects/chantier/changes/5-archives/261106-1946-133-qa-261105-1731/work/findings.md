# Findings (chantier 0.4.1 at origin/main 6b288e6, throwaway repo, Windows)

- **`file` of an existing slug exits 3.** Steps: `chantier file "Export the report as CSV"` twice. Expected: exit 1 or 2 (concepts.md: 3 = stale Foreman epoch). Actual: `error: CR folder already exists ...; choose another slug`, exit 3. (The message also does not name `--slug`.)
- **`triage` cannot re-prioritise a backlog CR, and its error misleads.** Steps: `triage .agents/changes/2-backlog/P2/dark --priority P3`. Expected: moved to P3 (docs/use-cases.md "Make it a P2" implies the user sets priorities freely), or a clear "only inbox CRs". Actual: `... is not directly inside ...\1-inbox`, exit 1. A bare name (`triage dark`) gives the same error with a cwd-resolved path; no hint that a full path is needed.
- **`order drop` is not idempotent and reports a second drop as done.** Steps: `order drop CR-101` twice. Expected: second says already dropped / refused. Actual: new order O-6, `dropped CR-101: <same trash path>`, exit 0. Also `order drop 101` fails (`unknown CR 101`) while the CR is shown as `CR-101`; `order add` prints `CR-102` - the accepted form is only learnt by trying.
- **Orders the CLI already executed stay "pending".** After `order drop CR-102` (CR moved to trash at once), `status` still lists `O-4 drop CR-102` under "orders pending", and `land` is refused because of them. With no Foreman running, a new user cannot tell finished from waiting. docs/use-cases.md says `status` shows an order "until it is done", so it is consistent, but the output says "dropped" immediately.
- **Status vocabulary: dropped CRs show as `cancelled`**, while docs/use-cases.md says the folder goes to `5-trash/` ("drop"). Also `order note CR-102` is accepted on an already cancelled CR, and `order merged CR-101` on it errs with exit 2 (fine).
- **Error texts for `order` are wrong or vague.** `order rounds --note 0` prints `order rounds <cr>` (the help says the number goes in --note; the CR is also needed, but the usage line shows no number). `order budget --note -5` prints only `order budget --note <usd>`, not why -5 is refused. `order add` without `--note` was not the issue, but `order add` / `drop` need `--batch` when several batches exist, only learnt from `-h`.
- **`order add` on a CR without a spec: `open` says `grill the CR first`, fine, but `order qa` creates `1-inbox/qa-<date>` that `open` then also refuses** (`missing Change Specification`), consistent with docs but the message gives no hint that QA folders are not meant to be opened.
- **`cost` and `close` unusable on a fresh batch.** `cost` (any form) fails exit 2: `no Foreman transcript recorded: the Foreman runs chantier foreman transcript $CLAUDE_CODE_SESSION_ID`, whereas docs/use-cases.md "Know what it costs" suggests `cost` simply works; a $0 line would be less alarming. `close` says `landed: none` with no pointer to `land`; `land` fails listing pending orders O-1..O-8 and says nothing on how to clear them without a Foreman. So the whole file/triage/open/order/cost/close path cannot be completed by the CLI alone (expected by design, but undocumented in use-cases.md).
- **`open` output is cryptic**: `CR-101 spec` then a `brief:` path; the line does not say the folder moved from backlog to `3-requests/01-b1/101-...` nor what to do next.
