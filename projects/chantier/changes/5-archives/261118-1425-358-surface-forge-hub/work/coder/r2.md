## Points that differ from the brief

- "A's batch paused": `pause` is refused while a CR is not merged or cancelled, so A's batch is ended
  the CLI's way (`order merged` for three CRs, `order drop` for the red CR and the last one), which
  pauses it. The PR merged after the pause is the dropped last CR's.
- `hub.json`'s PID is checked as one stable PID of a process other than the watcher's launcher: on
  Windows the venv launcher forks the real Python, so `Popen.pid` is not the recorded PID. B taking
  the lock is checked as the PID changing while B's watcher is alive (only B is left).
- A cancelled CR's PR is not read by the hub whatever the pause, so the post-pause check rests on
  the running-batch rule; the pytest suite holds the finer cases.
