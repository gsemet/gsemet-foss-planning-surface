## 5. Arrow geometry and why the head floats

`js/views/batch-graph.js::path(graph, from, to)`: it measures with `getBoundingClientRect` relative to `.graph`: start `x1 = from.right`, `y1 = mid-height`; end `x2 = to.left`, `y2 = mid-height`; cubic `M x1,y1 C mid,y1 mid,y2 x2-6,y2` with `mid = (x1+x2)/2`; `marker-end="url(#ar)"` with the marker `viewBox 0 0 10 10 refX=8 refY=5 markerWidth=7 markerHeight=7 orient=auto`, `markerUnits` default `strokeWidth` (stroke 1.4, hover 2). `drawEdges` redraws after each paint (`mount`'s `after`) and on window `resize` only (`batch.js` lines 48-60).
Why the head floats (analysis, not reproduced in a browser):
1. The path stops 6px before the card and the marker's tip (x=10, refX=8) lands 2 units past the end, so the tip stops about 4px short of the card, never on its edge.
2. `orient=auto` takes the tangent at the path's last point: the last control point is `(mid, y2)`, so the tangent is horizontal at the very end, however steep the line is just before it. With the 90px column gap (50px on a phone) and a large vertical distance between source and target, an S-curve comes in steeply from above or below and only flattens in the final few pixels: the head points right while the visible line comes diagonally from below, which is what the user saw on CR-321.
3. `markerUnits=strokeWidth` makes the head grow from 1.4 to 2 times on hover (the arrow's `hl` class), so the tip moves.
4. A moved node leaves a stale arrow: Inter loads with `font-display: swap` after the first paint and changes text widths and node heights; the arrows are measured before that and only redrawn on `resize`. After this CR the badge and the two-tone band also change heights.
Smallest fix: end the line at the card's edge with a short horizontal final segment: `M x1,y1 C mid,y1 mid,y2 x2-12,y2 L x2,y2`, marker `refX=10` (tip on the path end), `markerUnits="userSpaceOnUse"` with fixed size (about 8px) so hover does not scale it, and `drawEdges` also called from `document.fonts.ready.then(...)` in `mount` (and from a `ResizeObserver` on `.graph` if a font swap after mount still shows). If the target is not strictly right of the source (levels guarantee `x2 > x1` today), no change needed. The Coder must first reproduce with the batch-23 record shape (CR-321 `after: [CR-319]`, in level 2 while level 1 is taller) in the demo copy.
