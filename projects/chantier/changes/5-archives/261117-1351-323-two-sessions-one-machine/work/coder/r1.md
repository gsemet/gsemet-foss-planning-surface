# CR-323 round 1 (Coder)

## What changed (worktree, not committed)

CLI (`skills/chantier/scripts/cli/src/chantier/`):
- `board/running.py` (new): write/remove/read of the `running` record in `board.json`
  (`pid`, `host`, `port`, `version`, `served`, `started`), `live()` (uses `procs.alive_since`,
  `unreadable=True`), `stop_command()` (`taskkill /PID n /T /F` on Windows, `kill n` else),
  `find_pid()` (psutil lookup of a `chantier board` listening on a port).
- `board/command.py`: `_running()` replaced. A live record is probed at its own host and port:
  same version and same `served` reuses (seat registered, `board already running at <link>`); another
  version exits 4 with the "already serves this surface" line; silent exits 4 with the "does not
  answer" line. No live record: the configured address is probed, same version reuses, an older one
  exits 4 (PID from the answer, else psutil, else `PID unknown` with the "stop it from the session
  that started it..." text). After the bind the record is written; `_run`'s `finally` removes it
  when it names this PID. Nothing is ever signalled.
- `board/key.py`: `--new-key` keeps `running` (and any other key of the file).
- `board/routes.py`: `/api/board` has `pid`.
- `core/surface_batches.py` (new): `other_batches(repo)` -> the one `other batches on this
  surface: ...` line (read-only, `batch.json` of the other projects; `closing` state; Drivers =
  `len(rails.held)` + 1 with `stack_agent`; `<project>: batch.json unreadable`); None in-project.
- `commands/preflight.py`: P14 line on a surface project (`ok`, never warn/fail).
- `commands/batch_status.py`: the line after the autosync line, only when another batch exists.

Cards/docs: `chief-of-staff.md` (staging rule in "With a planning surface" and the "Stopped by the
user" bullet; P14 in plan step 1, other batches in step 2; Routes row), `griller.md`, `concepts.md`,
`session-start.md` (board bullets), `docs/web-board.md`, `docs/planning-modes.md` ("Two sessions
on one surface"), `AGENTS.md` (board.json line), `scenario/README.md` (coverage bullet).
`agents/` and `com.github.copilot/agents/` untouched.

Tests: `tests/test_board_running.py` (new; parametrized start decision over same / other version /
silent / dead / no record old / no record old with pid, with `os.kill` forbidden; `--new-key` keeps
`running`, exit removes only its own PID) and `tests/test_surface_batches.py` (new, parametrized).
They are in new files because `test_board.py` would exceed 400 lines.

Scenario (`scenario/run_scenario.py`):
- `external_surface`: `status --project demo` holds the other-batch line; `preflight --project
  other` holds a P14 line naming demo's batch and passes; in the board block a second `board
  --project other --port 0 --seat sess-b` prints `board already running at` the same link and
  `/api/board` answers an int `pid` (a seat for `other` is taken first, left in the `finally`,
  so the board does not stop by seats).
- `remote_board`: step 8's "port held by another program" check moved to just before step 10 (a live
  board's record now wins over a configured port, so it needs no live board); a check that a second
  `board --port 0` with a live board prints `board already running at` its link; `board.json`
  holds the `running` record while it runs; the "late" (no seat) board starts after `second`
  stopped; the record is gone after the stop and the key stays.
- Setup preflight check: no P14 line in-project.
