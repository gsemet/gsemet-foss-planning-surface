# Explain a refusal before the user hits it: why, and what to do now

Type: docs (cards). Filed 2026-11-13 by a Chief of Staff, from markdown-okf-schema-studio.

## Owner's words

See `intake/request.md` (the owner's model message, in French).

## The rule to add

When a rule or the CLI will refuse what the user asks, the Chief of Staff says so at once, in the
user's language, in three parts: what is refused, why the rule exists, and what the user can do
now (the alternatives). Not after trying, not only after the refusal.

## Case 1 (the trigger)

A running direct batch takes no new CR (`order add` exits 2; only a release or a fix joins).
Why: it protects the Chief of Staff's attention while it steers. What to do: wait for the pause
(note: a batch with a release CR pauses only after the release ended, so the new CR misses that
release), switch to Foreman mode (made for this dynamism), or refine the request meanwhile in
another session.
