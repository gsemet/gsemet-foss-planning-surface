# Release notes: kind-first plain text and framed images

Release notes: teach the Release Driver a plain, kind-first way of writing the text and of capturing images. Structure and format of the notes stay as they are.

Why: the user saw the markdown-okf-schema-studio 1.12.1 note (an urgent bug-fix release): it reads like a 1.12.0 feature release, a revert is presented as a new feature, and block-editing fixes are presented as features; no well-framed image; the text is long and indirect. A Fable audit of all the repo's notes (2026-11-24) found: a fix worded as a new ability in 7 of 19 notes; a closing "why it matters" line in 9 (gone since the 1.10.0 ban, so a written ban works); bad news hidden or softened in 6 (user-facing known issues under "For contributors", removed settings mid-paragraph); whole-page or oversized images in 6 of 11; mechanism told instead of consequence in 5. Cause: release-template.md (and the OKF repo's guideline, which ranks above it) require a verb subtitle and a "what you can now do" heading whatever ships; nothing on release kind, bad news or length. Also: no fixed image width, caption rule or named crop tool; driver.md says a Driver never opens an image, the template says the Release Driver reads each image it produced.

Audit draft of rules (to grill): kind first (feature, fix, restore, breaking, internal; subtitle names it; full version in the title); one sentence per item, "Fixed: ..." for fixes, a restore owns the earlier release's mistake in one clause; Removed/Changed/Known issue as labelled lines in the visible part; budgets (subtitle 16 words, item 20, visible part 120 for a patch, 250 for a feature); banned constructions with real before/after cases; image protocol (only visible changes, one per change, crop to the changed element, 900-1200 px wide, at most 600 px high, joined before/after, alt text as caption, no sentence about a missing image); a ten-question yes/no self-check. Placement: the card says what the role judges; the project's own scripts/release_notes.py --check holds the mechanical refusals; the CLI gets nothing; the OKF guideline gets the same amendment.
