## Decisions and open points

1. `origin/HEAD` unset: `not-a-branch` blocks (strict C.6). A fresh `git clone` sets it, a hand-made remote does not (the tests run `git remote set-head`). Driver to say whether to be lenient.
2. A dead writer thread leaves the server serving, the entry removed (writes refused), `board: the writer stopped: ...` on stderr.
3. Default audience of a line is the projects with a seat; a blocked or conflict line goes to the projects holding the paths when it names any.
4. The first commit of a project creates `changes/.gitignore` under the lock, which counts as a change moving: that commit waits one more quiet period. Harmless; the failed-step test pre-creates it.
5. Git's `warning:` and `hint:` lines are dropped from a failed step's text (a CRLF notice used to bury the real error).
6. Locks: the project locks are let go before every journal append (same non-reentrant lock). `staged` needs the same path in two consecutive cycles (a hand `git add` in progress is not blocked at once).
7. `try_lock` (core.files) is used as the hub does; the "second loop gets no lock" tests ran on Windows only. Check them on POSIX in CI.
8. Line endings: my first scripted writes made CRLF files on Windows; all normalised to LF (`git ls-files --eol` shows none left).
