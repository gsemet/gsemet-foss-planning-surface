## What changed

- `pyproject.toml`: `watchfiles==1.3.0` added and banned at module level. `uv.lock` regenerated
  (abi3 wheels for the three systems).
- `src/chantier/board/watch_files.py` (new):
  - `Settler` is pure: a project settles after 1 s with no change, or 5 s after the first change
    of a stream that never pauses.
  - `FileWatchThread` makes the notification watch (`watchfiles._rust_notify.RustNotify`) in the
    caller's thread, so `start()` returns the mode (`notify` or `check`) before the start line.
  - `feed()` counts only the paths the fingerprint covers (`fingerprint.counts_for`, so locks are
    ignored). A path at depth 1 or less under a surface's `projects/` re-reads the project list.
  - `tick()` walks each due project once (`ctx.settle`).
  - If the watch fails to start, or dies later, it switches to check mode: a stderr line
    (`STOPPED`), `on_mode("check")` (which updates the `server` entry's `files`), then one check
    every `CHECK_S`.
- `board/fingerprint.py`: new `counts_for(rel)`.
- `board/context.py`:
  - `revs` (under the lock).
  - `settle(project)`: walks once, keeps the result, and wakes the push loop when it moved.
  - `rev(project)`: the kept value, or one walk that is then kept.
- `board/reads.py`: `state_of` computes the rev as `sha256(ctx.rev + "\n" + live.mark())`, with no
  walk per read.
- `board/api/ops.py`: every board write op (and `config.put`) calls `ctx.settle` after it writes.
- `board/api/push.py`:
  - New `wake()` and a `woken` event.
  - New `observed()`: true with a socket sub, or while a long-poll is held, or within `2*HOLD_S`
    of a long-poll.
  - `PushThread` waits on the wake or on `push_every`.
- `board/api/times.py`: `CHECK_S=5.0` and `IDLE_STOP_S=1800.0`. The test seam takes 4, 5 or 6
  fields (`FEWEST`); missing fields keep their shipped values.
- `board/idle.py` (new): `IdleStop` (the time is passed in, it stops through `ctx.stop`, `STOPPED`
  line) and `IdleThread`.
- `board/command.py`:
  - Constants `WATCHES`, `CHECKS`, `STOPS_IDLE`, `FORGE_WHEN_OBSERVED`, `BOTH_FLAGS`, and
    `files_line()`.
  - `--stop-idle` with `--forge-always` is a usage error.
  - Before serving, every project gets its first fingerprint, and the watch's mode is known
    before `_announce`, which prints the file-watch line last.
  - The `server` entry gains `files`, plus `stop_idle` and `forge: always` when given.
  - `_run(ctx, sock, files, args)` starts and stops `FileWatchThread`. With `--stop-idle` it runs
    an `IdleThread`. The hub's observer comes from `_observer()` (`lambda: True` with
    `--forge-always`). Shutdown order: idle, the writer's final cycle, files, push, hub, then the
    entry is removed.
  - The "already running" lines add the file-watch line from the entry, `FORGE_WHEN_OBSERVED`,
    and `STOPS_IDLE` last.
- `declare/board.py`: the two flags, each with its help text. A `_switches` helper keeps
  `register` under 50 lines.
- `hub/loop.py`: `poll(now, observed)`. With no observer the hub is idle (`set_idle`); the first
  observer gets a cycle at once. `HubThread(loop, on_death, observed)`.
- `hub/cycle.py`: `set_idle` writes `idle: true` once and sets `last=None`; `cycle()` drops it.
- `hub/state.py`: `write_server(..., **extra)` and `set_server_files(git_dir, mode)`.
- `hub/lines.py`: `hub_line` prints `forge hub: PID <n>, the surface server, idle (no client
  subscribed)` or `..., last read <t>`. The `a watcher` branch is gone.
- `writer/lines.py`: the new `START` text (section 4).
- Tests:
  - New `tests/test_file_watch.py`: the settle rule (quiet, and a stream), two projects, locks and

  - Reworked: `api_client.settled(ctx)` is the shared settle helper (used in `test_board_prs`
    through `Board.edit`, and in `test_server_api_ws`). `test_board_exposure`, `test_board_running`

- Test time: `just test` took 105 s on this machine. The same suite took 101 s here before the
  two new files, which add about 5 s of test time. A full run I started earlier, before
  `test_server_api_ws` got its settle, hung on that test (its `next_of` loops on ticks) and may
  still have been running during the gates.
- The real backend is reached through the private `watchfiles._rust_notify.RustNotify`. The
  public `watchfiles.watch` generator does not give the mode before the start line. The version
  is pinned at 1.3.0.
- On Windows, `RustNotify` on a root that does not exist does not raise and reports nothing.
  The board refuses a missing planning folder before it starts, so this cannot happen in use;
  the tests create the folder first.
- `FORGE_WHEN_OBSERVED` is tested on `_running_lines` with the entry. No test runs a full second
  `board --seat --forge-always` against a running board.
- "Seats registered and not observing do not count": `IdleStop` reads only
  `PushLoop.observed`, and seats are not subscriptions. No test covers it on its own.
- "Without the flag, no stop": no `IdleThread` is made without the flag. No test covers it.
