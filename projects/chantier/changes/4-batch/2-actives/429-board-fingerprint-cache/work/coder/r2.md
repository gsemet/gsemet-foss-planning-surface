## What changed

- `src/chantier/hub/watch.py` (rewritten):
  - `Watch` no longer reads `forge-journal.jsonl` and is no longer a hub. Removed: `HubLock`,
    `elect`, `yield_hub`, `serving`, the `Hub` import, and the `, the hub` / `hub is chantier <v>`
    clauses.
  - Kept: `WatcherLock`, `subscription`, `for_subscription`, `waking`, the EVENTS and SEAT ends,
    the output and the last line.
  - `start()` takes the lock, then `connect()`. A recorded board gets the seat registered when it
    is this session's. With no board, `seat_rule()` runs in the spec's order (no key, no seat, no
    transcript, this session's seat, another's) and, for this session's seat, `start_board()`:
    detached spawn, then up to 20 s of `server.json` plus the probe. The start line follows, then
    the lines passed on.
  - `poll(now)` stays the seam. It drains the feed's queue; a lost link opens again after
    `RETRY_S`, from `after = cursor`. No transport within `SILENT_S` ends the watcher with
    `silent_text`. A `Refusal` ends it: kind `key` gives the refused-key line, kind `protocol`
    gives the server's sentence plus the restart hint. A `Refused` read gives `NOT_SERVED`.
  - New ends: `IDLE`, and `END` (an `Ended` with its line and exit code).
  - `watch()` returns `(lines, code)` through `run()`.
- `src/chantier/hub/watch_lines.py` (new). It holds:
  - the line constants, `Ended`, and `OTHER_VERSION` ("board is chantier <v>: restart it to run
    this version");
  - `told(e)`, which prints the sentence the server already gives as `text` (see the open points)
    and falls back to `journal.event_text`.
  - It is split out of `watch.py` so that file stays under the 400-line limit.
- `src/chantier/hub/feed.py` (new):
  - `LinkFeed`: a `Link` read in a daemon thread into a queue. It stops at the first loss or
    refusal.
  - `Board`, the test seam: recorded, probe, register, link, spawn, clock and sleep.
  - `board_argv` builds `cli board --seat <session> --stop-idle`.
  - `spawn`: POSIX uses `start_new_session`. Windows uses
    `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`, never `DETACHED_PROCESS`. Both use DEVNULL for
    all three streams and `close_fds`.
  - `passed_on`: BEYOND, then NO_NETWORK, then WATCHES or CHECKS.
- `clients/tui/link.py`:

## Open points

- The server's `events` lines carry `text` already told (`topics._told`). Printing them with
  `journal.event_text` would say "board wrote (move): board wrote (move): ..." twice. `told()`
  uses the server's sentence when `_told` would have told the line, and `event_text` otherwise.
  `docs/server-api.md` should say that `text` is the told sentence (round 3).
- On Windows, the board started with no console window is unproved until a `chantier gate` run
  with the user at the screen. The PR's Known gaps must name it.
- The no-`welcome` case is handled in the watcher, by a 20 s timer from the first link opened
  with no transport answering. `Link` itself does not time out.
- A board that restarts mid-run (it was lost, then one started or found again) prints no line;
  the link simply comes back from the cursor.
- `hub/lines.py:board_lines` still says that another version's board "writes do not reach the
  watcher". It is a `status` line, and the spec keeps `status` unchanged; round 3 can reword it.
- `evals/results/claims-v0.14.0.md` names the removed test. It is a released results file, so I
  left it as is.
- Round 3 is not touched: the cards, AGENTS.md, the docs, the scenario itself and server-api.md.
  The scenario still describes a hub watcher in its bullets.
