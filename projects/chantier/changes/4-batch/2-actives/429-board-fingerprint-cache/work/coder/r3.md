### A product bug the scenario found

`src/chantier/board/projects.py`: `_project(surface, name)` now finds a project by
`surface / "projects" / name`. It used to resolve the bare name in the working folder's surface.
A board that a watcher starts from the project's code clone (`feed.spawn(..., repo.root)`) died at
once with `no project folder ...\code\projects\other in a planning surface`. Every watcher-started
board on a surface with more than one project would hit this. The fix covers all three callers
(`refresh`, the `SurfaceChoice` branch, `open_projects`). New test:
`tests/test_board.py::test_a_board_started_from_a_code_clone_serves_every_project_of_the_surface`.
