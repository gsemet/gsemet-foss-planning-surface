## Deviations from the specification

- `way_back` takes `(d, c)`, not `(c)`: a queued CR's text needs the batch to find what it waits
  for. It lives in `commands/leftover.py` because `endpause` imports `closing`, and `closing` needs
  it (an import cycle otherwise); `endpause` re-exports it.
- `close`'s refusal runs BEFORE `check_idle`, not after: `check_idle` counts every CR not ended
  ("`<cr> is blocked, not merged or cancelled`") and would always raise first, so the spec's
  order could never reach the new message.
- `end_of_batch` is now called whenever a CR ended in the command (it returns `[]` unless the
  batch ended, or every CR left is parked/held/blocked/queued behind such CRs); the callers' own
  `all_merged` tests were dropped.
- `open_counted` and `what` moved from `commands/wait_view.py` to `core/waits.py` (import cycle
  through `status`); `wait_view` imports them back.
- A held CR is `ready`, so a queued CR `after` it is not "waiting" in `waits_for` (a ready CR is
  met); a held CR still appears in `way_back`/`left` lists through its own line.
- The `<destination>` in the `close` and `left_open` lines is printed as
  `<trash|P1..P4|3-ready>`.
