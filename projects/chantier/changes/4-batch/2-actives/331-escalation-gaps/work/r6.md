# Round 6 (Coder)

Defect fixed: a generic escalation set only by the shipped defaults (no user `chantier.yaml`,
Copilot) printed no contract lines, because `contract_lines` read only the resolved playbook's
per-role `escalation`.

## What changed

- `src/chantier/plugin_files.py`: `contract_lines(role, text, resolved, escalated=None)` also
  treats a role as generic when the escalation map `escalated` (the batch's frozen
  `record.escalation`, or the shipped defaults' map) holds `mode: generic` for it. It still
  prints at most once per role per call. `chief_prompt_lines` takes `escalated` and passes it
  on. `worker_prompt_lines` now takes `(root, cr, batch, record)`: host, playbook and
  `recorded_escalation(record)` come from the batch record (this keeps ruff's argument limit).
- `src/chantier/commands/facts.py`: the one caller of `worker_prompt_lines` passes the record
  (`take`, `round`, `handoff` build their facts here).
- `src/chantier/driver_prompt.py`: `driver_prompt_lines` passes `recorded_escalation(d)`.
- `src/chantier/commands/rules.py` (`playbook`): passes the escalation map it already computes.
- `tests/test_playbook_escalation.py`: a new test with two cases (`shipped`: no user file;
  `user`: coder escalation gpt-6.1-sol) on a Copilot batch. It asserts that the coder contract
  heading appears in take as `[heading, "  heading"]`, and exactly once in round and in handoff.
- `tests/test_playbook_config.py`: the existing generic-start test now counts only the coder's
  headings. On Copilot the shipped generic escalations of conflict-resolver and debugger now also
  print their own contract, once per role, which this fix intends. Line count is unchanged (400).
