## 2. Where the spec's assumptions differ from the code

1. **2.1 Note rules and shared function.** `check_take` raises for ready/blocked/working with no note before it reads agent, budget, slot, deps. To "answer every other check" the shared function takes `note` and `access` passes a non-empty placeholder (only truthiness is read), then adds the "take needs --note" ending itself when status is working, ready or blocked. No change to `check_take`.
2. **2.2 Read-only leases.** `leases.liveness` and `hold_records` delete dead hold records. Smallest change: a keyword `drop: bool = True` on `hold_records`, `liveness` and `check_free`, passed by `access` as False (mirrors `ticket_cr(p, drop)`). The `lease` and `take` callers keep the default. Without it the spec's "a dead hold record is still there afterwards" test fails.
3. **2.3 Texts.** `write: refused` lines (spec 4.3) differ from `lines.refusal`/`state_line` (C.8/C.10) in wording and print `$CHANTIER` literally in code, not through `cli_command(repo)`. Recommendation: build the `write` line from `lines.START`, `lines._older`, `lines._then`-style pieces made public, so one source holds the words; follow the spec's `write: refused: ...` shape and the code's literal `$CHANTIER` (as `seat`'s and C's lines print), unless the user wants `cli_command(repo)`. This is a question for the Chief of Staff (section 5).
4. **2.4 `stopped` writer state.** A live `writer` entry in `stopped` is a refusal (`lines.refused`). Spec 4.3 lists only the six states. Proposed line: `write: refused: the surface's writer is stopped: <text>; start the surface server (...)` from `lines._stopped`. Needs a decision and one more test row.
5. **2.5 `check_publish` side effect and name.** In `access`, set `repo.command = "take"` before the shared call (the refusal then reads `take: the surface's writer is not running: nothing written; ...`, which `access` strips) and call `writer_lines.forget()` afterwards, so `cli.with_notes` adds nothing. Both are in access's handler, not in the store.
6. **2.6 Mode `--batch` and CR.** `take` never verifies that `--batch` holds the CR before `b.cr()`; `access` must use `read_batch` then look the CR up and say `unknown CR` as `Batch.cr` does (exit 0 or 1 is the spec's call: spec says exit 0 whatever the answers; "no batch holds" is in the `claim: refused:` / `push: refused:` form; "unknown CR in batch" should take the same form).
7. **2.7 Leases in push.** Spec 4.5 reads `c.lease` for the CR; `LIVE` states for lease claims in code are only `{"working"}` (`records.LIVE`), consistent with step 2. `leases.claim` accepts a `not confirmed` current lease and logs `lease-late`; `access` must not. Spec "expired" -> `NOT_CONFIRMED`; the push line text says "expired" in spec 4.5.7: the project avoids that word for the lease ("not confirmed", never "gone"). Question 5.2.
8. **2.8 `--epoch` list in cards.** `chief-of-staff.md` ("Carry `--epoch <n>` on exactly these commands and on no other ... any other command refuses `--epoch`") becomes false: `access` takes `--epoch`. Spec section 6.1 does not edit that list. Also `foreman.md` may repeat it. The doc edit is one clause ("and, optionally, `access`"); not in the spec's list.
9. **2.9 AGENTS.md.** The spec's ordinal/count clause is moot: HEAD's commit already removed ordinals ("names each exception, no ordinals"). The `lease` item is a prose item inside "Named exceptions" with a `;` separator; `access` is added as one more item after `wait` and before the writer sentence, in the same form ("`access`: read-only, ... built on ... with no measured cost."), no count to change.
10. **2.10 `driver.md` line.** "Means: the lease" exists (line 751), is linked off the common path and is not in `startup-manifest.json`'s `cr-driver` readings: the line goes there, no byte on the 45,000 path. `foreman.md` target text is at line 175 ("The batch's limits are the CLI's"); `griller.md` "In a planning surface" at line 75; `chief-of-staff.md`'s direct-mode place is "Steering a batch yourself" (line 1646), bullet "Leases" is the natural neighbour.
11. **2.11 Fingerprint helper.** `tests/store_spy.py:fingerprint(project)` exists (bytes, skips locks, skips `.repo`); it has no mtime and does not cover the git folder's `chantier/`. Spec wants bytes AND mtime for planning folder + `chantier/`, `batch.json`, `events.jsonl`. Write the stronger helper in `test_access.py`, or extend `fingerprint` with an `mtimes=` option (smaller).

## 4. Risks

- **Size values:** the change alters no size or value other code measures from except `driver.py` (363, shrinks) and the 45,000-byte common path (not touched: the `driver.md` line is under "Means: the lease", which is not a manifest reading; verify with `test_startup_manifest.py`). Searched `363`/`377`: only the spec's 377 is wrong. `MAX_LINES` 10: output is at most 6 lines.
- **A missed side effect makes `access` write:** `Repo.find()` (writes `.gitignore`: use `readonly=True`); `RenderedBatch` (writes STATUS); `refresh_for_check` (writes the spend); `leases.claim` (renews); `hold_records` (unlinks); `lines.wrote` (feeds `with_notes`). Each has a counter in 2 and a test row in the "nothing written" check.
- **The "one check function" test:** refusal text parity between `take` and `access` is real only when `take`'s refusal is not decorated after: `take` raises through `main` as `error: <text>`; the test compares `str(e)` / stderr minus `error: ` with `claim: refused:`'s text. `check_epoch`'s stale text and the note rules are outside the shared function by design.
- **Windows:** the test for "dead hold record stays" needs a pid that is dead (`DEAD` in `batch_helpers`, already used by `test_leases.py`); a hold record of the live test pid for the live case. Hold-record liveness uses file mtime (`alive_since`), so the "nothing written" test must not touch it.
- **Clock seam:** `clock.fix(T0)` as in `test_leases.py`; lease `expires` is on the frozen clock. The `lease-late` event must NOT be logged by `access` on a not-confirmed lease (checked by `events.jsonl` bytes).
- **Cost of `just test`:** one in-process `chantier` call is ~0.05-0.1 s; about 45 cases fit the spec's 1.5 s only when states are built once per module. Reuse `leased`-style fixtures and `surface` templates; avoid one `open_batch` per case (parametrize over a small prepared state list).
- **`Repo.command` leak:** `repo.command = "take"` is set on the access's own repo instance only; no module global.
- **Release branch case:** needs a real git state (top CR, `refs/heads`): one case only, as the spec allows; copy a setup from `test_carry_ship.py`/`test_stack_base.py` if it exists, else a prepared batch with a release CR and a CR with a recorded head.
