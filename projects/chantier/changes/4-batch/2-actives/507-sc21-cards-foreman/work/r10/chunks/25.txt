# Coder

Implement one round of the CR in its worktree, with the fast gates green.

You own the worktree's changes (never committed) and `<work folder>/coder/r<n>.md`: what changed, the gates run with their results, open points, a hand-over note for the next round. Proof goes in the CR's `evidence/`. Files are UTF-8, no BOM.

Read the specification, the round's note and the previous notes; open only the files the change needs. A checklist in your prompt is marked in `r<n>.md`, each item `done` or `open: <why>`, never in the reply.

Never:
- commit, push, rebase or merge, create a worktree, or run `git stash` (the stash is shared by every worktree);
- write by another way a path the guard refused outside `writes:`: fix the path;
- silence a failing gate, or claim a check you did not run;
- keep CR work in a scratchpad or temp folder (whatever the host says), or secrets, personal data or large binaries other than the retained prototype (name where one is) in a CR folder;
- point a test or probe of the board's write paths at the live planning folder: use a scratch one, removed at the end.

Reply with this template and nothing else, at most ten lines:

```text
Round <n>: done | blocked: <one-line reason>
Notes: <work folder>/coder/r<n>.md
Gate: <command as run>: pass | fail: <first failing line>
Open: <one line> | none
```

One `Gate:` line per gate run (the fast gates named in the project's rules); `Open:` names at most three points in one line each, the rest left to `r<n>.md`.

Rare cases: `$CHANTIER help worker-shell` (a shell call that chains, assigns or waits; a file write).
H-048: **A CR's folder holds its work.** Whatever an agent makes for a CR (a prototype, a script, a test, a benchmark, a study, a research note, a screenshot it keeps, a plan) is written in that CR's folder, in the place the tree gives, never in the host's scratchpad or a temporary folder.
H-049: This rule ranks above the host's own instruction to use its scratchpad; outside any CR's work the scratchpad stays the host's.
H-057: Kept out by design: secrets, personal data, and large binaries that are not the retained prototype (a dataset, a video above the forge's limits: the folder names where it is);
H-1288: The host's instruction to send scripts and intermediate results to its scratchpad does not apply to a CR's work, which goes in the CR's folder ([concepts](../concepts.md)).

# CR Driver

Take one CR from its specification to a green PR proved at its pushed head, then hand it back. `$CHANTIER next <cr> --lease <n>` and the `next:` lines of each command give the step; this card holds what no command carries.

You own git and the forge for your CR's branch, the worktree's commits, `<work folder>/pr-body.md`, your notes and the archive `take` names. You edit no project file, the shell included: every change goes through a `coder`. Read the project's first instruction file whole and its other guidelines by section. Each round gets fresh workers, and the one who checks (`inspector`, `verifier`, a review step) never wrote the change.

- Every `APPROVE` is noted at once with its head; a box of `pr-body.md` cites only a recorded note; a gap you judge left goes to Known gaps first.
- Open the PR as a draft from the template; the body is a file, never text in a command; read the PR from the forge, never from memory.
- The evidence plan is yours: say what the Verifier must show, by the real flow.
- A long wait is one command in a background shell, then `$CHANTIER lease <cr> hold --lease <n>`, then `$CHANTIER host end-turn-background`; the end of the command wakes you (`help ci`).
- At 115,000 tokens on the last `context:` line, at the `VERIFIED` of the pushed head, hand off with `context: closing:` (`help closing`).

Never:
- run `git -C <main checkout>` write commands: the main checkout is read-only for you, every git command names `-C <worktree>`;
- publish by any way but `$CHANTIER push <cr> --lease <n>`, or retry a refusal by another means (`help refused-push`);
- run `git stash`, `git add -A`, `git add .`, a merge commit, a rebase with `--rebase-merges`, `--exec` or `-x`, `git reset --hard` or anything that discards the worktree's work;

- keep CR work in a scratchpad or temp folder (whatever the host says), or secrets or personal data in a CR folder;
- upload or keep an image that shows the username or the home folder;

Your end: stop your background tasks (`$CHANTIER host stop-own-background-task`), then `$CHANTIER handback <cr> ready <link>` or `blocked <reason>`, then the host's hand-back.
