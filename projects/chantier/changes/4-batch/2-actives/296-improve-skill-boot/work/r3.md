# Round 3

Implemented the Inspector blockers: Foreman startup is now a separate, wrapper-less
manifest entry whose prompt is built by the Chief of Staff and reads only the common,
host, role and named startup sections. Stack Driver maps to the Driver card's Stack
driver contract. Action readings now include session-start and each worker/specification
role, while batch readings are limited to Foreman/concepts/host material. Foreman
autosync is explicit opt-in, and session-start distinguishes server-announced binding
from probed local readiness and untested LAN reachability.

Board Start now reuses a live board participant after stop/start, observes an early join
failure and returns its exact diagnostic while disabling the group instead of claiming
success. The scenario assertion covers the explicit start followed by join. Restored
the base skill-registration and role-section regression tests and moved the startup
structure test to its own file. The structure test asserts every action has readings;
mutation proof: temporarily replacing `batch` readings with `[]` made
`test_empty_action_readings_are_rejected` fail, then the mutation was reverted.

Base tests removed by round 2 and restored equivalently:
`test_four_skills_the_router_and_three_thin_ones_listed_by_copilot` and
`test_every_role_has_its_section_in_its_card`. No base CLI test was dropped without
equivalent coverage.

Real boot definition: UTF-8 byte size of the common core, host core, role core,
startup manifest, the host wrapper (except Foreman, which has no wrapper), and each
role's declared mandatory startup section. The Chief-built Foreman prompt is represented
by its manifest entry and short startup sections, never by loading the whole Chief,
Foreman, concepts or host cards.
