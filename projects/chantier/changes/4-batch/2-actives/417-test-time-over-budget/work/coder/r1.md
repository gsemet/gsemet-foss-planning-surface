# Round 1 (Coder)

No test id is added, renamed, merged or removed: fixtures and settings only, so no inventory table.

## What changed (all under skills/chantier/scripts/cli/tests/ except the justfile)
- `writer_rig.py`: `rig.make()` no longer runs `git remote add`, `fetch`, `branch -u`, `remote set-head`
  and a second `git clone` per test. The origin and the second clone ("other") are built once per
  module (`other_template`); each test copies them, writes the remote/branch config and the
  `refs/remotes/origin/{main,HEAD}` files directly, and re-points the copy's `url`. Writer tests still
  drive real git (commit, rebase, push). Measured alone: setups are now 0.07 s; the writer tests' time is
  almost all the real git processes of the code under test (about 15 git calls per cycle, 137 per
  conflict test), which cannot go without a fake: no more saving there.
- `conftest.py`: `shared_state(factory, name, build)`: a prepared state built once per run instead of
  once per xdist worker (first worker builds, others wait on a marker file in the run's base folder;
  without xdist a plain folder).
- `store_spy.py`: `build_states` (the 7 s `states` session fixture of the command table, built by each of
  16 workers) uses `shared_state`. `access_batch` moved here from `test_access.py` (that file hit the 400
  line limit of test_code_targets).
- `test_access.py`: `batch_template` uses `shared_state` + `store_spy.access_batch`.
- `cost_world.py`: the cost world template is shared across workers (marker file `done`), not one per worker.
- `justfile`: `pytest -q -n auto --dist worksteal` (same tests; worksteal evens the tail of the 4 to 8 s tests).
