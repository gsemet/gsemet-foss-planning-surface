## For the PR

- `platformdirs` 4.14.8 wheel: `platformdirs-4.14.8-py3-none-any.whl` (pure Python,
  `Root-Is-Purelib: true`, no requirement, no compiled file), so Linux, macOS and Windows. sha256
  `1e34af590de4d978631b751eb2202f2fee4497537a17c1720b12fcf57b331392`.
- Windows resolution in that version (`windows.get_win_folder`): the environment variable
  `WIN_PD_OVERRIDE_APPDATA` when fully qualified, else the known-folder API through `ctypes`
  (`SHGetKnownFolderPath`); registry or environment only where `ctypes` or `winreg` cannot be
  imported. `APPDATA` is not normally read. Checked on this machine: the folder equals
  `%APPDATA%\chantier`: True (no override variable set).
- macOS: `~/Library/Application Support/chantier`, unless an absolute `XDG_CONFIG_HOME` is set
  (platformdirs' rule, kept); a relative one is ignored. macOS users run `chantier login` again.
- Footer words: `drag a border: resize  Shift-drag: select  Ctrl-click: open a PR`. Help rows:
  "Drag a border", "Wheel", "Shift-drag".
- Support for those words, read in the Windows Terminal source at tag v1.25.3131.0 (the version
  installed here), `src/cascadia/TerminalControl/ControlInteractivity.cpp`:
  `_getHyperLinkForPointerPress` returns the link on a left press with Ctrl; `PointerPressed`
  checks it before VT mouse input (comment "GH#9396: we prioritize hyper-link over VT mouse
  events"); `_canSendVTMouseInput` is false while Shift is held, so a drag selects. Not tried.
- "A terminal that does not answer gets no mouse" holds on POSIX only: on Windows blessed falls
  back to the console's own mouse input. Apple Terminal gets no mouse.
