Short name: `own-gate`

1. own-gate-Q1: **Who owes the local Windows long gate in a parallel batch.** A. Each PR passes it before it is called ready to merge (each lands alone on main); the exemption "owed by the stack top only" applies to a stack batch only. AGENTS.md and the cards say so for parallel, series and stack.
2. own-gate-Q2: **The batch shape at open.** A. The Chief of Staff asks the user at open, with its recommendation from the overlap of the CRs' files, instead of taking parallel by default; `status` shows the shape.
3. own-gate-Q3: **Grilled enough.** A. Specify, for the running batch batch-31.
4. own-gate-Q4: **Series.** A. Each PR of a series batch owes the local run, as in parallel.
5. own-gate-Q5: **Exempt CRs.** A. A CR the project's rules exempt from the long gate does not owe the local run.

Destination: running batch batch-31.

6. own-gate-Q6: **The local run fails while the user's board holds port 8765.** The user's word: set up a dynamic port system (the port is incremented by 1 until a free one is found). Done in its own CR (`long-gate-webui-check-starts-a-second-bo`, widened to the dynamic port); this CR waits for it (`after`) so each PR's run can pass.
7. own-gate-Q7: **Another project's rule that names only the stack's top.** A. The cards follow the project's rule when it gives a rule per shape; the reading each covered CR applies only when the rule names the stack's top alone.
8. own-gate-Q8: **A docs-only CR on top of a stack.** A. It still owes the local run; Q5 applies to parallel and series only.
9. own-gate-Q9: **No Windows run covers the merged result.** A. Acceptable; each PR's run, carried over clean rebases, is enough; the merged result is left to the CI ubuntu job.
