# Add a How we test page linking test levels to requirements

Add a documentation page "How we test", published in the docs and on the site. It explains the different levels of tests (unit, contract, simulated bench and visual, real VS Code integration, acceptance, stress, mutation, the e2e groups and their CI jobs) and how each is linked to the levels of requirements (StRS paths, SwRS scenarios, the @tests_req and @accepts_req markers with their #S<n> fragments, the okfreq coverage reports and the viewer cards). It describes the model as delivered by CR-504 and CR-505 (okfreq 0.18 paths, scenarios and acceptance tests), so it follows them in the stack.
