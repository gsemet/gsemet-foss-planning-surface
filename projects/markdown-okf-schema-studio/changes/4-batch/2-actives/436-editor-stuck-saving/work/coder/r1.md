# CR-436 round 1: coder report

Branch `chantier/batch-07/cr-436-block-editor-stuck-on-saving-markdown-af`. Nothing staged, nothing committed.

## Cause and fix
- Page: the text box returns LF only, so on a CR LF file an unchanged block differed from its source, posted a final save, the host wrote nothing and never answered: the editor stayed on "Saving Markdown...". Fix: `textBoxText` in `src/page/features/blockEditor.ts` gives the text the source block's line endings (`matchLineEndings`, new `src/core/edits/lineEndings.ts`) before comparing and posting (autosave, Done, move chord).
- Host safety net: `completeActiveBlockEdit` (`src/session/features/blockEdits.ts`) posts `previewEditSource` with `done: true` when a final save ends with nothing written and no render to follow (not for a cancel). Page `receiveBlockEditSource` closes the saving editor on it (and resumes a pending navigation); other edit ids ignored.
- Protocol: `PreviewEditSourceMessage` gained optional `done?: true` (`src/core/protocol/hostToPage.ts`).
- Host also uses `matchLineEndings` (keepOwnEndings = true) before comparing/writing. Mixed blocks keep the endings of lines left alone.
