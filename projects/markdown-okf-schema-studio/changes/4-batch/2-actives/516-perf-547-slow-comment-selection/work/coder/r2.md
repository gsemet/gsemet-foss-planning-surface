## What changed

Point 1, the three content-root `:has()` rules:

- `main#sphinx-myst-preview-content` carries `data-okf-aligned-float` exactly while it holds an
  aligned image, figure or table; the three rules test that attribute (same specificity as before).
- New pure `src/core/preview/alignedFloat.ts` (selector, attribute, `markAlignedFloat` for parsed
  HTML). The host writes the attribute in the rendered page (`core/security/html-sanitizer.ts`) and
  in the exported file (`core/export/exportContent.ts`, after editors are removed), so no page
  script is needed. `core/preview/contentPatch.ts` leaves the attribute out of the page shell, so a
  patch stays a patch.
- New `src/page/modules/alignedFloat.ts`: `syncAlignedFloat` (called by the content patch at once)
  and an observer that reacts only to images, figures and tables; after a change it re-runs the
  first-element clearance (`runtime.ts`, `page/features/contentPatch.ts`). A change the page makes
  itself switches the layout at the observer's microtask, before the next frame is drawn.

Point 2 (`page/modules/commentCompose.ts`): `selectionchange` refreshes at most once per frame; a
scroll only moves the button (`follow`) and does not read the selection. As before, a scroll hides
the button while the pointer is down or the page is busy.

Point 3a: `blockBefore` walks back from the end block instead of listing every `[data-line]`.

Point 3b: `page/features/editMode.ts` (`mouseover`, `mouseout`) and `page/modules/codeCopy.ts`
(`mouseover`, `mouseout`, `mousemove`) act at most once per frame, on the latest element. A pointer
that leaves the window removes outline and button at once. A newer focus change drops a waiting
outline move; Tab, click and focusout apply a waiting copy-button move first.

Point 3c (`page/features/scrollCore.ts`): a throttled scroll report reuses the selection text while
the selection ends are the same. The kept text is dropped on `selectionchange`, on a change of the
content (observer) and on a switch of the page root that hides or shows content (observer on eight
root attributes). The last one fixes a defect of my own first version, found by a test: collapsing
the properties table under an unmoved selection left the old text in the report.

## Open points

1. `editMode.ts` `mousemove` (it records that the pointer, not the keyboard, owns the hover
   actions) is not framed: it writes once per keyboard-to-pointer switch, and framing it could
   override a later keyboard owner set in the same frame.
2. `perf-547` at 5 and 4 minutes leaves about 30 s of the job after a cancelled step for
   `ci-hang-dump` and the upload (setup took 20 to 28 s). A cold dependency cache would eat it.
   Rule 11 forbids raising a limit for a slow run; a real hang leaves less proof than before.
3. Between a selection change and its frame the Comment button's remembered selection is the
   previous one. Opening the box reads the selection afresh first, so only a selection collapsed
   and then the shortcut within that one frame would open on the earlier selection.
4. The "after" real-window runs are still to be made; this round proves the restyle count only in
   headless Chromium, and claims no time gain in a window.
