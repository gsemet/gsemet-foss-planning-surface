# Short video S1, horizontal (1920x1080): "Your agent's analysis, as a real page"

Status: scenario v2, 2026-10-28 (take 2). Vertical version: [../10-short-videos-vertical/01-s1.md](../10-short-videos-vertical/01-s1.md). Common rules: [00-common.md](00-common.md).

## Idea

Show a page that other Markdown editors cannot display: an agent's **performance analysis and
optimisation plan**, written in rich Markdown. The contrast between the raw source and the
rendered page is the message; the last beat shows that wide content breaks out of the reading
column so long tables stay readable.

## Demo document: `perf-analysis.md` (fictional)

"Export service: latency analysis and optimisation plan", written as an agent would write it:

1. Front matter (`type: analysis`, `status: proposed`, `owner: Platform team`) → properties table.
2. A `{note}` admonition: the TL;DR ("p95 export latency is 8.2 s; the plan brings it under 1 s in
   three steps").
3. A MyST grid of three cards with the key figures (p50 / p95 / error rate, before → target).
4. A Mermaid **sequence diagram** of a slow export (Client → API → Renderer → Storage), short
   participant names, one `Note over` for the slow step.
5. A **Vega-Lite** chart: measured p95 latency per week (line) and the projected latency after each
   optimisation step (dashed line), from inline data.
6. "Plan" section: a short numbered list of the three steps with the projected time saved.
7. Last: a **wide table** of the projection per endpoint (8–10 columns: endpoint, calls/day, p50,
   p95, after step 1, after step 2, after step 3, gain, owner, risk), in Auto width so it breaks
   out of the reading column.
