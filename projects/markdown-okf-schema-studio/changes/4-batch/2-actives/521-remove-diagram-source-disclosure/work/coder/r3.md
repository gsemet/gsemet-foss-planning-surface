## What changed

The built-in engine answers a source it cannot draw through its success callback, with a picture of its own error. The
page now recognises that picture and sets `data-render-state="error"`. The picture stays shown as before; the CSS then
shows the "Diagram source" disclosure, closed, in the preview and the HTML export. The owner's decision in
`02-answers.md` (a syntax error keeps its source) now holds for the default engine.

The recognition is one pattern, anchored at the root of the SVG (`<svg ...><defs/><g>`), for the three forms the real
engine (`@plantuml/core` 1.2026.9) produced: the "[From ... (line N) ]" banner, "Your data does not sound like JSON
data" (or YAML), and "Diagram not supported by this release of PlantUML". A drawn diagram that writes these words, or
imitates the banner with a note in the same colour, stays `rendered`. An unanchored pattern matched such an imitation.
