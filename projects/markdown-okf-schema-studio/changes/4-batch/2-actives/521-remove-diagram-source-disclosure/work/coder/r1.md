## Finding: the find index and a render state that changes later

`findMatches` (findBar.ts) calls `collectTextBlocks` afresh on every search, so each new search sees the current
render states. The only automatic refresh is `initializeContent` (contentPatch.ts), which runs before new diagrams
draw, and nothing searches again when `data-render-state` changes. So with the find bar open during a content patch,
the source of a figure that then fails is not matched until the next search; the rare reverse (a PlantUML include
redraw going from error to rendered) leaves matches in a hidden panel until the next search. Pending diagram text
already had the same staleness. No MutationObserver added: outside the specification, and a refresh scrolls.
