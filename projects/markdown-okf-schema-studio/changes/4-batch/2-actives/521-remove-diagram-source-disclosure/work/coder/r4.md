## Open points (worded for Known gaps)

- An EBNF grammar counts as a failed render only when the diagram source itself starts with `@startebnf`. A grammar reached only through `!include` shows the engine's "Syntax error!" picture as drawn, with no source panel.
- An EBNF comment whose text starts at the picture's left margin hides a "Syntax error!" line drawn right after it, which then counts as drawn. This errs on the safe side (no false error), and no such picture came out of the probes.
- The recognition reads the picture layout of `@plantuml/core` 1.2026.9. A later engine release that draws its error pictures otherwise needs the probe run again and the fixture captured again.
- Some sources that look wrong are drawn by the engine without an error and count as drawn, for example `a = "x" ;;`. The titled `;;` case in work/verify.md is drawn by this engine, while the verifier's e_issue_doc variant shows "Syntax error!" and is matched.
