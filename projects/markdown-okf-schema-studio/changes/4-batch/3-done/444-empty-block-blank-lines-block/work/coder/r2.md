## What changed

1. Fix 7 (editor kept across a patch). The logic was NOT really there: `applyContentPatch`
   always called `closeBlockEdit(false)`, and the content swap dropped the block. Now:
   `contentPatch.ts` keeps an editor that has `replaceBlankRun` open; `blankLines.refresh()` puts the
   held block (same element) and its editor frame back at its run's place after the swap, never moves
   a kept block while its editor is open, and lets it go at the first refresh after the editor closes.
   Page test "an editor opened from a blank-lines block stays in its element across a patch without
   that run" (runtimeBlankLines.test.ts): same element, same place, Cancel posts previewEditCancel
   with replaceBlankRun 3-6.
2. Page checks added: Delete/Backspace post nothing on a only-focused blank-lines block; a run
   starting on the separator line that ends a list shows one; the label is not in textContent;
   a forged data-okf-blank-runs element placed among blocks and before/after insert points is ignored
   (host's last element still counts).

   scenarioDefinitions1.ts, scenarioIds.ts. `renderFixtures.ts` appends the host's marker (now
   exported `blankRunsMarker` of renderPipeline.ts). Scenario count in test/site/e2eGroups.test.ts
   484 -> 487. PNGs in the CR folder evidence/: blank-lines-block-edit.png,
   blank-lines-block-selected.png, blank-lines-block-reading.png.
