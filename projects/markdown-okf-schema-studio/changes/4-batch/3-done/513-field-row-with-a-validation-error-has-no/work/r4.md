## Cause

The Dark, White and Cream palettes set `--studio-errorForeground` but neither
`--studio-inputValidation-errorBackground` nor `--studio-editorWarning-foreground`, so those two came from
the VS Code theme inside a forced mode.

## What changed

- `src/core/preview/styles/pageChromeStyles.ts`: each of the three forced palettes declares
  `--sphinx-preview-issue-error-background` (the mode's error colour at 14, 10 and 12 % for Dark, White,
  Cream) and `--sphinx-preview-issue-warning` (Dark `#cca700`; White and Cream
  `var(--studio-charts-yellow)`).
- `src/core/preview/styles/propertiesStyles.ts`: the field-row and warning-row rules read those two
  variables first, then the specification's theme token and fallback. The whole-document error row now
  has its own rule, unchanged in value (it does not read the new variables). No `--studio-*` token is
  redefined, so editors, badges, outlines and info rows keep their look. The edit hover rule is unchanged.
- The Current mode declares neither variable: it reads the theme tokens and fallbacks as before.
- `pageChromeStyles.markers.ts`: two `@implements_req` markers (FMSCHEMA-084, -023).
- `test/core/preview/fieldIssueStyles.test.ts`: three tests that resolve the shipped stylesheet with the
  tokens of a dark and of a light host.
- Requirements: new S10 in FMSCHEMA-084 and in FMSCHEMA-023, Method lines, Criteria sentence, a Known
  issue and the THEME-025 relation in 084; "light background" became "tinted" (false in Dark). The CR-513
  entry of `requirements/tiers/log.md` is extended. THEME-025 is not edited: its text does not have to
  name these rows, S10 states the behaviour and 084 relates to it.
- `CHANGELOG.md`: "light red background" became "red-tinted background"; same reference group.
- No visual scenario added or changed: 0 seconds added to the CI visual job.
