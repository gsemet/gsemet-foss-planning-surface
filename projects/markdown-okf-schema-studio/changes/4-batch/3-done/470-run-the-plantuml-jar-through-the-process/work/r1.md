## What changed
- `src/core/render/plantUmlHost.ts` (new): core-local structural interfaces `PlantUmlProcesses` and `PlantUmlFiles`. `core` cannot import `host-api` (rule core-is-the-bottom-layer), so the ports are matched structurally.
- `src/core/render/plantUmlRenderer.ts`: no `child_process` and no `fs`. The jar runs through `processes.run`, the jar check and the cache identity through `files.stat`. `resolveJavaCommand` is async and takes `files`. Spawner test hooks and `killProcessTree` removed. Without `processes` or `files` the diagrams are `unavailable` ("PlantUML needs a host that can run programs; ...").
- `src/core/render/renderPipeline.ts`: `plantUmlProcesses` and `plantUmlFiles` options.
- `src/session/features/plantUml.ts`: `engineFor` returns `builtin` when `capabilities.processes` is false (the JS-engine fallback lives there).
- `src/session/sessionFactory.ts`, `src/session/features/baselineDiff.ts`: pass `host.processes` and `host.files` when the capability is on.
- `src/host-api/processRunner.ts`: `ProcessResult.signal?` (keeps the "exited with signal X" message).
- `src/node-services/processRunner.ts`: child detached on POSIX, stop kills the process group; reports `signal`.
- `.dependency-cruiser.cjs`: NODE_DEBT entry of the renderer is now `path` only. No exception added.
- Requirements: DIAG-089 gets a "host cannot run programs" scenario; dated entry in `requirements/tiers/log.md`. Markers kept on moved code and tests.
