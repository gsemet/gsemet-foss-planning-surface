# Round 1

## Changes (worktree, not committed)

- `scripts/check-no-merge-commits.sh`: the single-tip peel is now a chain walk down the first
  parents over two-parent merges. `head` becomes `HEAD^2` only when the walk reaches a first parent
  that is an ancestor of the base, each lower second parent is an ancestor of the one above and, in
  a chain of two or more, each subject matches `^Merge [0-9a-f]{40} into [0-9a-f]{40}$`. Otherwise
  `head` stays `HEAD`. One pass, no arrays; the walk stops at the first non-nested head. Header
  comment and the comment at the walk updated. The rest of the script is unchanged.
- `test/build/test_no_merge_commits.py`: helpers `_stack`, `_forge_merge`, `_chained_test_merge`
  and the seven cases of the specification, same names. Existing tests untouched.
- `.agents/guidelines/pull-request.guidelines.md`, "Updating a branch": one sentence.
- No `CHANGELOG.md` line. Rule read: `release-process.guidelines.md` step 2: "Every PR with a
  `feat` or `fix` commit adds one user-facing line to `CHANGELOG.md` `## Unreleased` [...] PRs that
  are only `test`, `ci`, `build`, `docs` or `chore` add no line and tick the template checkbox with
  "No user-facing change"." `git-commit-allowed-scopes.md`: "Never use `fix(ci)`"; use `ci`, without
  a scope. So: commit type `ci:`, PR checkbox "No user-facing change", no release note.
