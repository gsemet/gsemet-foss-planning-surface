# Redundant tests of src/core (CR-450, round 2, spec 4.7 and 4.8)

Nothing is removed or merged by this CR: this is the list a later change request works from. No existing test file changed.

## How to read it

- Source: the core phase of one real run of `just mutation-core` on a sample of 51 of 162 files of `src/core` (6,007 mutants, every one of the 19 sub-folders represented; the list is in mutation-campaign-note.md). Redundancy is therefore **on the sample**: a test judged here may also kill mutants of unsampled files, so no removal is final until the full run (rule 5 in the note).
- Judged tests: only tests whose file is named after a sampled source file of the same sub-folder (report reader rule added in round 2). Left out of the judgement, as counts only: 101 zero-kill, 722 redundant, 101 reaching no sampled mutant.
- Redundant = a test whose every killed mutant is also killed by a keeper (greedy set cover: sole killers first, then the largest gain; two duplicates are never both listed). Zero-kill = reaches killable mutants and kills none.
- Marks: **removal candidate**; **keep** (regression or boundary rule of 4.11, or sole carrier of an SwRS that no remaining test carries); **not judged** (reason given).
- The regression and boundary marks come from the test name and the comment lines around it (words such as regression, bug, fix, CR n, STAB-, boundary, at most, cap, limit, exactly, edge); they are a reading aid, to be confirmed by the change request that removes tests.
- The SwRS column shows, for each `@tests_req` ID of the test, how many other tests would still carry it if every removal candidate went. A candidate that was the last carrier of an SwRS was turned into **keep** (iterated until stable).
