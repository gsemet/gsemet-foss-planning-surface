## Design

The page (edit mode, no block editor open) accepts a drag that carries `text/uri-list` or `ResourceURLs`, marks the insertion bar nearest to the pointer with `sphinx-preview-insert-point--drop` (a 4 px line in the focus colour) and, on the drop, posts `previewDropFiles {insertAfterLine, uris, pinLine?, pinViewportTop?}`. The host keeps only `file:` addresses inside a workspace folder, reads the first 64 KiB of each Markdown file for its first heading, builds one relative reference per file (`![stem](rel)` for images, `[heading or name](rel)` otherwise; spaces and parentheses percent-encoded; `[`, `]`, `\` escaped in the text) and inserts them as a new block with `planBlocksPaste` (the CR 145 / block paste planner), as one undo step, refusing like a block paste (read-only, open editor, stale, included block). The answer reuses `previewBlocksResult` (op `paste`). Wiki links are out of scope (decision in 00-request.md).
