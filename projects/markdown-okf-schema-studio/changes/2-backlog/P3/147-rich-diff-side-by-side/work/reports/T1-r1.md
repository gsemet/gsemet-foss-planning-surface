## Design (as implemented)

- Host (`src/session/features/incomingChanges.ts`, new `baselineDiff.ts`): when the page reports the toggle
  on, the host reads HEAD text (same `vcs.headText` as the green bars), computes line hunks
  (`lineHunks`), renders the HEAD text with the preview's own pipeline (`renderPreviewDocument` +
  `buildPreviewWebviewHtml`, content container inner HTML only) and posts `previewBaselineDiff {html, hunks}`.
  HEAD rendering is cached per HEAD text; posted again on every render and when HEAD moves. Empty baseline for
  an untracked or unrenderable HEAD. Needs `showIncomingChanges` on and a trusted workspace (like the bars),
  but not the Diff button state.
- Page (`src/page/modules/sideBySide.ts`): the button `[data-sphinx-preview-sbs-toggle]` (toolbar row 3, after
  Diff) toggles `data-sphinx-preview-sbs` on `<html>`. Changed blocks (innermost mapped element met by a hunk,
  lifted to its list/table/pre) get a card inserted before them (grid, HEAD blocks left, a copy of the current
  block right, words marked by `diffSegments`); the original gets `data-okf-sbs-replaced` and is hidden by CSS.
  Added block: empty left; removed hunk with no changed block holding it: card with empty right at its place.
  Edit mode: button disabled, cards hidden by CSS and not built, green bars unchanged. A baseline of an older
  revision than the page content is ignored; a baseline received while the page is off is answered by
  posting `on: false`. The file is never touched (the module only reads and builds DOM).
- Protocol: `previewSideBySideChanged {on}` (page to host, gate `render`), `previewBaselineDiff {html, hunks}`
  (host to page, rule `render`, validated: html <= 20 MiB, hunks <= 100 000, integer lines, ends >= start - 1).
