# T1 round 1 report: CR 138 table column minimum width

## Behaviour

The rendered preview (read mode) had no cell minimum at all: `overflow-wrap: anywhere` made a
column's minimum content width one character, so a table slightly wider than the text column
squeezed text columns letter by letter ("docu/ment", "par/se", "HT/ML/out", "16/0 ms").
"Doubling" a minimum of about zero is meaningless, so this is an autonomous decision to list in the
PR body: read-mode cells of content tables get `min-width: 5em` (the frontmatter properties table
`.okf-properties` is excluded, it sizes its own columns). A table that no longer fits then uses the
existing wide-table behaviour (breakout in Auto, sideways scroll in Margin/Full).

Edit mode (CR 113) does NOT share the rule: it keeps its own `min-width: 8em` (300px for the edited
cell) in `editModeStyles.ts`, which outranks the new read rule by specificity. The two are separate
rules; the 8em value is unchanged.
