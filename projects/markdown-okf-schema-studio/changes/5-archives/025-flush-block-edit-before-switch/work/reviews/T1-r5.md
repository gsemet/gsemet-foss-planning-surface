## Fix correctness

- No editor open, or only a block editor: `flushOpenEditorsThen` calls `navigate` synchronously, so
  behavior is the same as before. Same-page anchors and the paths without a hook still post at once.
- Refused plain save: `receiveFrontmatterResult` re-enables the editor and then runs `afterResult`.
  `flushFrontmatterEditor` posts the save with `flush: true` and then the navigation or answer. The
  host still waits (`settleHostEdits`), so the typed text is written. The refused save made no edit,
  so there is one undo step.
- Accepted plain save: `saving` stays true, so the flush is a no-op. There is no second save and no
  extra undo step, and the navigation follows the result.
- No result: a 1000 ms page timer, below the host's `FLUSH_WAIT_MS` 1500, leaves about 0.5 s for the
  round trip. The `done` guard and `clearTimeout` stop a double navigate. Chained `afterResult` (two
  quick clicks) navigates once per click, as before.
- Key editor: the in-flight object now has `save`/`cancel`/`plainSavePending`. On refusal,
  `control.disabled=false`, so `saveKey` re-posts as a flush. This is correct, but untested (see
  below).
- Link and Back/Next: they pass `navigate` as a continuation, so a real pointer click (blur then
  click) is covered too. `previewEditFlushed` captures `flushId` before the async answer.
- readOnly and untrusted refusals are unchanged; there is no host change.
