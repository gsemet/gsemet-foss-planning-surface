## Map of trigger paths

| Path | Who starts it | Before | Now |
|---|---|---|---|
| Link to another file (`previewLink`, from `linkNavigation.ts`) | page | page posted only the link; the blur commit was the only save, and the host ran `handlePreviewLink` concurrently with the save, then `vscode.open` switched the document while the edit was still applying (`activeBlockEditSource` then failed: "source block changed") | page calls `flushOpenEditors()` then posts the link (anchors `#...` excluded: same page); host `handlePreviewLink` awaits `settleHostEdits` first |
| Toolbar Back / Next (`previewHistoryGo`, `historyControls.ts`) | page | host refused with a status bar message while a block edit was active; typed text not yet autosaved was neither saved nor kept | page flushes then posts; host awaits `settleHostEdits` and then goes (refusal removed) |
| Preview follows active editor (`followActiveEditor` -> `switchPreviewDocument`) | host | switch immediately, page unaware | `switchPreviewDocumentAfterFlush`: `flushPageEdits` (ask the page, wait for its answer, wait for the saves), then switch |
| Open Preview on another file while a follow preview exists (`openPreview`) | host | same | same helper |
| Webview hidden / disposed / window close / Reload Window | VS Code | `pagehide` and `visibilitychange` flush a pending autosave | unchanged; proven by existing unit tests `pagehide flushes a pending autosave...` and `visibilitychange to hidden flushes...` (scrollSync.test.ts ~4391-4430), not broken. `retainContextWhenHidden: true`, so a hidden panel stays alive and still answers a host flush |
| Panel dispose by `switchPreviewDocument` replacement (different workspace root) | host | n/a | covered by the same flush before the switch |

## Ordering guarantee

- Page to host messages arrive in order. The page posts `previewEditSave` (final) and/or `previewFrontmatterSave`, and only then the navigation (`previewLink`, `previewHistoryGo`) or the answer (`previewEditFlushed`).
- Host `handlePreviewEditSave` starts the WorkspaceEdit synchronously on arrival (`activeBlockEdit`, `applying`), frontmatter and checkbox saves are tracked in `preview.pendingSaves` (`trackPendingSave`). Before navigating, the host waits until `activeBlockEdit` is cleared (released after the apply and `completeActiveBlockEdit`) and `pendingSaves` is empty (`settleHostEdits`).
- Host-started switches ask the page first (`previewFlushEdit` with a flush id); the answer is matched by flush id only (not by stage ids, so a render that moved the stage does not lose it), then `settleHostEdits`.
- Every wait is bounded (1500 ms): a dead page, a refused save or a stuck apply never blocks the navigation.
- `handlePreviewLink` now compares `activeDocumentIdentity` instead of the stage object, because the flush's own save legitimately re-renders the old document (new stage) while the link resolves.
- Read-only / untrusted previews: the host sends no flush request (`preview.readOnly`), and the existing refusals of `previewEditSave` / `previewFrontmatterSave` stay. The new message `previewEditFlushed` edits nothing.
- One undo step per saved edit is unchanged (same save messages and same `applyEdit` path). Nothing changes when no editor is open: the page answers `flushed: false`.
- Invalid content: a block or table cell is written as typed (same as autosave). A frontmatter value editor with invalid YAML is sent with `flush: true`; the host then keeps the text as typed as a string value instead of refusing. A normal save still refuses invalid YAML.

## What only CI can prove

- All five real-input scenarios (real keystrokes, real webview, real tab switch, real Back).
- That the host `previewFlushEdit` roundtrip finishes well inside `FLUSH_WAIT_MS` in a real window, and the added async hop in `followActiveEditor` does not break existing integration scenarios that switch document and assert immediately.
- The invalid-YAML scenario assumes `title` accepts a string under `REQ_SCHEMA` (it should); the exact written form is only checked with `includes("a: [unclosed")`.
- The link/Back scenarios click with a real pointer, so the blur commit also fires; the pure race (no blur) is exercised by the tab-switch scenarios.

## Open points

- Frontmatter flush of a value that fails schema validation (not YAML syntax) is still refused by the host, so that text is not saved on a navigation. Only YAML syntax errors are kept as typed.
- Two host-started switches queued behind each other where the first replaces the ActivePreview (different workspace root) drop the second; the follow event fires again on the next editor change.
- Flush before pagehide only covers block editors (unchanged); a frontmatter editor open at window close relies on its blur save.
