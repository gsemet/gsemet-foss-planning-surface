- Host, `handleFrontmatterSave` in `src/extension.ts`: with `message.flush === true` it now skips the YAML-syntax refusal (round 1), the `frontmatterValueMatchesField` type refusal, and the whole schema-candidate block (validation error, missing candidate field, type mismatch). It uses real typing in the real editors, then a tab switch, for three cases: `meta` (object field, YAML editor) with `[unclosed` (invalid YAML), `meta` with `just text` (valid YAML, schema-invalid), and the `count` number field emptied (bad number). Fixture frontmatter gained `count: 3` and `meta: {a: 1}`, schema gained `count: number` and `meta: object`.

## F2 (medium): A -> B -> A during the flush

`switchPreviewDocumentAfterFlush` now records every request in a per-panel `LatestRequest` (new, `src/preview/flushWait.ts`). Each queued run, after its flush, calls `settle()`; only the last queued run returns the latest document and switches to it, and `switchPreviewDocument` re-checks "same document as the preview" at that moment. The early "already showing it" return only applies when nothing is queued (`idle`). So B queued, then A requested, ends on A. Unit test: `LatestRequest applies only the latest request, so A to B to A ends on A` (test/state/flushWait.test.ts).

## F3 (medium): link and Back scenarios now exercise the flush, not the blur commit

New helper `clickWithoutBlur` in `realInput.test.ts`: it asserts the caret is still in a TEXTAREA/INPUT, then dispatches a `click` MouseEvent (Meta on macOS, Ctrl elsewhere) on the link or on `[data-sphinx-preview-back]` with `element.dispatchEvent`. A dispatched event does not move focus, so the text box never blurs and the blur commit (`saveBlockEdit` on blur) cannot save the text. The only save left is the one posted by `flushOpenEditors()` from `linkNavigation`/`historyControls`, immediately before `previewLink`/`previewHistoryGo`. The typing uses a 5 ms key delay, so the whole sequence is far below the 400 ms autosave. The link and Back scenarios use it; the Back click at the end of the link scenario (after the typed text is saved) stays a normal click.
