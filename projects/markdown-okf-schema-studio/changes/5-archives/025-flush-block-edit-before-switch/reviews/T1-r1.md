## What is sound

- Ordering. The page posts the final save(s) before `previewLink` / `previewHistoryGo` / `previewEditFlushed`. The host starts the apply synchronously on arrival, and `settleHostEdits` waits for `activeBlockEdit` and `pendingSaves` to clear. The arrival-time `matchesCurrentPreview` check still sees the old stage, so the messages are not dropped.
- Bounded wait. `waitForAnswer` clears its timer. `waitForSettled` polls to a deadline and also ends on `disposed`. `flushWaiters` is deleted after the wait. No leaked listener or timer, and no deadlock for a dead, unready or disposed page. A `postMessage` that rejects falls through to `settleHostEdits`.
- Untouched editor: `postBlockEditSave(true)` closes it and posts nothing. The host lock is only taken on the first save, so there is no 1500 ms wait.
- No double save: `postBlockEditSave` clears the autosave timer. The T22 blur logic and the palette are untouched, since `flushOpenEditors` calls `postBlockEditSave` directly. Same-document `#` anchors skip the flush. `previewEditFlushed` is in the registry and edits nothing. A read-only preview sends no flush request, and the existing refusals stay.
- The "Finish the open block edit" refusal had no test or doc left behind (grep). Replacing it with flush-then-go matches the user's decisions.

## Findings

### F1 HIGH - typed frontmatter text can still be lost on a flush (contradicts the user decision)
`src/extension.ts:1583-1590`, then `1651-1700` (the schema checks).
- The flush only skips the YAML-syntax refusal. After that, `frontmatterValueMatchesField` (`1532`) and the "Schema validation failed" refusal (`1688`) still reject.
- The YAML editor is used for `list`, `unknown` and structured fields (scrollSync.ts `useYamlEditor`, ~1933). With a schema, a list field that holds invalid YAML becomes a string. `Array.isArray` fails, so it is refused and the page has already navigated away. The text is gone. The report admits this.
- The same loss happens for a valid-YAML value that fails schema validation, and for a number field that the page rejects with "Enter a valid number" (the page-side early return in `saveValue`, ~2323).
- The invalid-YAML test (`scenarioFlushInvalidYamlKeptAsTyped`) uses the `title` text field. That field never goes through the YAML editor in the UI, so the test proves a path real users cannot reach.

Fix, one of two options:
- (a) When `message.flush === true`, skip the schema and type checks (`frontmatterValueMatchesField`, `validationError`, `candidateField` not found) and write the value as typed. The preview then shows the validation diagnostic, as the autosave does for blocks. Keep the stale-field and duplicate-key refusals, because those cannot write anything.
- (b) Make the page keep the text in a fallback (for example a draft restored when the editor reopens) and say so.
(a) matches "write as typed, no data loss".

Also make the page-side number case post the raw text on flush instead of returning. Rewrite the test as a list field with a schema and invalid YAML, driven by real typing in the YAML editor, followed by a tab switch. Add a unit test for the host `flush` bypass. Is `handleFrontmatterSave` testable?

### F2 MEDIUM - race when the user switches A -> B -> A during the flush wait
`src/extension.ts:3952-3965` (`switchPreviewDocumentAfterFlush`).
- The guard `documentKey(document) === preview.documentUri` is evaluated at call time. With the preview on A, the switch to B is queued behind a flush. If the user returns to A before B runs, the second call returns early. The queued switch to B then runs and the preview shows B while the editor is on A. It is corrected only by the next editor event.
- The comment "the last request wins as before" is not true here.

Fix: store the latest requested document per panel (a WeakMap). In the chain's final `.then`, switch only to the latest request, or compare it with `vscode.window.activeTextEditor` / the latest request. Re-run the "same document as the preview" check at that point. Add a unit test or an integration step.

### F3 MEDIUM - the link and Back scenarios do not prove the race
`test/integration/realInput.test.ts:~3975-4027`.
- They click with a real pointer, so the textarea blur commits the final save before the flush runs (the report admits this). They pass on unchanged code for the same reason and do not guard the page-side flush ordering. Only the tab-switch scenarios cover it. The unit tests cover the ordering, which is acceptable, but the real-input claim "one per trigger" is overstated.
- Fix: use keyboard focus-preserving activation (focus the link with `Tab`/`Enter`, or dispatch the click through `page.evaluate` so no blur happens). Alternatively invoke the toolbar Back by its keyboard shortcut.

### F4 LOW - cell test assertion fragile
`test/integration/realInput.test.ts:4065`. `"| alpha | one1 |"` assumes the table serializer does not re-pad columns. The header `Value` is 5 wide and `one1` is 4. Assert with a whitespace-tolerant regex (`/\|\s*alpha\s*\|\s*one1\s*\|/`) unless scenarioTableMinimalDiff guarantees the exact form.

### F5 LOW - behaviour notes
- The flush runs on every non-anchor link click (external or blocked targets too) and on every Back/Next, including a same-document Back. It saves and closes the open editor even when the page stays. This is consistent with "save then close". Mention it in the PR.
- Every host-started switch now costs a page round trip, and up to 1.5 s with an unresponsive page. This is acceptable and bounded. It can alter timing in the existing integration scenarios. CI must confirm.
- The `pagehide` flush still covers only block editors, not the frontmatter editor (the report lists it as open). The user decision covers window close / Reload. Consider calling `flushOpenEditors()` from `pagehide` too, with `final=false` semantics, or document the limit.

### F6 LOW - CHANGELOG overclaims
`CHANGELOG.md` (new bullet): "Text that is not valid YAML in a property is kept as typed." This is false until F1 is fixed. After F1, re-read it. The rest of the bullet is accurate.
