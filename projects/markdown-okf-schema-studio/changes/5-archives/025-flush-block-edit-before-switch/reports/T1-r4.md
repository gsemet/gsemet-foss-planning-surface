# T1 round 4: CI failure in scenarioFlushFrontmatterKeptAsTyped

Worktree markdown-okf-schema-studio-wt-025, nothing committed.

## Cause: test-harness bug, not a product bug

`scenarioFlushFrontmatterKeptAsTyped` (test/integration/realInput.test.ts) never opened a preview.
Each scenario uses a fresh fixture inside `withFlushDocuments`, which only opens the text documents.
The other flush scenarios (a to d) call `openSidePreview(first)` + `waitForRender(first)` first; scenario e went
straight to `showTextDocument(first)` + `waitForPreviewOf(first)`, so no preview existed and the wait timed out
(the failing line is the first `waitForPreviewOf(first)` of the loop). The flush/switch code was not involved.

## Fix

Added `await openSidePreview(first); await waitForRender(first);` before the case loop. Intent and assertions unchanged.
Edit mode is still enabled inside the loop by the existing check.

## Other scenarios after it

Scenario d (cell + frontmatter) already opens the preview; it ran no earlier than e so it is untested in CI, but
it follows the same pattern as a to c, which passed. Later scenarios (SaveKeepsBlockInPlace etc.) are pre-existing.
