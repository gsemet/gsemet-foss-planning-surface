## R2-1: pagehide / hidden page flush a frontmatter editor

- `src/webview/scrollSync.ts`: `pagehide` and `visibilitychange` (hidden) now call `flushHiddenPage()` = the existing pending-autosave flush plus the new `flushFrontmatterEditor()` (extracted from `flushOpenEditors`, runs `edit.save()` inside the `flushingEditors` guard, so the save carries `flush: true`).

- Unit tests: "pagehide and a hidden page save an open frontmatter editor as a flush" (fails on old code), "pagehide saves the typed text of an open table cell".

## R2-2: a refused flush is no longer silent

- Block and frontmatter saves sent by a flush now carry `flush: true` (block saves too; validator `validFlush` accepts it on `previewEditSave` and `previewFrontmatterSave` only).
- `postFrontmatterEditError` and `postEditSourceError` (`src/extension.ts`) show `vscode.window.showWarningMessage` when `message.flush === true`, naming the field (`the frontmatter field "x"`, renamed key if any) or the block (`the block at lines A-B`), with the reason and "That text was not saved." These two helpers cover every refusal and failure (stale field, duplicate/empty key, rejected WorkspaceEdit, stale block, source changed). A normal save posts only the in-page error, as before.
- Pure helper `flushRefusalMessage(what, reason)` in `src/preview/flushWait.ts`, unit test in `test/state/flushWait.test.ts`. Test "a flushed block save carries the flush flag, a normal save does not" (fails on old code).

## R2-3: key typed with spaces

`saveKey` during a flush trims the typed key; an empty or unchanged result closes the editor keeping the old key. A normal save still refuses padded keys. The flushed rename message carries `flush: true`. Unit test "a key typed with surrounding spaces is trimmed on a flush and refused otherwise" (fails on old code).
