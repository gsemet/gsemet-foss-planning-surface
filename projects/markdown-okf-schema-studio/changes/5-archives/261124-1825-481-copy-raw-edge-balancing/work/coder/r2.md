## Core fix (found by the new check)

`src/page/features/rawCopy.ts`: `isPageChrome` treated any element with a `data-line-number` attribute as chrome. A code line is
`<span class="myst-code-line" data-line-number="1">code text\n</span>` (the number is drawn by CSS from the attribute), so every
code line was chrome: any selection that started or ended in a code block was left to the browser (also with the setting off, and
in the base CR), and the copied HTML lacked the code. The attribute is no longer a chrome test; `renderedHtml` removes the
`data-line-number` attribute from the copied HTML instead (the visual `CHROME` assertion still holds). No core-module test was
added: the rule lives in the page's chrome predicate; the visual v55 off cases (code word and code lines in a list item) and v56
code cases are the failing-then-passing proof (they failed with "the copy was left to the browser" before the fix).
