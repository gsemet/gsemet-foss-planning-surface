## What changed

### 1. Warning banner for conf.py MyST warnings (decision 1)

- `src/preview/previewStatus.ts` (new): the status-region markup, moved out of `webview.ts`
  because `webview.ts` imports `vscode` and the visual page builder must use the same markup.
  `webview.ts` re-exports the names it used to export, so callers did not change. Diagnostics now
  carry an optional `code`, and each status line gets `data-sphinx-preview-diagnostic-code`
  (`myst-extension` for the conf.py checks).
- `src/webview/warningBanner.ts` (new, injected with `.toString()` like its neighbours):
  - `warningBannerState(status, lines, dismissedKey)` decides when the banner shows: only for a
    `success` status with at least one `myst-extension` line.
  - It also builds the key: an FNV-1a hash of the sorted messages, with the `file:line[:col]: `
    prefix removed so that moving a line does not count as a new set.
  - `warningBannerText(n)` gives the text: "N MyST syntax warning(s) from conf.py".
  - `installWarningBanner` builds `[data-sphinx-preview-warning-banner]`: `role=status`,
    `aria-live=polite`, an icon (CSS mask), the text, an **Open Problems** button and a close
    button (`×`, `aria-label="Close the warning"`). The banner is placed right after the status
    region, so it comes first in the Tab order.
- `src/webview/scrollSync.ts`:
  - installs the banner and calls `warningBanner.update()` in `initializeContent`, which runs on
    load and after every content patch;
  - copies the line code in `applyStatusRegion` and checks it in `isValidContentPatch` (an
    optional string of at most 100 characters);
  - adds two new runtime context fields, `dismissedWarningBanner` and `warningsInProblems`.
- `src/preview/previewMessages.ts`: two new message types.
  - `previewShowProblems` carries nothing.
  - `previewWarningBannerClosed` carries `key`, at most 32 characters, matching
    `^[0-9a-z]+-[0-9a-f]{8}$`.
- `src/extension.ts`:
  - The session map `dismissedWarningBanners` (document URI → closed key) feeds
    `dismissedWarningBanner` into `scrollContext`. `warningsInProblems: false` is set when the
    workspace is not trusted.
  - The `previewShowProblems` handler runs `workbench.actions.view.problems`. The
    `previewWarningBannerClosed` handler stores the key.
  - Both messages are gated on `documentId` only, like `previewPlantUmlInclude`, so a page one
    render behind still works. Both are allowed in read-only and untrusted previews because they
    edit nothing.
- `src/preview/previewStyles.ts`: banner styles in the stylesheet only (no `style=`).
  - Placement: `position: absolute` at the top left (top 6px, inside the 40px gap above the first
    element), 30px high, one line. The width is capped so it ends left of the floating toolbar:
    196px reserve, 164px when the toolbar is collapsed.
  - Colours come from theme variables. The yellow accent is
    `color-mix(charts-yellow 75%, editor-foreground)`, which is readable on light, dark and cream.
    There is a forced-colors fallback.

### 2. Pasted image (decision 2)

- (a) `src/webview/pasteImage.ts`: `imageParagraphEdit(value, start, end, name)` inserts the image
  as its own paragraph.
  - It adds a blank line before and after, unless the image is at the start or end of the text or
    a blank line is already there.
  - Spaces and tabs around the caret are dropped, so no line keeps trailing blanks.
  - The file name is selected after the paste.
  - The paste hook in `scrollSync.ts` now uses it.
- (b) `src/preview/previewStyles.ts`: `p:not([data-sphinx-preview-figure]) img { vertical-align: middle; }`.
  - Root cause: the HTML was already inline. The real-window capture looked "above the paragraph"
    because a 96px image sits on the text baseline, so the short text line sits at the bottom of
    the image.
  - With the fix, the line runs through the middle of the image.
  - Paragraphs that hold only an image (`data-sphinx-preview-figure`, set by `widthMode.ts`)
    keep their centred figure behaviour and the default alignment.

## Autonomous decisions (not covered by the spec)

1. **Banner placement.** The banner is absolute, not fixed and not in the flow. It sits in the
   40px gap above the first element, left of the toolbar. So:
   - it takes no room and moves no content or scroll-sync anchor (asserted);
   - it never covers the sticky heading band (it scrolls away with the top of the page);
   - it never covers the toolbar (asserted).

   The trade-off: a user scrolled down only sees it at the top of the page. The Problems view and
   the squiggles are unchanged.
2. **"Stays closed for the session"** means: until the extension host restarts (a module-level map
   keyed by document URI), plus the page's own memory across content patches. The key ignores the
   `file:line` prefix, so editing above a warning does not bring the banner back. A warning added
   or removed does.
3. **Only the `success` status shows the banner.** `recovery`, `stale` and `error` already show
   their status region with the diagnostics list, so a banner would repeat it.
4. **Restricted Mode.** `publishMystDiagnostics` publishes only in trusted workspaces, so the
   Problems view is empty there. The banner then has no Problems button, and its `title` tooltip
   lists the warning lines. The lines also stay in the status region for assistive technology.
5. **Texts.** "N MyST syntax warning(s) from conf.py" (the count first, so the ellipsis in a very
   narrow pane keeps it), the button "Open Problems" (aria-label "Open the Problems view to see
   the warnings"), and a close button with aria-label "Close the warning".
6. **Paste in the middle of a line** splits the paragraph around the image paragraph. Spaces or
   tabs at the caret are dropped. A selection is replaced.
7. **Inline image fix.** The fix is `vertical-align: middle` on images in non-figure paragraphs.
   I did not cap the image height: a large inline image still makes a tall line, but it reads as
   part of the line.
8. **Status markup moved** into `src/preview/previewStatus.ts`, so the visual page uses the real
   markup. Every status line now carries its code attribute, not only `myst-extension`.
