## Design (decision update honoured)
Bars cannot sit in one column as pseudo-elements/shadows of each block (indent differs per block, pre/table/img clip or round them). So `incomingChanges.ts` appends one `div[data-sphinx-preview-change-layer]` (aria-hidden, pointer-events none) to the body, with one `<span>` per marked block. `layout()` sets only `top` and `height` (setProperty, same pattern as other webview code) from the block's box; the stylesheet gives every bar the same `inset-inline-start: 8px`, `width: 3px`, `border-radius: 0`, the gutter colour (works in light/dark/cream, RTL via inline-start). No block gets any padding/margin/shadow change, so nothing moves, no ancestor clips the bars, full block height. A code block is marked on its inner `<code>`, so the bar uses the enclosing `<pre>` box. `layout()` runs after `apply()` (also when ranges are cleared), from `stabilizeLayout` (existing ResizeObserver on the content, image loads) and on window resize. Diff toggle off: `html[data-sphinx-preview-incoming="off"] [data-sphinx-preview-change-layer] { display: none }`.
