## What was built

- A chevron on every heading that has content below it (shown on hover, on focus and while folded).
  Pressing it hides every block up to the next heading of the same or a higher level. Folded blocks are
  `hidden="until-found"` + `data-okf-folded`, so the browser find still reaches their text and the page
  unfolds the section on `beforematch`.
- Keyboard: `Cmd+Alt+[` / `Ctrl+Alt+[` toggles the current section (focused heading, else the last heading at
  the reading line). Ignored in text boxes.
- Fold all / Unfold all: new Fold button in toolbar row 3 (between TOC and Diff, aria-pressed while any
  section is folded) and two command-palette commands, "Fold All Sections in Preview" and "Unfold All Sections
  in Preview" (palette only offered when a Studio preview or custom editor has focus).
- View state, never written to the file: folded keys (`level|text|occurrence`, same shape as the TOC keys)
  kept per document in the webview state (`headingFolds`, at most 24 documents), re-applied after every content
  patch and reload.
- Navigation unfolds the target: `revealElement` (TOC click) and `navigateToAnchor` unfold the folded
  sections around the target and re-measure.
- Edit: blocks of a folded section are left out of `selectableBlocks` and `bodyBlockAtLine`; folding is refused
  while a block or frontmatter editor is open; the chevron click is stopped so it never opens an editor.

## Open points

- The `Cmd+Alt+[` shortcut is covered by unit tests only; the QA helper cannot press `[` so it was not driven in a
  real window. No real-window integration test (test/integration) was added for folding.
- Fold state lives in the webview state (survives reload and window restore of the same panel), not in host
  workspace state; a closed panel forgets it.
- A folded heading whose text is edited loses its fold (key = level|text|occurrence). Stale keys of deleted
  headings stay in the state until fold/unfold all clears them.
- In edit mode the insertion bars inside a folded section are hidden with it (no insert under a folded heading).
- Folded blocks are `content-visibility: hidden`; very tall folded content keeps its layout cost low but is still
  in the DOM.

## Autonomous decisions

- Per-document fold state kept in the webview state (reuses the TOC key scheme), not a workspace preference.
- `hidden="until-found"` + `beforematch` for "search unfolds the target" (native Webview find has no other hook).
- One toolbar Fold button that toggles (fold all / unfold all) instead of two buttons; the two commands are
  separate palette entries.
- Shortcut `Cmd+Alt+[` / `Ctrl+Alt+[` (VS Code's own fold keys, matched on the physical key).
- New StRS-TOOLBAR-002 and SwRS-TOOLBAR-003/004/005/006/008 (IDs from `okfreq new`; 007 existed).
- Folding is refused while a block/frontmatter editor is open rather than closing the editor.
- Process note: once I started a QA-helper window before noticing another task held WINDOW-TESTS.lock (my wait loop
  did not stop); I stopped it within a minute without touching the lock, then waited and took the lock properly.
