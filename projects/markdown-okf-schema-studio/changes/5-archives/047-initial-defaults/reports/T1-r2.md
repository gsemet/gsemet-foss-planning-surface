## Root causes

1. Static job (run 39981315097): `test/security/package-contract.test.ts:236` failed with
   `the built-in PlantUML engine ships pinned and the JAR is an explicit opt-in setting`.
   - The PlantUML PR added this test. It reads
     `packageJson.contributes.configuration.properties[...]` as an object.
   - This CR turned `contributes.configuration` into an array of categories, so
     `.properties` is `undefined` and the test throws.
2. Integration job (run 39980605279): `paletteMode.test.ts:79` failed with
   `the setting gives the first mode 'myst' !== 'strict'`.
   - In round 1, `trusted-suite.ts` calls `pinStoredWorkspaceChoices()` first. That call stores
     the palette mode `myst` in workspace state.
   - The first step of the palette test assumes that nothing is stored yet. It sets
     `editing.defaultPaletteMode` to `strict` and expects the first preview to start in `strict`.
   - The product rule (decision 2, `initialPaletteModeOf`) says a stored mode wins over the
     setting. So the preview correctly started in the pinned `myst`.
   - The test's precondition no longer held. The product was correct.

## Fixes

- `test/security/package-contract.test.ts`: the PlantUML test now types `configuration` as
  `ConfigurationCategory[]`. It reads `useJar` and `jarPath` through the existing round-1 helper
  `contributedSettings(...)`. Every assertion is unchanged.
- `src/extension.ts`: new test-only export `clearStoredPaletteModeForTests()`, which removes the
  stored palette mode. It follows the same pattern as `resetPreviewThemeModeForTests`, and no
  product path calls it.
- `test/integration/extensionApi.ts`: re-exports it.
- `test/integration/paletteMode.test.ts`: before the "nothing stored yet" step, the test calls
  `clearStoredPaletteModeForTests()`, which restores the precondition the step describes.
  - Its existing last step still stores `myst` again for the suites that follow.
  - No assertion changed. The test still checks, in order: the setting decides, the stored mode
    wins over the setting, and an invalid mode is not stored.
- `README.md` (review nit N1): the Settings intro now says that the theme and toolbar state are
  built-in starting points, and that the palette follows `editing.defaultPaletteMode`.
