## Optional nits

- N1 (doc wording), `README.md:313-316`: "these are built-in starting points, not settings" is
  true for the theme and the toolbar. The GFM palette, though, is the default of the
  `editing.defaultPaletteMode` setting, which is listed a few lines below. Suggested wording:
  "the theme and toolbar state are built-in starting points, not settings; the palette follows
  `editing.defaultPaletteMode`. A choice you make in the preview is remembered per workspace."
- N2 (fixed waits), `test/visual/capture.py`: the new `check_preview_toolbar` wrapper (expand
  click and recollapse click) uses `page.wait_for_timeout(200)`. This follows the harness idiom in
  the same function (about 139 existing uses), so it is not blocking. A wait on the state change
  would honour the "no fixed sleeps" rule better, for example
  `page.wait_for_function("document.documentElement.getAttribute('data-sphinx-preview-toolbar-state') === 'expanded'")`.
  If the 200 ms is there for the toolbar re-measure, keep it and add a comment saying so.
- N3 (duplication): `PINNED_WORKSPACE_CHOICES` is defined twice, in `test/visual/renderOptions.ts`
  and in `test/integration/storedChoices.ts`. The two have the same value. That is acceptable
  because they belong to two separate harnesses, but a comment that cross-references them would
  keep them in sync.
- N4 (coverage, informational): the trusted, scroll-sync, untrusted and standalone real-window
  suites were not run this round. Only the reload suite was run. Run the manual heavy CI job
  (`gh workflow run ci.yml --ref feat/initial-defaults -f heavy=true`) before marking ready, as the
  coder suggests.
