## Product changes (decisions 1-3)

- `src/state/previewTheme.ts`: new `DEFAULT_PREVIEW_THEME_MODE = "cream"`.
- `src/webview/scrollSync.ts`: the page fallback for the theme mode (no stored mode from the
  host, no webview state, or an invalid mode) is now `DEFAULT_PREVIEW_THEME_MODE`. The palette
  fallback is now `DEFAULT_EDITING_CONFIGURATION.defaultPaletteMode`. Both values come from the
  single constants and are no longer duplicated literals.
- `src/state/previewViewPreferences.ts`: `DEFAULT_VIEW_PREFERENCES.toolbarCollapsed = true`.
- `src/webview/toolbarCollapse.ts`: the page fallback (no `initialViewPreferences`) is now collapsed
  (`!== false`).
- `src/configuration/editingConfiguration.ts`: `defaultPaletteMode` default `gfm`. New pure
  `initialPaletteModeOf(stored, source)`: a valid stored mode wins, otherwise the setting. The
  host's `initialPaletteMode()` in `src/extension.ts` now uses it, so it has unit tests.
- `package.json`: `editing.defaultPaletteMode` default `gfm`.
- Stored choices win (decision 2): the host still sends a theme mode only when one is stored. View
  preferences are normalised field by field, so a stored `toolbarCollapsed: false` is kept. The
  stored palette mode wins over the setting. The defaults are never written to storage (no message
  is posted on startup).
- Every other default is unchanged (decision 3).
- `src/extension.ts`: new test-only export `storeWorkspaceChoicesForTests` (same pattern as
  `resetPreviewThemeModeForTests`), used by the integration pin below.

## Autonomous decisions

1. The visual and integration pins are one named constant each, applied by the harness, instead of
   being repeated in about 300 visual scenario definitions. Only the fresh-workspace pages opt out.
   This keeps the pin explicit and reviewable in one place, and keeps every existing PNG
   byte-identical.
2. The fresh-workspace scenario is in group theme-zoom (cream is the theme default). The dark host
   uses 460 px so that its PNG differs from the light one.
3. The fresh scenarios set `previewThemeMode: "cream"` and `toolbarState: "collapsed"` as the
   expected state. This reuses the cream palette checks and the final collapsed check.
   `check_fresh_workspace` runs before anything can click, so a regression cannot be hidden by
   those checks.
4. A test-only `storeWorkspaceChoicesForTests` export, rather than sending page messages, so the
   suites can pin the choices before the first preview opens.
5. The static toolbar markup (`previewToolbar.ts`: theme button "current", collapse button
   expanded) is unchanged. The page script sets the real state at once, and the markup cannot know
   the stored choice.
6. README images are not regenerated, because their sources are unchanged.
7. The untrusted window capture (`trust-security/r01`) and the reload captures now show the cream
   theme, because those windows are fresh workspaces. I did not pin them.
