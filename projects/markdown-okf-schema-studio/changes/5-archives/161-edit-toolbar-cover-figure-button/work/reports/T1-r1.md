# T1 round 1 report (CR 161)

## Root cause (geometry)
Integration log: viewport 421 px, toolbar rect top 12 / bottom 178 / left 290..304, figure 60 px under the pane top.
`installFigureEditButton.place()` (src/page/modules/figurePanel.ts) puts the button at the figure's top right and,
when the figure is under the sticky chrome, pushes it down to `usableTop + 2` (toolbar bottom 178 + 4 = 182 -> 184),
but clamps it to `figure.bottom - 34` so it stays inside the figure. The test figure (240x120 svg, 60%) is short:
reproduced in the mock host at 420 px: figure 59.8..152.6 (93 px), so lowest = 119; button 290..363 x 119..138 lies
fully inside the toolbar (304..406 x 12..178) -> `elementFromPoint` at the button centre is the toolbar's
"Fold all sections" row (row 5). With the four-row toolbar (bottom ~134) the same figure had room, hence green before.
Not a flake: a layout collision, deterministic.

## Decision: product
Product promise holds: the button is the way to open the figure form (SwRS-MDOKFSTUDIO-PALETTE-153) and the
existing code already intends it to be "pressable below the sticky chrome" (usableTop). A short figure at the top
right of a narrow pane made it unreachable for users too. The test aims at a spot that is reasonable; I did not
touch the integration test (no force click, no retry, no assertion change).
