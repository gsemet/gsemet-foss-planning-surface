## Findings

1. **The SwRS claims a behaviour that the code does not have, and no test covers it.**
   `requirements/tiers/swrs/layout-width/SwRS-MDOKFSTUDIO-LAYOUT-023.md:81` says "the editor moving to
   another cell changes nothing". The spec's Done-when also says that moving between cells keeps the
   table at its breakout width. In edit mode, the selected cell gets `min-width: 300px`
   (`src/core/preview/styles/editModeStyles.ts:316-318`). The table is now measured while a cell is
   edited, so each move changes its natural width and the breakout follows it. I measured this in real
   Chromium: the page and stylesheet of `tableBreakout.test.ts`, edit mode on, and a frame built like
   the real one (class, hidden cell content, textarea, Done and Cancel buttons). I put it in different
   cells and ran a layout pass each time:
   - ten columns, tick matrix: 734 px with no editor, then 933, 1003, 933 and 1009 px;
   - three columns with a long URL: 795, then 1033, 795, 795 and 980 px;
   - six columns, mixed text: 907, then 1068, 1068, 1068 and 907 px.

   Before this change, the box kept the column width while a cell was edited. Now, in a table that
   breaks out without reaching the cap, a move between cells re-sizes and re-centres the box by up to
   about 270 px.

   The table always stays marked wide, so no column is cut. But the requirement row is wrong, and the
   Tab, arrow and click moves are not tested. Fix one of these two ways, and take the choice to the
   owner if needed:
   - (a) keep the breakout of a table while a cell editor is open, and re-measure only on a real resize
     (a pane resize or a toolbar change);
   - (b) write the real behaviour in LAYOUT-023: the breakout grows to fit the 300 px minimum of the
     edited cell. Add a test that moves the editor between cells and asserts that the table stays
     wide.

2. **The new test cannot see the real effect of the editor on the layout.**
   `test/page/tableBreakout.test.ts:311-325` builds the frame without the class
   `sphinx-preview-table-cell-editor`, without the hidden cell content and without the Done and Cancel
   buttons, and the page is not in edit mode. So the `min-width: 300px` rule never applies. The
   width-equality assertion at line 325 passes only because the setup is unrealistic: with edit mode on
   and the real frame, the width moves (see finding 1). Make the setup realistic:
   - set `data-sphinx-preview-edit-mode="on"` on `<html>`;
   - give the frame its class, and wrap the cell content as `hideTableCellContent` does;
   - then assert what the requirement says.

   If (a) of finding 1 is chosen, the equality can stay; if (b) is chosen, assert that the table stays
   wide and is not narrower than before.

3. **A table that fits the column now breaks out when one of its cells is edited.** The spec does not
   say this, and no requirement or test covers it. Example: nine short columns of two-word tokens stay
   in the column at 609 px with no editor (not wide). With a cell editor open, the table is marked wide
   at 790 to 878 px, because the 300 px minimum of the selected cell pushes it past the column. Before
   this change, the table stayed in the column and scrolled. The spec says only that a wide table
   keeps its breakout, and "Other width modes: unchanged".

   Decide this with the owner, or at least write it down: a row in the refusal or acceptance table of
   LAYOUT-023 (`SwRS-MDOKFSTUDIO-LAYOUT-023.md:79-81`) and a line in the PR body. The CHANGELOG line
   should then say it too. Option (a) of finding 1 (keep the width the table had when the editor
   opened) would also remove this jump.

4. (Minor) **The editor's text now counts when the columns are sorted.** `planTable` reads
   `textContent` (`src/page/modules/widthMode.ts:152-155`). An edited cell's text now also holds the
   hidden rendered content and the "Done" and "Cancel" labels. A token cell with two or three words
   then counts as four or five words, and the column changes from token to prose (LAYOUT-044) while
   the cell is edited. The token attribute is then removed and the cells can wrap. I did not see a
   table go back to the column in the cases I measured. Still, the plan should skip
   `[data-sphinx-preview-table-cell-editor]` (or read only the rendered content) when it counts words.
   This also keeps finding 1 small.

5. (Minor) **The new refusal row has no test.**
   `SwRS-MDOKFSTUDIO-LAYOUT-023.md:80` ("A wide table holding an editor field other than a cell
   editor: not marked wide") has no test and no "Known issue". Add a case to the new test (a textarea
   outside a cell frame, so the table is not wide), or add a Known issue line.
