## Root cause
VS Code injects `<style id="_defaultStyles">` in every webview, in `@layer vscode-default`, containing `blockquote { background: var(--vscode-textBlockQuote-background); border-color: var(--vscode-textBlockQuote-border); }`. The preview set no background on blockquote, so the host's dark colour (`#2b2b2b` on Dark Modern) showed through whatever the preview theme. Round 1's rule `#sphinx-myst-preview-content blockquote { background: var(--studio-textBlockQuote-background ...) }` is unlayered and has id specificity, so it wins on both counts; `--studio-textBlockQuote-background` resolves to the theme value (cream #efe9dd), not the host colour. Inline code in the quote has its own translucent tint (`rgba` 8% of accent), not a dark background; it only looked dark on the dark quote.

## Test
Unit test models the VS Code default rule (type selector, specificity 0-0-1) and requires every preview rule that sets a background on blockquote to outrank it (small specificity calculator, comments stripped). Fails on the pre-round-1 CSS ("the preview sets a background on block quotes"; round 1's own test fails too), passes on HEAD. Verified by temporarily restoring HEAD~1 of contentBlockStyles.ts, compile, run, then `git checkout` of the file. Limit: a unit test cannot see the real injected layer; the real-window run above is the proof.
