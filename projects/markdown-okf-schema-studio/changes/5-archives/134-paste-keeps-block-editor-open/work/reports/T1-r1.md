# T1 round 1 report (CR 134)

## Reproduction (real VS Code window, before the change)

Case: tall code block of the CR 123 page, editor open, 40 lines pasted with Cmd+V into the text box.
Probe in the webview (message and scroll log) showed the chain:

1. paste: the caret reveal puts the page at scrollY 1480 (caret at the end of the paste, in view).
2. 400 ms later the autosave applies the paste to the document; VS Code scrolls the left text
   editor to the applied edit (first visible line 22).
3. the host sends `sourceScroll line=22` (`ScrollSyncController.syncEditorToPreview`, "the editor
   leads"); `followSourceScroll` moves the page to 643 and the caret (y 1512) is out of view.

No content patch arrived in my runs (document version stayed 1), so the editor did NOT close; the
described "re-render closes the editor" did not reproduce. What reproduces is the page jump and the
caret out of view after a paste. The empty-document "Start writing" paste (CR 123 case b) did not
jump either. So the before-shot matches the user's "scroll jumps" part only, not "editor closes".

Before shots: `reports/shots/before-window-tall-pasted-cream.png`,
`reports/shots/before-window-tall-pasted-dark.png` (page jumped up, caret/end of paste not visible).
After shots: `reports/shots/after-window-tall-pasted-cream.png`,
`reports/shots/after-window-tall-pasted-dark.png` (page stayed, end of paste in view, editor open).
Themes: preview cream and preview dark (VS Code colour theme Default Dark Modern in both).
