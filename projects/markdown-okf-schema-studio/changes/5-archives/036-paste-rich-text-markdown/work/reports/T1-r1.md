## What it does
The page takes over a paste whose clipboard has text/html (image paste with empty plain text still goes first and is unchanged; Cmd/Ctrl+Shift+V is detected by keydown and left native). The HTML goes to the host (parse5 lives host-side, same pattern as image paste), the Markdown comes back and replaces the selection of the moment of the paste. If the conversion fails or is empty, the clipboard plain text is inserted instead.
Converter: headings, bold/italic/strike (tags and styled spans, Google Docs wrapper with font-weight normal handled), links (only http/https/mailto/tel/relative/#), nested lists (incl. Google Docs sibling nested lists, Word mso-list paragraphs, task checkboxes), inline code, fenced code (language from class), blockquotes, GFM tables, images as `[alt](src)` links, hr. Scripts, styles, comments, hidden content, data: images, unsafe URLs and all other attributes dropped; unknown elements keep text only.

## Autonomous decisions (for the PR)
- Images pasted in HTML become `[alt](src)` links (per decision), data: images keep alt text only.
- VS Code copy: several lines become a fenced block without language; a single line stays plain text unchanged.
- Tables with colspan/rowspan/nested tables are not converted: cell text only.
- Hard line breaks `<br>` become a backslash-newline.
- Conversion runs in the host (parse5 is not in the webview), so a paste has one short round trip; 10 s timeout then nothing is inserted if the host never answers (plain text is only used on an explicit failure answer).

## Open points

- Real-window (integration) paste with a true OS clipboard was not exercised; Playwright dispatches a synthetic ClipboardEvent.
