## Not unified (and why)
`figureDirective.ts:123` and `markdownTable.ts:489` test `---` as the YAML option separator of a
directive body, not document front matter; `listTableMove.ts` likewise. They are not front-matter
sites, so left alone (the audit's "five front-matter sites" counted them). Other fence-like regexes
(`mystUnclosedFences`, `sourceEdits`, `sourceTransforms`, `blockMove`, page list-table openers) are
outside the five named sites and were not touched.

## Differences unified (most correct = CommonMark)
1. Fence indent: opens only at 0-3 spaces. Before: `mystGithubAlerts` took any indent, anchoring
   `\s{0,3}` (tabs allowed), mystTargets `[ \t]{0,3}`. A 4-space-indented ``` is now content.
2. Closing fence: same mark, at least as long, nothing but white space after, indent 0-3. Before:
   mystTargets and navigation closed on a line with an info string (```` ```js ````) and ignored
   trailing text; alerts accepted any indent on the closer.
3. Front matter opener: `---` on line 1, no indent (trailing spaces ok). Before anchoring and
   mystSyntaxDetect accepted ` --- ` (trim) and gridToctree `trim()` too.
4. Front matter closer: `---` or `...`, no indent, trailing spaces ok. Before gridToctree used
   `\s*$` (same), anchoring and detect `trim()` (indent accepted). All three now accept `...`.
5. `escapeHtml`: one function, quotes escaped by default. `highlight.ts` called it without
   `&quot;`; changing that broke its existing assertions, so it passes `quotes = false`
   (text content only): output unchanged. `propertiesTable` and `previewStatus` already escaped quotes.
6. `escapeRegExp`: both copies were identical.
