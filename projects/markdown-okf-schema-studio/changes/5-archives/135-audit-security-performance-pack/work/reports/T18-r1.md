# T18 round 1: worker-thread renderer, abort and adaptive debounce

Worktree `markdown-okf-schema-studio-wt-135-t18`, branch `change-requests/135-t18-render-worker`
(base 54c76b5b). Nothing committed.

## Files changed

- `src/node-services/renderWorker.ts` (new, 342 lines): `createWorkerRenderer()`, the
  `PreviewRenderer` port on `worker_threads`. The same file is the worker entry: it serves renders
  when `workerData.role` marks it. Strings in, strings out (`SourceRenderInput` to
  `SourceRenderOutput`).
  - One warm thread (`maxWorkers` 1). It starts on `warm()` at activation and preloads the MyST
    engine. A second render at the same time waits for it, because a second thread would start cold.
    The idle thread stops after 5 min.
  - Abort: `worker.terminate()`, the render rejects with `RenderCanceledError` at once, and a
    replacement thread starts immediately so the next render finds a warm one.
  - Fallback: if the thread fails before it posts `ready` (missing script, load error), this render
    and all later ones run in-process. A ready thread that dies during a render fails only that
    render. Re-running the same input on the host could take the host down too. After 3 deaths in a
    row the renderer also falls back to in-process.
  - Test hook `setRenderWorkersEnabledForTests(false)`.
- `src/host-api/previewRenderer.ts` (new): the port `{ render: SourceRenderer; warm(); dispose() }`.
  `HostServices.previewRenderer?` is optional, so a host without one (host-memory) renders in-process.
- `src/core/render/renderPipeline.ts`:
  - New `renderPreviewSource(input)`: the old render body as plain data in and out (resource policy,
    includes, globs, security and MyST diagnostics). It returns `renderMs`, the MyST render time
    without the engine load.
  - `RenderOptions.renderSource?`: the host's renderer. `RenderResult.renderMs?`.
  - A render whose signal is already aborted never starts.
  - A cancellation from the renderer stays a `RenderCanceledError`; it is no longer wrapped as
    `RenderError`.
  - `enabledMystExtensionsFor` is looked up on the host and passed in, so the worker never holds a
    stale `conf.py` cache.
  - No new Node import in core.
- `src/node-services/build/buildQueue.ts`:
  - Adaptive debounce: `currentDebounceMs()` returns `debounceMs` until a build finished, then
    `clamp(2 x lastBuildMs, debounceMs, maxDebounceMs = 1000)`.
  - `durationOf(result)`: the session passes `result.renderMs`, so a worker start or the engine load
    does not inflate the wait.
  - Overrun abort: a newer request is due while a build runs. If the build has run at least
    `max(debounceMs, 2 x lastBuildMs)`, it is aborted (outcome `superseded`) and the newest request
    starts. Otherwise a timer re-checks at the overrun point. Each abort raises the estimate to the
    time the aborted build ran, so a document that suddenly grew cannot starve the preview.
  - No estimate (first build): nothing is aborted. The existing "in-flight finishes" test keeps its
    intent.
- `src/session/previewManager.ts`: passes `renderSource: host.previewRenderer?.render` and
  `durationOf`.
- `src/host-vscode/vscodeHost.ts`: `previewRenderer: createWorkerRenderer()`.
- `src/host-vscode/activation.ts`: `warm()` on start, `dispose()` on stop.

## Open points

1. `scenarioAlertDropdown` fails consistently with the worker on this machine. It is a known flake
   (T6, T7), but the reviewer or driver should rerun it on a quiet machine and on the base, or with
   `ci-stress`, before integrating.
2. The bundle grows by `out/bundle/renderWorker.js` (3.4 MB minified): the MyST engine is bundled a
   second time. This interacts with T17 (bundle trims).
3. The sanitizer and the source-mapping pass (`annotateSourceMappings`, `rewriteSphinxHtml` in
   `session/webview.ts`) still run on the host: about 100 ms of the 518 ms at 11k lines. Moving them
   needs their resource-resolution callbacks as data; that is out of the named scope.
4. A ready thread that dies during a render fails that render rather than re-running it in-process.
   This is a deliberate safety choice; there is no test for it, and none for the busy-thread wait or
   the idle stop.
5. The worker's own caches (highlight, KaTeX, headings) are per thread and are lost when an abort
   terminates the thread. `conf.py` extensions are passed from the host, so cache invalidation stays
   correct.
6. The SwRS id is `LIFE-004`. Another in-flight task could still allocate it before integration;
   T19's `LIFE-002` was avoided.
