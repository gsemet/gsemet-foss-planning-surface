# T5 round 1 report: one parse5 pass per page build

Worktree: markdown-okf-schema-studio-wt-135-t5, branch change-requests/135-t5-single-parse5-pass (nothing committed).
Compatible with T4 (b89cd2cd) by design: only `injectContentSecurityPolicy` of html-sanitizer.ts is touched
(T4 edits other parts of that file); `injectSourceMappings` is untouched and now the only source mapper.

## Changes
- `src/core/mapping/sourceMapping.ts`: `annotateSourceMappings` (and its parse5 helpers) deleted.
- `src/session/webview.ts`: no pre-annotation parse; `rewriteSphinxHtml` (with `sourceMapping`) does the numbering.
- `src/core/frontmatter/propertiesTable.ts`: the properties table `<section>` writes its mapping attributes inline
  (it was the other caller of the deleted function).
- `src/core/security/html-sanitizer.ts`: `injectContentSecurityPolicy` is a string splice into `<head>` (drops CSP metas of the
  head only, as before); documents without a head element keep the old tree path.
- `src/core/preview/contentPatch.ts`: shell memory (3 entries, keyed by the page with nonces normalized) so
  `planContentPatch`/`shellKey` do not re-parse the loaded page; `parsedPageCount()` exported for the test.
- `src/core/render/mystTables.ts`, `mystRenderer.ts`: pipe tables without aligned columns get `data-line`/`data-end-line`
  on the syntax tree (merged into `data` when the writer's table handler resets it), so the HTML pass is skipped.
  `needsHtmlTablePass`: list-tables, raw HTML tables and aligned columns still use the HTML pass.
  Reason for the limit: the writer applies a row's `data.hProperties` to all cells and reads `parent.align` after
  deleting it, so per-column cell alignment cannot be set on the tree without hacking library internals.
- `test/visual/renderFixtures.ts`: dropped the redundant pre-annotation call.
- SwRS: GFM-008 (scenario, note, tested_in_files), LIFE-069 (scenario, note), TRUST-012 (note, tested_in_files).
- Behaviour note: `renderMyst` output for documents with only unaligned pipe tables is no longer re-serialized by parse5
  (e.g. `-->` stays `-->`, `hidden` not `hidden=""`); the page is unchanged because the sanitizer parses it anyway.
