# T17 round 1 - Bundle trims (uncommitted in markdown-okf-schema-studio-wt-135-t17)

## Changes
- `scripts/page-bundle.mjs`: new `extensionBundleOptions()` (extension build; plugin turns the `require("./highlight")` and `require("katex")` calls into runtime requires of `./lazy/highlight.js` / `./lazy/katex.js`; alias `js-yaml` -> shim), `lazyModuleOptions()` (the two lazy CJS files), `mermaidBundleOptions()` (ESM + code splitting, chunks in `out/bundle/mermaid-chunks/`).
- `esbuild.mjs`: uses the three option sets.
- `scripts/js-yaml-shim.mjs` (new): `load()` on top of `yaml` (MyST engine only calls `yaml.load`); empty text -> undefined, merge keys on. One YAML library now (yaml); js-yaml removed from the bundle only, it stays a transitive dependency of myst in package-lock (no package.json change, nothing added).
- `src/core/render/mystRenderer.ts`: highlight loaded through a lazy `require("./highlight")` wrapper (skips when no `<code`).
- `src/core/render/mathRenderer.ts`: KaTeX through lazy `loadKatex()`.
- `src/session/webview.ts`: Mermaid tag is `<script type="module" ...>` (no `defer`, module scripts are deferred).
- `test/visual/renderFixtures.ts` + `test/visual/capture.py`: module script tag and Chromium `--allow-file-access-from-files` (module chunks do not load over file:// otherwise; verified with a playwright probe: without flag blocked, with flag both diagrams render).
- SwRS: scenarios + file lists + method lines in MYST-024 (KaTeX), CODE-001 (highlight), DIAG-001 (Mermaid); `@implements_req` markers on the new functions. No new requirement files (avoids id collisions with parallel tasks).
- Not done: json5 (29 KB), he, csv-parse, parse5 stay (myst/our deps, would need shims; out of scope). No user-visible setting changed, no docs change.
