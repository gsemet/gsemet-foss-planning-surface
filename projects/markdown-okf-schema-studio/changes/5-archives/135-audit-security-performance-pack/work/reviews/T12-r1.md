## Correctness
- Cache key is the whole JSON tuple (command, args incl. `-D` options and JAR path, workspace root,
  security profile, JAR size:mtimeMs, source). No digest, so no collision poisoning. Env differs from the
  key only by values derived from workspace root and constants; fine.
- Only fulfilled renders are stored (`run.then`); every reject path (exit code != 0, timeout, overflow,
  abort, spawn error, stdin error) skips the store. Failed renders are never cached (tested).
- Uncacheable sources (`!include/!import/!theme/!pragma`, `%getenv`, `%date`...) and JAR stat failure
  yield no key. Oversized source and pre-aborted signal bypass cache and gate (they never spawn).
- LRU bound: 64 entries, refreshed on hit, oldest evicted.
- Concurrency: slot taken synchronously, released in `.finally` of `renderSource`, which covers
  close/error/timeout/overflow/abort/spawn-throw (spawn throw is inside the Promise executor, so it
  rejects and releases). A waiter aborted while queued is removed and rejects without holding a slot;
  once a waiter is resolved its abort listener is removed, and `start` always runs, so no slot leaks.
  Hand-off to the next waiter keeps `activeRenders` at <= 2.
- Identical sources in one page share one in-flight promise (per call, so abort semantics stay per call).

## Notes (non-blocking)
- The cache is bounded by count (64), not bytes: worst case 64 x 8 MiB SVG (plus sources up to 1 MiB in
  keys). Real SVGs are small; consider a total-size cap as a follow-up.
- The slot is released when the render settles, not when the killed process has exited (timeout/abort
  send the group kill first). A dying JVM may briefly overlap the next one; acceptable.
- Non-JAR executable mode has no binary mtime in the key (already listed by the coder).
- Env vars other than the ones set (e.g. `JAVA_TOOL_OPTIONS`) are not in the key; negligible.
