## Findings

1. **Required: the user docs are not updated.** The definition of done says "Docs updated when a
   user-visible behaviour or setting changes". `docs/user/settings.md` (lines 58-63) still
   describes `frontmatter.bundleRoot`, `frontmatter.projectRoot` and
   `frontmatter.allowOutsideWorkspaceLinks` without saying that a workspace value is ignored in
   Restricted Mode. Only `CHANGELOG.md` mentions it. Fix: add one sentence to the Frontmatter
   entries, for example "In Restricted Mode a value set by the workspace is ignored". The
   `plantuml.useJar` entry already gives its trust condition.
2. Note, not blocking: `issuedIds` reuses `PlantUmlIncludeWatch`, a list of at most 1024 entries
   that drops the oldest first. In a document with more than 1024 distinct included files, a
   nested include whose parent id was dropped is refused. This is acceptable, but the DIAG-053
   boundary table could say so in one row.
3. Note, not blocking: the comment in `hostRequests.ts` ("not for a script of the page") claims
   more than the code does. The flag blocks only clicks dispatched by a script. It holds because
   the webview API handle is not exposed. A short clause saying this would keep future readers
   from relying on the flag alone.
