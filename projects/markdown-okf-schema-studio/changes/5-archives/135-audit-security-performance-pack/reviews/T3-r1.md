## Checked, no change needed

- **Symlink refusal.** `isSymbolicLink` runs before the read and uses `fs.lstat`, so links are not
  followed. A dangling link counts as a link, and a missing path returns false. Only the last path
  component is checked. That matches the scope: the sidecar sits next to the document.
- **Atomic write.** A random 12-hex `.tmp` sits in the same folder, then a rename. A failed write
  or rename removes the temp file (the remove errors are swallowed and the first error is
  re-thrown).
- **TOCTOU.** If a link appears between the check and the rename, the rename replaces the link
  entry and does not follow it, which is acceptable. The read in that window could follow a new
  link, but the content must parse as a valid comments file to be kept, so the exposure is
  negligible.
- **Temp file and symlinks.** `writeFile` on the temp path would follow a link planted there.
  The name has 48 random bits and is created only just before the rename, so the risk is
  acceptable. An exclusive create (`wx`) would close it fully, but the port does not support that
  today, so this is optional.
- **`moveSidecars`.** It renames with `overwrite: false`, which moves a link as a link. The
  `update` that follows then refuses it. Safe.
