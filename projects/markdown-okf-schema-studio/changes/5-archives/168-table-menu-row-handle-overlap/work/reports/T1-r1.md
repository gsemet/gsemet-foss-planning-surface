## Root cause

- The table bar (`.sphinx-preview-table-menu`) was `position: static; z-index: auto`. The row/column handle layer (`[data-okf-row-handle-layer]`, a child of `body`) is `position: absolute; z-index: 2`. A positioned element always paints above a static in-flow one, so wherever a handle box lies on a bar button, the handle wins the hit test. Only the stuck bar (translated, `position: relative; z-index: 3`) was above the layer. No ancestor of the bar creates a stacking context (checked in Chromium), so layer 2 vs bar auto is the whole story.
- The log (heavy run 40732349085) shows only that the row 1 handle of table `data-okf-row-table="3"` (the pipe table at source line 3, after "# Structure") intercepts the click on "Delete selected column" (3rd press of scenarioTableStructure, after the two column inserts); it has no rects. Integration window: viewport 1400x900, sidebar and aux bar closed, so about 700 px per pane.
- Geometry in headless Chromium (mock host pages, widths 480-900, scroll 0-230, 2 and 4 column tables, with and without heading): bar above the table in flow (for example 700 px: bar 56,40 to 580,126; table top 148; row 1 handle 95,201 to 116,222), never overlapping a handle. With a forced stuck shift the stuck bar wins (z 3). So I could NOT reproduce the exact real-window overlap geometry headlessly. Hypotheses, unproven: a handle placed before the bar grew or wrapped (five-row toolbar inset wraps the bar to 2-4 lines, "Delete selected column" is the first button that lands on a wrapped line at the left, over the handle strip x range), or a table right of the bar (centred or row-shifted).
- The z-order defect is certain regardless of which geometry produced the overlap.

## Does a real user hit it?

Yes, to the extent the overlap geometry occurs: Playwright's "intercepts pointer events" is the browser hit test, a real pointer press goes to the same element. The press would land on the "Move table row" button instead of the bar button. So this is a product fix (bar above handles), not a test-aim fix. The test (`tableStructureReal.ts`) is unchanged.
