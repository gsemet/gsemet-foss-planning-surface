# T1 round 1 report: relative images in Restricted Mode (CR 238)

## Cause

Not the encoding: images with spaces (written `%20` or between `<...>`), next to the document or in
a subfolder, already resolved in Restricted Mode (reproduced, they load). The cause is the policy
and the webview roots, two cases:

1. Restricted Mode set the resource root to the document folder only (`createSession`), so an image
   in the workspace folder outside the document folder (`../images/x.png`) was refused by the
   policy (`resource-outside-root`) and was not in the webview `localResourceRoots`.
2. A document in the home folder (or above): `isBroadReadOnlyRoot` refused every resource, images
   included, and `previewLocalResourceRoots` returned no root.

CSP is not involved (`img-src` is the webview `cspSource`).

## Fix

- `src/core/security/resource-policy.ts`: roots carry `documentFolder`; new option
  `{ image: true }` on `resolveResource` / `resolveResourceDetailed`. In a read-only policy, a
  request whose decoded path ends in png, jpg, jpeg, gif, webp or svg (and has the option) may use
  the workspace root and may use a broad document folder (the document's own folder only; a broad
  workspace root gives `restricted-root`). Every other request (includes, diagram files, globs,
  non-image files) is limited to the document folder, as before. Dot-segment refusal (before and
  after realpath) and symlink escape are unchanged.
- `src/session/webview.ts`: page resources resolve with `{ image: true }`.
- `src/session/features/rendering.ts`: `previewLocalResourceRoots(resourceRoot, readOnly,
  workspaceFolder?)`: read-only gives the document folder (even broad) plus a non-broad workspace
  folder; the policy of the page gets the workspace folder as second root in Restricted Mode.
  The render (includes) still gets only the document folder.
