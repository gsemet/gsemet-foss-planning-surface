## What was confirmed, and how

By reading `src/page/modules/widthMode.ts`:

- `wrapperOf` returns the element when its parent is `#content`; for an `IMG` whose parent is a
  `P`, child of `#content`, with empty trimmed `textContent`, it returns the paragraph. It does not
  count the images.
- `eligibleWrappers` drops a wrapper already listed (`wrappers.includes(wrapper)`).
- `sizedElement` takes `wrapper.querySelector("img")`: the first image in the paragraph, at any
  depth. Declared width, intrinsic width and the `%`/`em`/`rem` exclusion come from it.
- A linked image has an `A` parent, so `wrapperOf` returns nothing for it; neither the `A` nor the
  `P` is in the candidate selector.

By a throwaway probe (rendered with `renderPreviewDocument`, shipped page and stylesheet, real
Chromium, 1100 px pane, Width clicked to Auto; SVG images of 900 px "big" and 50 px "small"). It
lived in the ignored `out/scratch-cr511/` and is removed.

| Markdown | Rendered | Marked in Auto |
| --- | --- | --- |
| big image alone | `p(img)` | `p`, 212 px |
| two big images, one line | `p(img,img)` | `p`, 212 px (once) |
| small then big | `p(img,img)` | nothing |
| big then small (two lines) | `p(img,img)` | `p`, 212 px |
| linked big (Markdown, and raw `<a><img>`) | `p(a(img))` | nothing |
| bare small + linked big | `p(img,a(img))` | nothing |
| linked big + bare small | `p(a(img),img)` | `p`, 212 px |
| `{image}` directive, with and without `:target:` | `p(img)` (no link) | `p`, 212 px |
| big image followed by text | `p(img)` with text | nothing |

Verdict on the review:

- (a) confirmed in part. A textless paragraph with several images does get measured, but the images
  are **not each measured**: the paragraph is measured and marked once, with the first image's
  sizes (a big second image is not widened). The Criteria say this, not the review's wording.
- (b) confirmed: a linked image alone in a top-level paragraph is not measured. With a bare image
  beside it, the paragraph is measured because of the bare one.
- The checklist's "an image is measured only when its direct parent is a top-level paragraph" was
  not used as written: an image that is a direct child of the content is also measured by the first
  line of `wrapperOf`. The Criteria keep "a direct child of the content".
