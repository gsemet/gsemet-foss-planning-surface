## 3. Generator `scripts/generate_orchestrator.py` + `just orchestrator`

Python 3.11+, standard library only, style of `scripts/select_e2e_run.py` (module docstring that
states the contract, `from __future__ import annotations`, argparse, `main(argv) -> int`, testable
pure functions). Recipe in `justfile`, with a comment line like the others:

```just
# Rebuild .agents/changes/03-requests/ORCHESTRATOR.md from the STATE.md headers, the backlog and the archives.
orchestrator CHANGES=".agents/changes":
    uv run --no-sync python scripts/generate_orchestrator.py "{{ CHANGES }}"
```

(Adjust so `just --unstable --fmt --check` passes.)

Inputs, relative to the changes root (positional argument, default `.agents/changes` resolved
against the repository root = parent of `scripts/`):

- **Active**: every directory `03-requests/*/`. Its `STATE.md` first four lines must match the
  header of the guideline exactly (regexes, ` · ` separators):
  `driver: X · updated: X` / `status: (working|wait-ci|ready|blocked|landed) · step: X · round: X` /
  `head: X · PR: X · run: X` / `next: X · question: X`. A missing `STATE.md` or a header that does
  not match is an **error**: the path is printed on stderr (`error: <path>: unparsable STATE.md
  header (line N)` or `missing STATE.md`), the row is still written with status
  `⚠️ unparsable header` (never guessed), and the script exits **1** after writing the file.
  Row columns: `CR (spec) | Subject | Status (STATE.md) | Branch | PR`.
  CR = NNN linked to `NNN-slug/00-request.md` (if absent, the first `.md` in the folder, sorted);
  Subject = first H1 of that file with a leading `NNN — ` / `NNN - ` / `NNN: ` prefix stripped;
  Status = icon + `status step round` linked to `NNN-slug/STATE.md`; icons 🟢 ready,
  🟡 working / wait-ci, 🔴 blocked, ✅ landed; Branch = `` `change-requests/NNN-slug` ``;
  PR = `[#n](https://github.com/<owner>/<repo>/pull/n)` when the PR field holds `#n`, else `—`.
  Folders whose name does not start with three digits are still rows (CR column = folder name).
  Sorted by CR number descending (newest first), as the live file does.
- **Backlog**: every directory `02-backlog/P*/*/`. Columns `Priority | Item | Title | Files`.
  Item = folder name linked to its first `.md` file (sorted by name; relative link
  `../02-backlog/P2/slug/01-intent.md`); Title = first H1 (`# `) of that file, outside YAML front
  matter; Files = number of regular files under the folder, recursive. Sorted by priority then
  folder name.
- **Drift**: a backlog item that is also a CR's `backlog-item/` (CR under `03-requests/*/` or
  `04-archives/*/`) — match when the CR folder name minus its `NNN-` prefix equals the backlog
  folder name, OR when the H1 of the CR's `backlog-item/` first `.md` equals the backlog item's H1.
  Such an item is NOT listed in Backlog (it is listed only under its CR, in Active or Landed), a
  `warning: drift: <backlog path> is also <CR backlog-item path>` goes to stderr, and the generated
  file lists it under a short "Drift" line or bullet list just after the alert. Drift alone exits 0.
- **Landed**: every directory `04-archives/NNN-*/` (three digits). Columns
  `CR (spec) | Subject | Report | PR | Date`. CR linked to `../04-archives/<dir>/00-request.md`
  (fallback first `.md`); Subject = H1 of that file, prefix stripped as above; Report =
  `[report](../4-archives/<dir>/report.md)` or `—` when no `report.md`; PR = first `#NNN` found in
  `report.md` in a PR context (`PR [#236]`, `PR #43`, `/pull/236`; prefer the `/pull/n` URL, then
  `PR #n` / `PR [#n]`), linked to GitHub, else `—`; Date = first `YYYY-MM-DD` in `report.md`, else
  `—`. Sorted by date descending, ties by CR number descending; undated rows last, by number
  descending. Non-directories (e.g. `RUN-BRIEF-run3.md`) are ignored.
- **Notes**: `03-requests/ORCHESTRATOR-NOTES.md`, appended as is at the end (after the tables)
  when it exists; nothing when it does not.
- Repository for PR links: `--repo owner/name`, default parsed from `package.json`
  `repository.url` of the repository.

Output `03-requests/ORCHESTRATOR.md` (option `--output` to override), plain GFM + GFM alert:

```markdown
# CR table

<!-- Generated by `just orchestrator` (scripts/generate_orchestrator.py). Do not edit: edit
ORCHESTRATOR-NOTES.md or the STATE.md headers, then run `just orchestrator`. -->

> [!NOTE]
> Updated YYYY-MM-DD: N active CRs.

Repository: [owner/repo](https://github.com/owner/repo). Process:
[change-requests-lifecycle.guidelines.md](../../guidelines/change-requests-lifecycle.guidelines.md).
Worktree of CR NNN: `../<repo>-wt-NNN`.

## Active
...
## Backlog
...
## Landed
...
(notes)
```

**Idempotence and the date**: the date is today's date (option `--today YYYY-MM-DD` for tests).
If the existing output equals the new content once the alert date line is ignored, the file is
NOT rewritten (so a second run is byte-identical even on another day, and the date says when the
content last changed). Deterministic order everywhere; trailing newline; UTF-8.
