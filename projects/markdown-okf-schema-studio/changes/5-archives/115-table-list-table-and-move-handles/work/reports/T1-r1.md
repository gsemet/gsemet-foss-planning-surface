## Root causes found (reproduced in a real VS Code window)

1. **List-table "disappears" on a cell click**: the click opens a pipe cell editor inside the clicked cell; when the host source is a `{list-table}` (or any table the cell editor cannot read) the page falls back to the raw editor and hides the table, but left the raw editor frame inside the now hidden cell. The frame had a 0x0 box: nothing to edit, and the focus loss saved the unchanged text. Same cause for HTML tables, `{csv-table}` and a `{table}` caption. The conversion itself (pipe to list-table, header included) was already correct (the text and the render keep every cell); the "lost heading" was this invisible frame.
2. **Row handles "grab but do not move"**: `busy()` refused every drag while any editor was open, and a click on a cell (the usual state when the writer wants to move a row) opens a cell editor. Without an open editor the drag worked (checked with a real mouse drag).
