Status: implemented in the worktree `/Users/az02065/Projects/DevTools/markdown-okf-schema-studio-wt-131` (nothing committed). Nothing left running; the window lock was taken and released.

## What changed

- `src/core/render/highlight.ts`: highlight.js replaced by Shiki (`shiki/core`, JavaScript regex engine, no WASM, sync API). 32 grammars bundled (python, ts/tsx, js/jsx, json/jsonc, yaml, bash/shellsession, c, cpp, csharp, rust, go, java, kotlin, sql, toml, diff, markdown, html, css/scss, xml, ini, dockerfile, powershell, latex, lua, makefile, ruby) plus Shiki's own aliases and `console`, `ipython`, `myst`, `node`, `patch`, `svg`, `tex`. Unknown language = plain text. Tokens carry colour classes (`sd-<hex>` Dark+, `sl-<hex>` Light+), never `style` (page CSP forbids it). Every block of 2+ lines is wrapped into `.myst-code-line` spans, each ending with its own `\n` (so textContent/selection/find equal the source; checked in Chromium that the old no-`\n` markup lost empty lines in a selection).
- `src/core/render/codeTheme.ts` (new): Dark+/Light+ palettes, class names, CSS rules, and a contrast fix: the 3 Dark+ colours below 4.5:1 on #1e1e1e (#000080, #646695, #808080) and the Light+ ones below 4.5:1 on cream are moved to the nearest passing tint.
- `src/core/preview/styles/codeBlockStyles.ts` (new, joined after content block CSS): dark surface, token CSS, line numbers as `::before` generated content (`user-select: none`), diff block treatment on dark. Removed from `contentBlockStyles.ts`: `.hljs-*` rules, the YAML link-colour override, old line-number rules.
- Settings (`settingsRegistry.ts`, `package.json` regenerated): `preview.codeBlocks.darkBackground` (order 23) and `preview.codeBlocks.lineNumbers` (order 24), boolean, default true, `scope: resource`, startup boot settings (a change reloads the page). `pageSettings.ts` `applyCodeBlockSettings` sets `data-okf-code-dark-background` / `data-okf-code-line-numbers` on `<html>` (called in `runtime.ts`). MyST `:linenos:`/`:lineno-start:` write `data-myst-line-numbers` (always numbered); plain blocks get `data-myst-auto-numbers` (follow the setting); `:emphasize-lines:` unchanged.
- `src/page/modules/codeCopy.ts`: joins lines tolerating the new trailing `\n`.
- `tsconfig.json`: `lib` now `["ES2022", "DOM"]`. The DOM types were only available through highlight.js's `/// <reference lib="dom">`; removing highlight.js broke 100+ page files without it.
- Dependencies: `package.json` + `package-lock.json`: `shiki ^4.5.0` added, `highlight.js` removed (unused now). Lock diff reviewed: shiki + 21 transitive packages (`@shikijs/*`, oniguruma-to-es, regex*, hast/mdast utils nested under `@shikijs/core`, etc.), all additions. Unrelated churn from the driver's install: 5 `libc` fields dropped from `@napi-rs/keyring-linux-*`; I restored them. The code imports `@shikijs/langs/<x>` and `@shikijs/themes/<x>` directly (transitive deps of shiki, hoisted); boundaries check passes.
- Docs: `docs/user/settings.md`, `CHANGELOG.md`. SwRS: new `CODE-039` (line numbers) and `CODE-040` (dark background) via `okfreq new`; updated `CODE-001`, `CODE-005`, `CODE-007`, `CORE-028`; dated entry in `requirements/tiers/log.md`. Markers (`@implements_req`/`@tests_req`) added in src, tests and visual scenarios; coverage lists filled by `okfreq update-coverage`.
