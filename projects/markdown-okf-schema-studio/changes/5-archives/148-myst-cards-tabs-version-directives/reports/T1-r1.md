## Findings per part of the intent

1. `{card}`: not supported before (rendered as a raw directive box). Now rendered like a grid card.
2. `{tab-set}` / `{tab-item}`: no support before. Now a tab bar with ARIA, click, arrows, Home/End.
3. Version titles: the valid form `:::{versionadded} 0.47` rendered "Added in version 0.47:" (trailing
   colon added by Studio). Now "Added in version 0.47" (same for changed/deprecated). No lenient
   parsing of the `}::` typo.
4. README section, `docs/user/editing.md`, CHANGELOG entry added.

## Open points / autonomous decisions

- `just requirements-update` also reordered file lists in three unrelated SwRS (DIAG-097, CORE-071,
  REVIEW-003): pre-existing drift under the locked okfreq 0.13.0. Kept because `just check`
  (`update-coverage --check`) needs them; the driver may drop them if the base already tolerates it.
  The index of StRS MYST-001 gained `derived_by` 097/098/099 (this CR).
- Card order: standalone card is header, title, body, footer (as MyST and the CR text). A
  `grid-item-card` keeps its existing order title, header, body, footer (not changed).
- Tab titles are plain text inside the button (Markdown/links dropped). Non-tab-item content inside a
  tab-set stays below the panels. Tab ids are `myst-tab-<line>-<n>`. Tab choices live in the page
  (per set position and sync group), not in the file or vscode state, and are re-applied after a patch.
- Edit mode: tab-set and each panel are mapped blocks (innermost click wins, like grid cards); clicking
  the tab bar only selects. Moving a tab item above/below non-item blocks is generic block-move
  behaviour and was not restricted.
