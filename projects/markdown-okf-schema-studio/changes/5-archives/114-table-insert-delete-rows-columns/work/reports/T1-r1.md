# T1 round 1 - CR 114 (table insert before/after, delete rows and columns)

Worktree: /Users/az02065/Projects/DevTools/markdown-okf-schema-studio-wt-114 (nothing committed).

## Root cause
A row or column button changed the table model but left the cell editor in the old DOM cell. The editor then showed the new, empty cell (the "wiped title"), and later cell switches used DOM indexes against a model with an extra row or column (so delete looked broken). The fix: every structural button saves the table (final save) and reopens the editor in the target cell after the page rendered it again, the same path as Tab on the last cell.

## Behaviour now
- Table bar: Row above, Row below, Row -, Col left, Col right, Col - (Row above is off in the header row; Row - off on the header or last body row; Col - off on a one-column table). Insert never touches existing cell content; the editor reopens in the new row or column.
- Plain `{list-table}` (one header row via `:header-rows: 1`, one-line cells, no title, label, other option or indentation) now opens the cell editor with the same buttons and is written back as a list-table (text unchanged while untouched). Other list-tables still open the raw editor. "List table" conversion button is disabled on a list-table.
