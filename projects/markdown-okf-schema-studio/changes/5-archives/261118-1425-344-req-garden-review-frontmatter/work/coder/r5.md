## Residual risk: cached listing of the schema directory

I checked it in src/node-services/schemaFiles.ts (`listFiles`). The listing is kept only while the
directory's stamp (`mtimeMs:ctimeMs:ino`) stays the same. A listing whose modification time is
younger than 2 s is not kept at all. A rename and a file creation change the directory's time,
so the next refresh lists the folder again and the step needs no extra wait. The same holds in
`finally` (rm and rename back).

`matchSchemaFile` prefers `.yaml` over `.json5`, so the YAML file has to be moved aside. The `.aside`
name does not end in `.schema.<ext>`, so it is never a candidate. The schema registry resolves by
candidate path: the json5 path is a new entry, and the YAML entry's dependency check re-reads the
same text after the rename back.
