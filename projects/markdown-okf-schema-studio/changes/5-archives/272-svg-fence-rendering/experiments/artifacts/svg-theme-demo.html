Inline SVG: planned rendering

A preview of how Markdown OKF-Schema Studio plans to show SVG written straight into Markdown (issue #336). This page imitates the result; it is not the shipped feature.

Both forms will render: a fenced block with the svg language, and a raw <svg> that fills a whole block. The picture follows the page theme.

Switch the theme: the SVGs below change with it, because they use theme variables instead of fixed colours.

1. The example from the issue

A rectangle filled with var(--surface) and outlined with var(--border). In a plain image these variables would not resolve and the shape would turn black.

Markdown source 
```svg
<svg viewBox="0 0 960 320" xmlns="http://www.w3.org/2000/svg" font-family="sans-serif" font-size="13">
  <rect x="15" y="15" width="450" height="290" rx="8" fill="var(--surface)" stroke="var(--border)" stroke-width="1.5"/>
</svg>
```

2. A diagram an agent would write

Three layers of an extension, with text, a muted note, an accent and the named colours.

3. A variable Studio does not know

An unknown name uses the fallback written in var(), else the text colour.

Variables an SVG can use

VariableMeaning
--surface, --background, --bgBlock background
--borderBorders and separators
--text, --foreground, --fgText
--mutedSecondary text
--accent, --primaryAccent
--red, --green, --blue, --orangeNamed colours, adjusted for light and dark

What is removed before display

The SVG is placed in the page after cleaning: scripts, foreignObject, event handlers (onclick and the like), links to other sites and <style> elements are removed, and ids are renamed so that two SVGs on one page cannot clash. A <svg> inside a sentence stays dropped.
