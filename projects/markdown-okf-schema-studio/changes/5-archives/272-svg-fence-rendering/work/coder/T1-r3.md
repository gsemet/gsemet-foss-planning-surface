# T1 round 3 report: CR 272 svg fence and raw svg rendering

## Findings fixed
- A/C. src/core/render/svgPictures.ts: a comment block opens only on `/^ {0,3}<!--/` and a `$$` block only on
  `/^ {0,3}\$\$/`; a block closed on its own line (`-->` or a second `$$` after the opener) opens nothing.
  A `<!--` or `$$` in a sentence or a code span no longer stops fence tracking nor later raw svg blocks.
- B/G. src/core/security/html-sanitizer.ts: the value-checked set is SVG_ATTRIBUTE_NAMES minus every name
  `isAllowedAttribute` accepts (prefixes included, so aria-* keep main's rule everywhere), and the check
  (and the extra acceptance) applies only to elements in the SVG namespace (`namespaceURI`): an HTML `<p rotate>`
  loses the attribute as on main.
- D. src/core/security/svgSanitizer.ts: role, aria-label and aria-hidden are text attributes (kept as written,
  max 1000 chars, escaped by the HTML writer); aria-labelledby/aria-describedby keep only ids of the
  picture, renamed with its prefix. They left SVG_ATTRIBUTE_NAMES (so B no longer sees them).
- E. skills/writing-for-markdown-okf-schema-studio/references/svg.md "What is removed": strict function
  allow-list (color-mix, oklch, clamp, font name in parentheses dropped), use/textPath without a target in
  the same picture removed, svg in a comment, `$$` block, code block or HTML table cell not drawn, aria-label kept.
- F. requirements/tiers/log.md: TRUST-036 "existing, proposed".
- G: closed by B's namespace scoping.
