## Root cause and code path on current code

- Cause (pre-fix): the counter depended only on VS Code's shared recursive workspace watcher, which
  on Linux CI missed or delayed the write. Fixed by d53b756 (direct non-recursive `fs.watch` of the
  target's folder). The failing run predates it: decision 2 case "already fixed".
- Current code, traced: `setFrontmatterState(..., linksResolved=true)` creates the direct watch
  synchronously (`fs.watch` registers the inotify watch before it returns) and only then
  `patchPropertiesTable` posts the html with `data-okf-link-status="valid"`; the test waits for that
  html before saving, so the save cannot precede arming. A target is dropped from the watched set
  only if `linkedFileDetails` throws (file missing); an empty or truncated read still yields
  `previewFields: {}`, so no dispose/re-arm race during the save. Remaining silent failure mode:
  `fs.watch` failing to arm or erroring (ENOSPC/EMFILE/ENOENT) was swallowed with no trace.
