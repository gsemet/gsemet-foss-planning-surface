## Findings

### 1. major: the new unit test's "sibling is not counted" check can flake on a late second event of the target write

`test/frontmatter/linkedTargetWatch.test.ts:91-96` (new test "CR 044: the direct watch is armed when
it returns ...").

The test writes the target, waits until `events > 0` (it stops at the **first** event), takes
`counted`, writes the sibling, waits a fixed 400 ms, then asserts `events === counted`. A single
`fs.writeFileSync` often produces more than one watcher event for the target: on Linux, truncate and
write give two `IN_MODIFY` events, and on macOS FSEvents can split a write into `rename` + `change`.
If the second event of the **target's** write arrives after `until` returned, `events` grows past
`counted` and the test fails with "a sibling's write is not counted", although the sibling was
correctly ignored. The fixed `delay(400)` does not settle the earlier write; it only gives the late
event time to land in the window being checked. This is a new flake by CI rule 12.

The existing first test avoids this by checking the sibling **before** any target write.

Fix (either one):
- Do the sibling check first, as in the first test: write the sibling, `delay(400)`, assert
  `watch.state().events === 0`, then write the target and `until(() => watch.state().events > 0)`.
- Or remove the sibling part from this test. The first test already covers "sibling not reported"
  through the callback, and `state.events` is incremented on the same line as `onEvent()`. Keep the
  armed-at-return check (`{ status: "watching", events: 0 }`), "counts the target's write" and
  "`closed` after dispose".

### 2. nit: `entry` is used inside `fromVscode` before its `const` declaration

`src/extension.ts:1262-1275`. `fromVscode` refers to `entry`, which is declared a few lines lower.
This is safe today because VS Code delivers watcher events asynchronously, so the TDZ can never be
hit. Declaring `entry` (with `vscodeEvents: 0`) before the listeners and then setting its
`dispose`/`direct` would make the order obvious. Optional.

### 3. nit: in the stress helper, a failed wait does not show its own predicate's input

`test/integration/linkedTargetSave.ts:150-155`: the first wait in `scenarioLinkedTargetSave` checks
`data-okf-link-status="valid"` on the `related` field, but the diagnostics do not print that status.
The phase and the shown excerpts mostly cover it. Optional: add the related field's link status to
`linkedTargetDiagnostics`.

## Verified (no finding)

- **linkedTargetWatch API.** `state()` returns a copy. `dispose()` is idempotent and keeps `failed`
  (and its error) after dispose. `fail` closes the watcher on an `error` event and on a synchronous
  throw. It never throws.
- **extension.ts.** The `LinkedTargetWatcher` entry disposes the VS Code watcher, its three
  listeners and the direct watch through one `Disposable.from`. Both dispose paths, removal of a
  target no longer linked (line 1245) and preview dispose (line 4468), call `entry.dispose()`. No
  leak. `linkedTargetEvents` is still incremented in `refresh` for both sources, so users see no
  behavior change. The snapshot field is for tests only.
- **Integration helper against the old `previewEditing.test.ts` steps.** The same four waits keep
  the same texts and the same 10 s each. It polls a predicate every 25 ms (the same pattern as the
  existing `waitFor`), with no fixed sleep and no retry. The excerpt match is still exact (the old
  regex `>${text}</span>` is now `shownExcerpts().includes(text)`). "Event of the save" is stricter:
  `> eventsBeforeSave`, where the old check was `> 0`. One wait is added: the product-reported
  readiness signal, a direct watch with status `watching`, compared after `realpath` on both sides,
  which handles macOS `/var` against `/private/var`. Every timeout message carries the host state
  and the file on disk. No assertion is weakened.
- **Stress registration.** `stressPlan()` takes `available` from `Object.keys(STRESS_SCENARIOS)`
  (`realInput.test.ts:4423`), so the plan file itself needs no list. `linked-target-save` is
  selectable with `STUDIO_STRESS_SCENARIOS`, and the CI `just ci-stress` job (`ci.yml:169`, all
  scenarios by default) picks it up.
- **New unit tests fail on the unchanged code.** On the old `() => void` return, `.state` and
  `.dispose` do not exist (TS2339, and a TypeError at run time).
- **CHANGELOG.** The "For contributors" bullet in Unreleased is accurate and fits the neighbouring
  bullets. The user-facing bullet from the earlier cause fix already exists.

  existing convention of the repo.
