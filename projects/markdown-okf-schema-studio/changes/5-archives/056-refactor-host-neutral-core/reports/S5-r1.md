## Design

**Bundle:**
- `esbuild.mjs` builds `out/bundle/preview.js` from `src/page/main.ts` (iife, browser, es2022, minified).
- The bundle uses normal imports. No `Function.prototype.toString()` is used anywhere in the page build.
- esbuild emits `"use strict"` itself (tsconfig `strict`).
- The size is 267.6 kB.

**Boot context:**
- The host writes `<script type="application/json" data-sphinx-preview-runtime-context>` with
  `serializeRuntimeContext` (`<` is escaped, so the context cannot close its element).
- After that element comes `<script nonce=… src=preview.js>`.
- Only the JSON element changes between renders (PERF-11 kept).
- Without a bundle URI, the page gets the context element only, with no runtime. Before, it got an
  inline runtime. No production path lacks the URI.

**CSP:** unchanged.
- `script-src` is still nonce plus file.
- There is no `unsafe-inline` or `unsafe-eval`.
- The JSON element is never executed, so the CSP does not apply to it.

**HostTransport:** the runtime only knows `transport`. `pageHost.api` keeps the `vscode` name inside the
residual runtime so that it stays a strip-diff of the old template.

**Typed router and bus:**
- Feature modules register on `hostMessages` (one handler per type) and keep the old listener order.
- The bus carries `contentReplaced` and `plantUmlIncludesChanged`. Host messages never go through the bus.

**Theme tokens:**
- Every `var(--vscode-X)` in the page CSS became `var(--studio-X)` (384 places).
- The dark, white and cream modes set `--studio-X` (99 declarations).
- `VSCODE_THEME_TOKEN_CSS` (`:root, body { --studio-X: var(--vscode-X) }`) is placed first in
  `PREVIEW_ACCESSIBILITY_CSS`. It also covers the status pages.
- The Mermaid theme reads `--studio-*`.
- Why the selector is lower than the modes: the map's selector is less specific than the modes'
  `html[mode], html[mode] body`. A host variable the host leaves unset leaves its token unset, so
  every fallback behaves as before.
- Possible behaviour change on `html`: VS Code's inline `--vscode-*` on `html` no longer beats a
  forced mode there. I checked this: no `html`/`:root` rule reads a colour token, and only the font
  tokens are read at the root, which no mode sets. The visual run confirms there is no visible change.
