## 1. Final layout

```
src/
  extension.ts            VS Code entry (classified as host-vscode)
  core/                   host-neutral logic
    comments/ configuration/ edits/ frontmatter/ mapping/ myst/ navigation/ paste/
    preview/ protocol/ render/ scroll/ security/ state/

  page/                   browser bundle: runtime.ts, features/, modules/ (former src/webview)
  node-services/          Node ports + services: nodeFileSystem, paths, processRunner,
                          linkedTargetWatch, build/ (former src/build)

                          previewSession, previewNavigator (new), webview.ts, bibScan.ts, features/
  host-memory/            in-memory host (unchanged, kept as a sibling "thin host")

```

Decisions:

- **Everything moved into layers**; no legacy folder is left (`src/protocol`, `comments`,
  `configuration`, `frontmatter`, `mapping`, `myst`, `paste`, `render`, `security`, `state`,
  `preview`, `navigation`, `git`, `build`, `webview` are gone).
- **`src/session` stays a top-level layer** (not in host-vscode): 02-multi-host §3.3 has a future
  `host-node` reuse the same controllers. **`src/host-memory` stays a sibling host** (`host-*` thin
  hosts of §3.3). **`src/protocol` → `src/core/protocol`** (§3.3 puts protocol types in core) with its
  own stricter rule.
- Seven top-level folders instead of five: the five asked for plus `session` and `host-memory`,
  each with its own rules.

## 3. dependency-cruiser

- `fnm exec -- npm install -D dependency-cruiser` → **dependency-cruiser 18.7.0** (`^18.7.0` in
  devDependencies). Lock diff: **package-lock.json +487 / −0 lines, 37 new packages**, all from
  registry.npmjs.org; package.json +1 line (plus the 2 test globs and 2 scripts).
- **TypeScript 7 has no compiler API**, so dependency-cruiser cannot read `.ts`
  (`depcruise --info`: typescript ✗). `scripts/check-boundaries.mjs` transpiles each `src/**/*.ts`
  on its own with esbuild into `out/boundaries/src/` keeping every import, type-only ones included
  (`import type` / inline `type` / `export type … from` rewritten to plain imports,
  `verbatimModuleSyntax`), then runs depcruise there. Verified with probe files (then deleted):
  type-only imports, inline `type`, `export type … from`, `vscode` (resolves to `@types/vscode`),
  Node built-ins, DOM packages, unresolvable paths and transitive Node reach are all reported.
- Run by `just check-boundaries` (`npm run check:boundaries`), called by `just check`.

Rules (`.dependency-cruiser.cjs`):

| Rule | Enforces |
| --- | --- |
| `vscode-only-in-host-vscode` | only `src/host-vscode/` and `src/extension.ts` import `vscode` |
| `core-is-the-bottom-layer` | core imports only core (and npm): decides S3 N2 — host-api → core (TextEdit, Revision) is the allowed direction, core never imports host-api |
| `core-no-dom-packages` | core ↛ mermaid, @plantuml/core |
| `core-no-node-builtins` + `core-node-debt-is-bounded` | core ↛ Node built-ins; 14 listed files may keep exactly the built-ins they use today |
| `protocol-is-host-neutral` | `core/protocol` imports only core (no npm, no Node) |
| `host-api-is-interfaces` | host-api imports only host-api and core |
| `page-not-to-host` | page ↛ host-api, session, node-services, host-vscode, host-memory, extension.ts |
| `page-no-node-builtins`, `page-reaches-no-node-builtins` | page ↛ Node built-ins, directly or transitively through core |
| `node-services-below-session` | node-services ↛ session, page, hosts |
| `session-not-to-page-or-hosts` | session ↛ page, hosts |
| `session-node-builtins-path-only` | session may use `node:path` only |
| `session-node-services-debt` | session ↛ node-services except 3 listed modules |
| `host-memory-is-a-thin-host` | host-memory imports only host-api and core |
| `host-vscode-not-to-page-or-other-hosts` | host-vscode ↛ page sources, host-memory |
| `not-to-unresolvable` | every import resolves (except `vscode`) |

every compilation, so a separate no-DOM tsconfig is not possible. core ↛ DOM is enforced through
imports only (no page module, no DOM-only package). See open point 2.

## 7. Open points

1. **`node_modules` is no longer a symlink in the worktree.** `npm install` replaced the symlink to
   the main checkout with a real `node_modules` directory: a full install, with dependency-cruiser
   in it. The main checkout's `node_modules` is untouched and has no dependency-cruiser. npm also
   skipped the root `postinstall` patch, so I ran `node scripts/patch-myst-imports.mjs` by hand
   (local script, no network). It skipped the `esbuild` and `@vscode/vsce-sign` install scripts
   too (allowScripts warning). esbuild works; `npm run package` / vsce-sign was not exercised.
   Main checkout needs `npm ci` (or the merged lock) to get dependency-cruiser.
2. **DOM in core is checked through imports only.** It is not checked at the type level, because
   highlight.js types load `lib.dom` everywhere. A future option: a no-DOM tsconfig for core once
   `render/highlight` types are isolated.
3. **npm reported 3 vulnerabilities** (1 moderate, 2 high) at install. I could not check whether
   they predate dependency-cruiser: `npm audit` needs the network, and that is out of scope.
4. The `NODE_DEBT` and session debt have no step in this CR, except okfFrontmatter (S8). They are
   bounded per file, so they cannot grow.
5. S8 must lower the baseline as it splits files (the check forces it).
6. `docs/unit-test-audit.md` and `CHANGELOG.md` history keep the old paths (dated documents).
   `coverage-map.py` still names `src/webview/scrollSync.ts`, which was already stale since S5.
