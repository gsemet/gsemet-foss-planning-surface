## Findings

### B1 (blocking): `realpath` used the native implementation

- **Fix.** `createNodeFileSystem().realpath` now uses `promisify(realpath)` from `node:fs`. This
  is the JS implementation, as used by `fs.realpathSync`, and not `fs.realpath.native`, which
  `fs/promises` uses. The TSDoc says it matches `fs.realpathSync`. The VS Code adapter delegates
  to this function, so the fix covers both.
- **Test.** The new test is `the Node file system keeps the case of the input path on a
  case-insensitive file system, like fs.realpathSync`, in `test/node-services/nodeServices.test.ts`.
  - It creates `CaseDir/File.md` in a temporary directory and resolves `casedir/file.md`.
  - It expects the result to equal both `fs.realpathSync(typed)` and the typed path.
  - On a case-sensitive file system (the typed path does not exist), it skips with `t.skip`.
- **Failure before the fix.** With `fs.realpath` from `fs/promises` restored on this macOS (APFS)
  machine, the test fails: actual `…/okf-node-case-…/CaseDir/File.md`, expected
  `…/okf-node-case-…/casedir/file.md`. It passes with the fix.

### N1: text snapshot in `resolvePreviewLink`

- **Fix.** `currentDocument.getText()` is now read once, as `currentText`, just before the
  `await navigator.validateResolvedPreviewNavigation(...)`. `frontmatterLinkIdentity` uses that
  snapshot. Between the link analysis and that read everything runs synchronously, so the identity
  and the analysis come from the same text again, as they did in `HEAD`.
- **Test.** None added. The race needs a document edit that lands during the stat/realpath await,
  inside `extension.ts`, and no unit seam reaches that today. The existing S1 host tests and the
  visual campaign cover the behaviour when there is no race. A direct test fits better when the
  preview session moves (S4).

### N4: in-memory store

- **`isApplying`.** The store now counts its edits in flight per document id, and wraps
  `changes.fire` in that count, with a `finally` that also handles a throwing listener. A listener
  of `onDidChange` therefore sees `isApplying(id) === true` for the store's own edit, as in the
  VS Code adapter (CR 046). After the edit, the count is back to `false`.
  - Test: `a memory store reports its own edit as in flight while the change event fires`.
  - Before the fix it failed: the listener saw `[false]`, where `[true]` was expected.
- **`idOf`.** Each path segment is now escaped with `encodeURIComponent`. `encodeURI` left `#` and
  `?` unescaped, so they became a fragment or a query of the id.
  - Test: `a memory store id is a file URI whose path keeps #, ? and % of a file name`. It covers
    `a#b.md`, `what?.md` and `100%.md`. It checks that `new URL(id)` has no hash or search, that
    the decoded pathname is the name, and that `open(id).path` round-trips.
  - Before the fix it failed on the `hash` assertion for `a#b.md`.
  - The existing `a b.md` round-trip test still passes.
