## Findings

### F1 (blocking, medium) — runtimeBundle test 3 compares against an oracle that S5 removes

`test/webview/runtimeBundle.test.ts:129-138`. The session trace of the bundled file is only
compared with the trace of the inline runtime (`session(undefined)`, i.e. `createScrollSyncScript`
via `toString()`). Apart from the first four entries, `inline` is never pinned. S5 removes the
`toString()` assembly, so the inline and context-free variants go away. The test then has nothing
to compare the bundle with: the S5 coder would have to delete the `deepEqual(shipped, inline)`
assertion, which weakens the test. The other option is to write a golden after the fact, from
code that has already changed.

Fix: pin the inline trace now as a literal expected value: the full array, the exact `scrollY`,
and the message list with types, identities, line, editedText and final. Then assert all three
variants against that literal (`deepEqual(inline, EXPECTED)`, `deepEqual(contextFree,
EXPECTED)`, `deepEqual(shipped, EXPECTED)`). After S5 the bundle keeps the same frozen oracle, and
the two pre-S5 variants can be dropped without dropping an assertion on the shipped runtime.
Add one sentence to the file header saying so: test 1 (`createPreviewRuntimeScript` reads no
undeclared name) checks the `toString()` mechanism and retires with it, while test 2 (the
shipped file) and test 3 (the golden trace) are the ones that must survive.

## Non-blocking

- N1 (low) — `runtimeBundle.test.ts:26-29` runs `node esbuild.mjs` from the unit run. It
  rewrites all of `out/bundle/` (extension.js, the mermaid and plantuml bundles, preview.js/css,
  katex). This is acceptable: about 0.7 s, the output is identical to `npm run bundle`, esbuild
  is a dev dependency, CI `ci-static` → `just check` has node_modules, and no other unit test
  reads `out/bundle` concurrently (previewRuntimeFile only matches the path string). The
  remaining hazard is a `just check` in the same worktree while a VS Code dev host or an
  integration run is reading `out/bundle/extension.js`. If that matters later, let `esbuild.mjs`
  take an output directory (for example an env var) so the test builds into a temp dir. That is
  a tooling change, not src/.
- N2 (low) — wire field names are spelled out in every new test: `documentVersion` in IDS, in
  `foreignIdentities` ("documentVersion as a string"), in `identityOf` / `nextIdentityOf`
  (previewTiming.test.ts:29-41) and in `PageIdentity` (hostHarness.ts:43-47). If S2 renames the
  identity field on the wire (the revision counter), these need a mechanical rename. That is not
  a weakening, and scrollSync.test.ts has the same coupling 449 times. To reduce churn, put the
  page identity in one shared constant or helper (for example export `IDS` from
  runtimeHarness.ts and build the variants from its keys).
- N3 (info) — runtimeHarness.ts:705: `timerDue` entries are never deleted on run or clear. This
  is harmless at test scale. Delete them in `clearTimeout` and when a timer runs, for hygiene.
- N4 (info) — `settle()` (200 `setImmediate` turns) comes before some positive assertions, for
  example the reload count at 2000 ms and the reassignment on a stale ready. Those paths reuse
  HTML that is already rendered, and 36 parallel runs stayed green. If one ever flakes on a slow
  runner, switch that assertion to `until(...)`, as the patch waits already do.
- N5 (info) — open point 3 of the report (debounces not covered: comments 150 ms,
  incoming-changes 300 ms, link enrichment / frontmatter, document-switch flush) is fine to
  leave to the existing campaign. It does not block S1.
