  - `own-id` covers `previewEditClosed` and `previewEditFlushed` (`disposed` only), as before.
  - `document` covers PlantUML include, Show Problems and banner close.
  - `comment` substitutes the stage revision, then runs `matchesCurrentPreview`.
  - `render` covers the rest of the registered types.
  - `page-state` keeps the old order: reload or patch-chain, render check plus `reportStaleEdit`,

- **Host to page.** `createHostMessageFilter` does what `sameContext` did per type, and the

    `hostRequests.receive` when their type ends in `Result`.

## Revision decision (autonomous decision 1)

The decision is acceptable for this step. The protocol and the page are now host-neutral: the page
only repeats `revision` and compares it for equality. The host maps the VS Code version in exactly
two named functions (`revisionOfDocument`, `revisionOfStage`). `TextDocument.version` is already a
per-document counter that only grows, which is the semantics `RevisionCounter` gives other hosts.
Adding a second counter now would change the numbers on the wire. It would break the pinned
real-input assertion (`data-sphinx-preview-document-version === source.version`) for no gain, and
S3 introduces the `DocumentStore` port anyway. One condition for S3 is in N2.
