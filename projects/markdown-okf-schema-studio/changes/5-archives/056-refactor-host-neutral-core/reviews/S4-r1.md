## Non-blocking findings

- **N1 (low) — double deferral**
  - Where: `src/session/previewManager.ts:811` and `src/session/features/plantUml.ts:128-137`.
  - What: `refreshReferencedPath` wraps `notifyIncludesChanged` in
    `deferWhileEditing("plantuml-includes")`, and `notifyIncludesChanged` wraps itself again with
    the same key.
  - Impact: none in practice. The queued work runs after the lock is released, so the inner call
    runs at once. In the worst case it re-defers under the same key.
  - Fix: drop one of the two wrappers. Either call `notifyIncludesChanged` directly, or make it
    post only. That restores the single deferral of HEAD.
- **N2 (info, for S6) — sync Node file access in the session layer**
  - "Ports only" is true for `vscode`, not for Node `fs`.
  - Direct use: `src/session` calls `node-services/paths.ts` (`realpathSync`, `statSync`,
    `os.userInfo`).
  - Indirect use, through modules it imports:
    - `frontmatter/linkedTargetWatch` (`fs.watch`)
    - `render/plantUmlIncludes` (sync read)
    - `frontmatter/okfFrontmatter` (schema lookup)
    - `myst/confLocator`
    - `build/buildQueue` (`canonicalPath`)
    - `preview/bibScan`
  - This is unchanged from HEAD and is acceptable for this step. List these explicitly when the
    S6 boundary rules are written: either allow `node-services`/Node for the session layer, or
    move these behind ports.
- **N3 (info, for S6) — new files over the ratchet ceiling**
