## B1: fixed

- `src/node-services/nodeFileSystem.ts:6,19,59-61`:
  - `realpath` is now `promisify(realpath)` from `node:fs`, which is the JS implementation.
  - I checked at run time that `fs.realpath !== fs.realpath.native`, and that `fs.realpath` has
    no `util.promisify.custom` override. So `promisify` wraps the JS callback version, which gives
    the same result as `fs.realpathSync`.
  - The TSDoc states this.
- `src/host-vscode/vscodeHost.ts:71` still delegates to `node.realpath`, so the fix covers both
  hosts.
- `test/node-services/nodeServices.test.ts:32-45` uses a mixed-case directory and resolves a path
  typed in lower case. It asserts equality with both `fs.realpathSync(typed)` and the typed path,
  and skips on a case-sensitive file system. This is the test I asked for. The coder says it fails
  with the native implementation, and round 1 confirmed that difference on this machine.
- Containment is unchanged. The root and the candidate still go through the same function.

  leaks.
