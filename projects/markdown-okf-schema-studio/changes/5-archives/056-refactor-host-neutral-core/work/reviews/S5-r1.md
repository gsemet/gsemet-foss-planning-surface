## Focus questions

### 1. `@ts-nocheck` on `src/page/runtime.ts`: no regression, so not blocking for S5

HEAD did **not** type-check this code. In HEAD `src/webview/scrollSync.ts`, lines 128–5617 are
the body of `runtimeScript()`, a template string. tsc saw a string literal; the analysis table
(01-analysis §3) describes it as "Untyped JS inside a string: no type check". Only three things
in that file were real TypeScript:

- the interfaces and `serializeRuntimeContext`, which are now typed with TSDoc in
  `src/protocol/bootContext.ts`;
- the injected `src/webview/*` modules, which are still typed in their own files and now
  imported normally;
- the dead `layoutMappings`.

I checked mechanically that nothing typed moved into the nocheck file:

- I rebuilt the HEAD runtime string from `git archive HEAD` (`createPreviewRuntimeScript()`).
- I un-escaped the template body.
- I diffed it with `runtime.ts` lines 66–4965.

Every change falls into one of these groups:

- `${fn.toString()}` became an import call;
- blocks moved to typed modules (about 700 lines out, 119 in);
- `\uXXXX` escapes became literal characters (the same runtime strings);
- the `contentReplaced` / PlantUML DOM events now go through the bus and `rendererBridge`;
- the `previewLinkTargets` handler is now on the router.

So the step is a net gain: about 1 100 lines are now strict TypeScript, and the residue is
exactly the old untyped string. The bundle undeclared-name test still guards the residue.

The spec says "typed bundle", so the step is only partly done. Removing `@ts-nocheck` now means
about 660 errors, which is S8's split work, not a minimal fix. Two follow-ups are required
(N1, N2) so that the debt cannot grow or be forgotten.

### 2. Behaviour and load-order equivalence: OK

- **Script order**: the page carries the same JSON element and `<script nonce src=preview.js>`
  as HEAD's production path (`injectRuntimeFile`). The bundle reads the context synchronously,
  as before.
- **Strict mode**: the old code was a `"use strict"` function. The new bundle starts with a
  file-level `"use strict"` before the IIFE. The behaviour is the same, because the script holds
  nothing else.
- **Boot JSON**: `serializeRuntimeContext` is unchanged from HEAD and escapes every `<`. The test
  "the boot context cannot terminate its containing script element" keeps the old
  `</script><script>` payload assertion.
- **CSP**: `src/security` and the CSP builder are unchanged. The retained
  `previewRuntimeFile.test.ts` still asserts no `unsafe-inline` / `unsafe-eval`. The no-bundle-URI
  path is now stricter: it injects no inline script at all (N4).
- **`acquireVsCodeApi`**: it is called exactly once, in `src/page/main.ts:14`. `pageHost` wraps
  the transport. The PERF-08 state and state-message throttle is a line-for-line port with
  `window` passed in (`pageHost.ts:47-112` against HEAD template 190-260). The `pageTimers` tests
  are byte-identical and pass.
- **Message listener**: `pageHostMessages.listen(transport, context, …)` (runtime.ts:4769) sits
  at the same place as HEAD's `window.addEventListener("message")` (template 5413). It runs
  synchronously during script evaluation, before `previewReady` can be posted. `context` is the
  same live object a content patch mutates, so the identity check per message is unchanged.
- **Removed listener**: HEAD had one other window listener, linkNavigation's (HEAD
  linkNavigation.ts:77). Its identity check (documentId, revision, requestId, `targets` array)
  is the same as the filter's `render` rule for `previewLinkTargets` (hostToPage.ts:349, 372-376).
  It now runs once, through the router.
- **Order of handlers and listeners**: features now register their router handlers earlier.
  Order does not matter there, because the router allows one handler per type. The button
  listeners keep their old order: theme, refresh, anchor (+ initial `postAnchorModeChanged`),
  edit mode (runtime.ts:4611-4614). The checkbox click handler keeps its "registered first"
  position (`checkboxes.bindClicks()`).
- **State restore**: `savedState = vscode.getState?.()` comes at the same point. The theme and
  anchor features take `savedState`. `anchorMode` keeps the `settings.scrollPreviewWithEditor`
  mutation and the saved-against-context comparison verbatim.
