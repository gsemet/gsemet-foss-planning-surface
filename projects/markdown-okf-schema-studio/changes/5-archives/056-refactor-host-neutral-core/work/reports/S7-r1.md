## Design

Three registries. Each keeps its pure data in `core` and binds code that needs the page in the page
layer. No boundary exception was added (`.dependency-cruiser.cjs` is unchanged).

### 1. Settings: one table (`src/core/configuration/settingsRegistry.ts`, core)

- One descriptor per setting, grouped by section (`PREVIEW_SETTINGS`, `EDITING_SETTINGS`,
  `FRONTMATTER_SETTINGS`, `COMMENTS_SETTINGS`, `PLANTUML_SETTINGS`), plus `SETTING_CATEGORIES`
  (section, title, order). A descriptor holds:
  - `schema`: the `package.json` fields, written as is and in their order (`type`, `enum`,
    `enumDescriptions`, `default`, `minimum`, `maximum`, `step`, `markdownDescription`, `order`).
  - `normalize`: the host-side read. It does exactly what the old readers did: stored booleans
    pass through unchanged, `trim` for the frontmatter roots, the clamps for width and depth, the
    palette mode check, `=== true` for `useJar`, and a string check plus trim for `jarPath`.
  - optional `boot`: the page reads the setting from its boot context. `startupSetting` marks a
    setting the content patch key compares; `liveSetting` marks one the page also follows by
    message (`showComments`). `read` is the page's normalization: `!== false` / `=== true` for
    flags, and `normalizeStickyHeadingDepth` for the depth.
- Generic functions: `readSettings`, `readSetting`, `settingDefaults`, `bootSettingKeys`,
  `contributedConfiguration()`. Types are derived from the table (`SettingValues`,
  `BootSettingKeys<D, "startup" | "live">`).
- The section modules (`previewConfiguration.ts`, …) are now thin typed views. Their export names
  and signatures did not change. `PreviewConfiguration` and the other types are now derived from
  the table, and their field TSDoc comes from the table entries.
- The table drives the boot context:
  - `PreviewRuntimeContext` extends `Partial<PreviewBootSettings>`, which is derived from the
    table. The six hand-written fields were removed.
  - The host writes `...previewBootSettings(configuration)` (`session/features/rendering.ts`).
  - The page reads `readPreviewBootSettings(context)` (`page/pageSettings.ts`).
  - `runtimeContextKey` and `RuntimeContextSettings` (`core/preview/contentPatch.ts`) and
    `runtimeContextSettings` (rendering) iterate `PREVIEW_STARTUP_SETTING_KEYS`.
- The table order is the boot context order. The generator sorts each category by
  `schema.order`, so the boot context JSON and the content patch key are byte-identical to HEAD.
- `PALETTE_MODES`, `PaletteMode` and `isPaletteMode` moved here (they are still re-exported by
  `editingConfiguration.ts`). `editPalette.ts` derives `MODE_RANK` from `PALETTE_MODES`, and
  `runtime.ts` uses `PALETTE_MODES` (same line count).
- Generator: `scripts/generate-settings.mjs` bundles the registry with esbuild in memory, so no
  compile step is needed. It replaces `contributes.configuration` and writes the file with
  `JSON.stringify(…, null, 2) + "\n"`; the HEAD file round-trips byte for byte through that.
  - `just generate-settings` (npm `generate:settings`) writes `package.json`.
  - `just check-settings` (npm `check:settings`, `--check`) fails when the file differs. It is
    part of `just check`, and therefore of `ci-static` and `preflight`.

### 2. Palette actions (`src/core/palette/`, core; handlers in `src/page/modules/editActions.ts`)

- `paletteActions.ts`:
  - `PALETTE_ACTIONS` holds the 40 descriptors, keyed by id, in display order (`satisfies
    Record<string, PaletteActionDescriptor>`). A descriptor is everything except code: label,
    title, icon, group, modes, scopes, shortcut, popover, static options, grid, emoji, colours,
    panel, `panelWhenInside`, `popoverAtCaret`, `hostList`, `hostDialog` and slash data.
  - The descriptor types (`EditActionMode` is `PaletteMode`, `EditActionScope`,
    `EditActionShortcut`, `EditActionOption`, `EditActionSlash`, `PaletteActionDescriptor`).
  - `PaletteActionId`, `PALETTE_ACTION_IDS`, and `ALERT_TYPES`, `ADMONITION_TYPES` and
    `COLUMN_ALIGNMENTS`, which the handlers share.
- `paletteIcons.ts`: `PALETTE_ICONS`, the icon markup that moved out of `editPalette.ts`. The
  `PaletteIcon` key union types `descriptor.icon`.
- `emoji.ts`: the picker data (`EMOJI_CATEGORIES`, `EmojiEntry`, `EmojiCategory`).
- Page, `editActions.ts`:
  - `handlers: PaletteActionHandlers` (`{ [K in PaletteActionId]: PaletteActionHandler }`) holds
    one entry per id: `apply`, plus the optional `available`, `explain`, `current`,
    `validateColor`, and the page-computed `options` (code block languages).
  - `actions = PALETTE_ACTION_IDS.map(id => ({ id, ...PALETTE_ACTIONS[id], ...handlers[id] }))`.
  - TypeScript refuses a descriptor without a handler, and a handler without a descriptor (excess
    key).
  - `EditAction` is now `PaletteActionDescriptor & PaletteActionHandler & { id: string }`. The old
    type names are re-exported from `editActions.ts`, so `editPalette`, `slashMenu` and the tests
    import unchanged.
- The edition palette and the `/` menu were already built from the registry list. They now get it
  from the core table: icons from `PALETTE_ICONS`, mode ranks from `PALETTE_MODES`.
- The `createEditActions` and `createEditPalette` docs no longer say "stringified,
  self-contained". That was stale since S5: the runtime imports them, and their tests import them
  directly.

### 3. MyST directives (`src/core/directives/`, core)

- `directive.ts` defines `MystDirectiveDescriptor`, with these fields:
  - `id`, `names`
  - `render(node, line)`: the pass on the `mystDirective` node
  - `attributes`: sanitizer rules, `{ valid(value, tagName), diagnostic: { code, message } }`
  - `style`: the preview CSS
  - `paletteActions`: `PaletteActionId[]`
- Three plug-ins, each with its pass, style and palette entry in one file:
  - `admonition.ts`: `admonition` plus the 10 kinds of `ADMONITION_TITLES`. Pass: position plus
    title inference. Style: the admonition callout block. Palette: `admonition`, `dropdown`.
  - `figure.ts`: `figure`. Pass: source lines on the figure container. Sanitizer rule:
    `data-okf-width` (`OKF_WIDTH`, which also replaces the duplicated `FIGURE_WIDTH` /
    `SAFE_OKF_WIDTH`). Style: figure and alignment rules. Palette: `figure`.
  - `tables.ts`: `table`, `list-table`, `csv-table`. Pass: alignment, list-table widths and
    header rows. Style: list-table cell and `:widths:` rules. Palette: `tableCaption`,
    `listTable`, `pipeTable`.
- `registry.ts`:
  - `MYST_DIRECTIVES`.
  - `directiveNamed(name)`: exact-name map; it throws at load on a duplicate name or attribute.
  - `directiveAttributeRule(attribute)`.
  - `directiveStyle(id)`.
- Wiring:
  - `mystRenderer.normalizeNode` replaced its three `mystDirective` blocks (admonition, figure,
    tables) with `directiveNamed(node.name)?.render?.(node, line)`, at the place of the first one.
    The name sets are disjoint and the blocks in between test other node types, so the order of
    effects is unchanged.
  - `html-sanitizer` applies `directiveAttributeRule(name)` where the `data-okf-width` branch was.
    The code, message and removal are identical.
  - `previewStyles.ts` places each plug-in's rules with `${directiveStyle("…")}` where they were.
- Helper moves:
  - The shared node helpers and types moved from `mystRenderer.ts` to `src/core/render/mystNode.ts`
    (`MystNode`, `RawHtmlNode`, `setHast`, `mergeProperties`, `sourcePositionProperties`,
    `findNode`, `normalizeTableAlignment`, `containsRawTable`, `takeAdmonitionTitle`).
  - The callout badges moved from `previewStyles.ts` to `src/core/preview/calloutIcons.ts`
    (`CALLOUT_ICONS`); the warning banner style uses them too.

## Open points

1. Page bundle size: the page imports the settings table, so the 18 `markdownDescription` texts
   ship in `preview.js` (+~5 kB minified). Keeping them out would need a second table for the
   descriptions, against "one table". Kept as is; the reviewer may decide.
2. Directive plug-ins cover the three directives that had dedicated code in `normalizeNode`.
   These still live in the renderer:
   - the version admonitions (`expandVersionAdmonitions`), `{include}` (`expandIncludes`) and
     `{uml}` (PlantUML);
   - the `data-myst-table-style` sanitizer branch (it keeps per-render state, the generated class
     map).
   The next step splits the renderer into named passes and can move them onto the same shape.
3. `chipToggle.ts` still reads `showComments !== false` itself. Its unit test evaluates the
   function through `toString()` in a `vm`, so the function cannot import the table. The rule is
   the same as the table's `liveSetting` read. I first changed it, saw that test fail, reverted
   it, and left it.
4. Stale "Injected … `.toString()`" comments remain in other page modules (`slashMenu.ts` and
   others). Some are still true for their tests. I touched only the two modules whose bodies now
   import.
