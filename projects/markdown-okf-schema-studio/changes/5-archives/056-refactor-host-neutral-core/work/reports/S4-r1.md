## What moved where

- Message handlers → the controller that owns the feature, all registered on one router per
  manager. A new unit test proves that each of the 41 gated types has exactly one handler.
- `ActivePreview` god object → `PreviewSession`, with its fields grouped per controller
  (`page`, `overlay`, `edits`, `scroll`, `frontmatter`, `plantUml`, `incoming`, `comments`, `links`,
  `probe`). Panel creation, the serializer and the custom editor stay in the VS Code activation.
- Event wiring: the activation translates VS Code events (rename, folders, active/visible editors,
  ranges, theme, save, close). Document changes come through `host.documents.onDidChange`.

## Equivalence notes for the reviewer

- The session tracks the resource roots it sets (`page.resourceRoots`) instead of reading
  `panel.webview.options`. This is equivalent because every session sets `[]` at creation.
- Open-document and sidecar lookups go through `host.documents.get(id)` (by URI string) instead of
  `textDocuments.find` by `fsPath`. This is equivalent for `file:` documents.
- `isOutsideChange` gets 1/2 mapped back from the `"undo"`/`"redo"` reason.
- The group lock sets `lockedColumn` after the lock command resolves (one extra await tick).
- Per-activation state (comment store, histories, banners) no longer survives a deactivate and
  re-activate. VS Code activates once per extension host. In the harness, each test activates
  once.
