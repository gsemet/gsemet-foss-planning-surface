# T1 round 1 - CR 123 the block edit toolbar never covers the edited content

## Root cause (reproduced headless, 460 px cream preview)
The edition palette is already in flow above the frame, inside one host, and sticky. Its sticking line is
4 px under the larger of the reading offset and the floating toolbar's bottom. A block whose host is nearer
the top of the pane than that line gets the bar pushed down over the frame (user image 1). For the figure
form, `keepTextInPlace` (editorChrome.ts) measured the scroll room from the frame's top, so the page scrolled
until the frame top sat on the sticking line, with the stuck bar over the form's title (user image 2).

## Fix (worktree /Users/az02065/Projects/DevTools/markdown-okf-schema-studio-wt-123, uncommitted)
- src/page/features/editorChrome.ts: new `reservePaletteClearance(edit)` (sticking line minus host top, +3 px,
  as `--sphinx-preview-palette-reserve` on the host; 0 when not needed or when the frame top is already more than
  one bar height above the line; measured on open, resize and palette height change, never on scroll; shifts
  the scroll anchor so the text is not scrolled back). `keepTextInPlace` now measures its room from the host's
  top (palette's own place), so the page never scrolls the palette onto the panel.
- src/core/preview/styles/contentLayoutStyles.ts: frame `margin-top: var(--sphinx-preview-palette-reserve, 0px)`
  (separate rule; the existing `margin: 0` rule and its test are unchanged). Marker PALETTE-021 added.
- src/page/features/pageRuntime.ts (type + `paletteReserve` field), blockSourceEditor.ts (call on open),
  scrollCore.ts (call when the palette height changes).
