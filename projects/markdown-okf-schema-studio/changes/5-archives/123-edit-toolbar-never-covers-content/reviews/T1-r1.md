## Design findings
1. Intent says "toolbar takes its real height in flow; editor and panels move down". The fix keeps the sticky palette and adds a
   computed margin-top reserve only when the bar is pushed over the frame. That meets the "sticky reserves height" decision in
   spirit but relies on JS measurement on open/resize/palette-height change, with a frozen value while scrolling (up to ~one bar
   height of gap). Acceptable only if proven in the real window; a pure-CSS in-flow reserve would be more robust.
2. The user's overlap occurs in a wide pane with a 2-row bar; the reserve applies only when `distance <= barHeight + 3`. Unproven that the
   user's block position (mid-document, scrolled) is covered: when the frame top is already above the sticking line the code reserves
   nothing, which is exactly the "tall block scrolled" case; the first lines under the stuck bar can still be hidden there. The
   autonomous decision ("sticky reserves the same height so the first lines stay visible under it") is not demonstrated for it.
3. Open the figure form via the Edit figure button (user's path, image 2) is untested even headless; the check uses the palette's figure button.
