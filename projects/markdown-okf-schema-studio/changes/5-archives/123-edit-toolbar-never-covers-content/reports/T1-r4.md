## Failure
Heavy CI run 40432564443, editToolbarCover.test.ts: "Timed out waiting for the Edit figure button to be shown. Page held:
{present:true, hidden:true, hovered:FIGURE, editMode:on}".

## Root cause (product bug)
`installFigureEditButton` (src/page/modules/figurePanel.ts) hid the button on any scroll (`window.addEventListener("scroll", hide, true)`).
A scroll raises no mouseover, so edit mode's `setEditHover` never re-synced: the figure stayed hovered (`data-sphinx-preview-edit-hover`)
and the button stayed hidden for good. In the e2e the test scrolls the figure to the top and hovers; the scroll event (smooth/anchored
scroll, late layout shift on a slow CI window) arrives after the hover and hides the button. Also `sync` returned early for the same
element, so a repeated sync could not recover.

## Fix
- `place(element)` factored out of `sync`; the scroll handler now re-places the button on the still-current figure (follows it) instead
  of hiding it. `sync` re-places when the button is hidden even for the same element.
- Files: src/page/modules/figurePanel.ts.
