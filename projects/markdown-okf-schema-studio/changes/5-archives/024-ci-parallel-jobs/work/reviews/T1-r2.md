## N1 (medium) Stale campaign state is reused silently
scripts/e2e-campaign.mjs:38-44. Two cases without `just clean` (env unset, i.e. local only):
 a) `begin` keeps the stage's OWN old `startedAt` when the run id matches (`reuse`). A re-run of `ci-visual`/`ci-integration` that dies before writing its manifest (visual/integration manifests are not deleted at start) leaves the previous passing manifest, which still satisfies `startedAt >= campaign.startedAt`; `ci-report` then passes on old evidence. The stage itself exits non-zero, but the report (and the e2e-manifest/junit) is green.
 b) `begin integration` adopts the SIBLING's run id from any existing file (`own?.runId || other?.runId`), even a day old. `ci-visual` yesterday + `ci-integration` today + `ci-report` passes with yesterday's visual evidence.
Fix: (1) always write a fresh `startedAt` in `begin` (drop `reuse?.startedAt`; keep own run id), so an old manifest predates the new campaign and is rejected; and delete the stage's own manifest at `begin` (visual: out/reports/e2e/screenshots/run-manifest.json; integration: out/reports/e2e/integration-manifest.json). (2) Adopt the sibling's run id only if the sibling's startedAt is recent (e.g. < 6 h), otherwise generate a new id and print a note, or make `report` fail when the two startedAt differ by more than that bound ("run just clean, then both stages"). Add a small node test for `begin` (fresh startedAt on re-run; stale sibling not adopted). `clean` (rm -rf out) does reset all files; preflight relies on it, which is correct.
