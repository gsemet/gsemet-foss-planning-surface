# T1 round 1: keyboard start on an empty document

Worktree: /Users/az02065/Projects/DevTools/markdown-okf-schema-studio-wt-156 (nothing committed).

## Root cause
`bindKeys()` in `src/page/features/insertPoints.ts` handled Enter only, and ignored every event whose
target is a BUTTON or A. Right after the edit-mode toggle is pressed, the toggle (a button) holds the
focus, and after a Tab or click the focus is on the Start writing button itself: Enter was dropped in
both cases. There was no ArrowDown handling and no keyboard-selection marker or hint on the button.
The existing visual scenario clicked the page body first, which hid the problem. The Arrow keys of
`blockSelectionView.ts` cannot help (they need blocks).

## Change
- `src/page/features/insertPoints.ts`: the Start writing point now holds the button (marker
  `data-sphinx-preview-start-selected="true"`, `aria-describedby`) and a hint `<p
  data-sphinx-preview-start-hint>` "Enter to create a new block". Enter and ArrowDown open the editor
  (same `openInsertPoint(start, 0)` as a click) when the target is the body, the preview content, the
  edit-mode toggle or inside the Start writing point; other buttons, links, fields, properties and
  editors, modifiers, IME, reading mode, failed render, filled documents and an open editor do
  nothing. ArrowUp is not handled. `blockMoves.ts` and `blockSelectionView.ts` untouched.
- `src/core/preview/styles/editModeStyles.ts`: the hint shares the typography rule of the editor
  status line (0.75em, description foreground) plus a 10px top margin; the selection ring (2px focus
  border, 3px offset) on the marked button. `firstClearance.ts` measures only the button: unchanged,
  the 20px/40px clearance check still passes.
- Docs: `docs/user/editing.md` (two lines in the keyboard paragraph).
