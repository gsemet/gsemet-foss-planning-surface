## What was done
- Format `<!-- THREAD` / `Author (YYYY-MM-DD HH:MM):` / 2-space-indented text / `-->`. Parser tolerant
  of CRLF, trailing spaces/tabs, tab indent, blank lines inside a message. Block-level only: an
  inline THREAD, or one without a valid header, stays an ordinary gray comment.
- Render: green chip (`okf-chip--thread`, CSS-mask speech bubble, label = first author, "(n)" when
  several messages), hidden body with one entry per message; the existing chip toggle expands it
  as the admonition-like box (green bar, title "Thread"). `showComments` off hides thread chips
  (separate CSS rule; existing gray/TODO rules unchanged). Styles only in the stylesheet.
- Interactions: reply box (Cmd/Ctrl+Enter or Reply) and "Delete thread" appended to the open body by
  the page (read-only in untrusted workspaces; blocked while a block/frontmatter edit is open;
  clicks in the body never open the block editor). New registered messages previewThreadReply /
  previewThreadDelete; the host re-reads the lines, refuses anything not exactly one thread,
  replaces only the last line (reply: author = comments.authorName, else git user.name, else OS user;
  local date same format; EOL of the document kept; `-->` in the text neutralised) or removes the
  thread lines plus one surrounding blank line; one undo step each.
- Creation: palette button + `/thread` (annotation group, strict mode, block scope) inserts an empty
  thread after the block with the caret on the message line; author comes from `threadAuthor` in the
  page context (resolved by the host, refreshed on each context build).

## Autonomous decisions (for the PR)
- Thread chip label = first author (+ message count) rather than a fixed word.
- Delete removes one adjacent blank line to avoid a double gap.
- Hidden with the gray chips by `preview.showComments` (TODO chips still always show).
- Slash aliases: thread, discussion, comment (no "note", it belongs to the admonition).
- Thread author for a new thread is resolved asynchronously and may be the OS user name for the very
  first page load before git answers.
