## What was built

- Charts: a `vega-lite` or `vega` fence becomes `<figure class="myst-vega-figure">` with a
  `.myst-vega-diagram` (spec text, `data-myst-chart-kind`) and a collapsed "Chart source" section,
  in every palette mode. The page runtime draws it as an SVG `<img>` (data URI), themed from the page
  CSS variables (foreground, muted, grid, link colour, font; light/dark palette by background
  luminance), error shown in place (`.myst-vega-error`, reason as plain text, source kept below),
  drawings cached by theme + source + data with the Mermaid cache (`createMermaidCache`), redrawn on
  theme change and on `studio:content-replaced`.
- CSP: no `unsafe-eval`. `vega.parse(spec, config, { ast: true })` + `new vega.View(runtime, { expr: expressionInterpreter })`
  (vega-interpreter). The page CSP is unchanged (`connect-src 'none'`).
- One more eval trap found and closed: Vega's CSV/TSV parser (d3-dsv) builds row readers with
  `new Function`. So the data files are parsed outside Vega: `src/core/render/chartInline.ts` turns each
  `data.url` into inline `values` (csv, tsv, json) before compile; Vega never sees a `url`.
- Data: the host reads each relative `url` through `readDiagramFile` (= `readBoundedText`, the `{include}`
  rules: workspace, Restricted Mode, symlink, 5 MiB), charged to the include budget, recorded as a
  dependency (re-render on change), max 16 files per chart; texts go to the page in
  `data-myst-chart-files`, refusal reasons in `data-myst-chart-errors` (both under the existing
  `data-myst-` allow-list prefix, so the sanitizer is unchanged). Remote urls (scheme or `//`) are never
  read and the chart shows "Remote chart data is not loaded: <url>". A custom Vega loader additionally
  serves only those files and only `data:image/`.
- JSON or YAML specs (`yaml` library already in the project; YAML 1.2 reads JSON).
- Lazy loading: own bundle `out/bundle/vegaPreview.js` (`esbuild.mjs`), added by
  `src/session/webview.ts` only when the content has `class="myst-vega-figure"` (script tag
  `data-sphinx-preview-vega`, nonce'd), like Mermaid/PlantUML (CR 135 pattern). It is part of the shell key, so a chart
  appearing or disappearing is a full page, as for Mermaid.
- Mode Full: `PALETTE_MODES = strict, gfm, myst, full` (settings registry, `package.json` regenerated
  by `just generate-settings`, host message check, boot context, page types, select label "Full").
  Actions `vegaLite` ("Vega-Lite chart", aliases chart, vega-lite, vegalite, plot, graph) and `vega`
  ("Vega chart", aliases vega, chart, plot), mode `full`, group `full` (slash group label "Full"),
  new icon `chart`; insert a 3-bar starter after the selection, title selected. `/chart` also matches
  Mermaid (it already had that alias, kept); in Full mode the slash menu prefers the `full` group.
- Docs: new `docs/user/charts.md` (examples JSON, YAML, Vega, data files, errors, Full mode, limits),
  links in `docs/user/README.md`, `settings.md`, `slash-menu.md`, `editing.md`; README section
  "Charts, no executable" with two images and docs links; `CHANGELOG.md`.
