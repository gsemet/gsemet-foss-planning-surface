## Cache mechanics (verified)

- **Order and empty cache.** Restore runs before `dev-ci visual`. The exact key never exists, so
  the prefix restore-key selects the newest saved set. When the cache is empty, `nullglob` gives an
  empty array, the copy is skipped, and the script logs "0 restored".
- **apt reuses the archives.** The archives go into `/var/cache/apt/archives` through `sudo -n cp`,
  with mode 644 and their original file names (epoch encoded as `%3a`). apt checks each one against
  the index hash and skips the download. Playwright's own `sudo apt-get install` uses the same
  folder, so both installs are covered. `partial/` already exists on the image.
- **The cache does not grow.** `autoclean` runs after `update`, so it drops only versions that are
  no longer downloadable. The set is then copied back. A changed set produces a new hash key, and
  an unchanged set skips the save.
- **Failed setup.** When `dev-ci visual` fails, the save step does not run (default `success()`).
- **Concurrent saves.** A duplicate key produces only a warning.
- **Retries and timeouts.** Dropping `Acquire::Retries` is justified: the log shows the same 59 MB
  `Get:4` started three times. It is consistent with rule 9. No `timeout-minutes` value changed.
  The 30 s stall timeout fails a job; it does not retry it.
- **`checks` aggregate.** The aggregate is unchanged.
- **Docs.** The guideline, AGENTS.md and CONTRIBUTING.md edits are consistent and wrapped at 100
  characters.

## Findings (none blocking)

1. **Low: `.github/workflows/ci.yml:88-91`, the save step runs when no archive exists.**
   `hashFiles` returns `''` when no `.deb` is present, for example if the image disables
   keep-downloaded. The step then saves an empty entry under `apt-archives-visual-Linux-X64-`. The
   job does not fail, but the empty entry can be restored by the prefix key and makes a useless
   save. Exact fix: replace the `if:` with the following.
   ```yaml
        if: >-
          hashFiles('.cache/apt-archives/*.deb') != '' &&
          steps.apt-archives.outputs.cache-matched-key != format('apt-archives-visual-{0}-{1}-{2}',
          runner.os, runner.arch, hashFiles('.cache/apt-archives/*.deb'))
   ```
2. **Low (optional): `.github/workflows/ci.yml:84-85,95`, the key does not name the runner
   image.** A switch of `ubuntu-latest` (24.04 to 26.04) restores the other release's archives. This
   is harmless, because apt rejects hash mismatches, `autoclean` prunes the old archives and the
   new set is saved under a new hash. Still, the first run after the switch downloads everything.
   Optional fix: insert `${{ env.ImageOS }}` after `${{ runner.os }}` in `key`, in
   `restore-keys`, in the save `key` and in the `format(...)` of finding 1. If you apply it, use
   `format('apt-archives-visual-{0}-{1}-{2}-{3}', runner.os, env.ImageOS, runner.arch, hashFiles(...))`.
3. **Info: `.github/workflows/pages.yml:58-61` (out of scope).** Pages still installs plantuml,
   graphviz and the Playwright deps from the live mirror, without `dev-ci`. The new wording of
   guideline rule 4 ("never from a live mirror on every run") now describes this workflow as
   non-compliant. A slow mirror can stall a tag deployment. Follow-up: switch pages.yml to the same
   restore, `just dev-ci visual` and save sequence. Do not do it in this CR.

   with `sudo -n tee` before `apt-get update` in `dev-ci visual`. The coder's report already notes
