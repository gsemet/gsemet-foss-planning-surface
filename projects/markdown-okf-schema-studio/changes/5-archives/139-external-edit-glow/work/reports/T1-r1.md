# T1 round 1 report: CR 139 an edit made by another tool to the active document glows

## Behaviour

Rule (decided by the main session): a change is the writer typing only when a key was pressed in a
text editor in the last 500 ms AND the changed lines are on a cursor or a selection of the document.
Every other change is foreign, whichever document is the active editor. Undo/redo and the preview's
own edit are unchanged.

Autonomous decisions to list in the PR body:
- VS Code has no key event. The key signal is a text-editor selection change of kind Keyboard (typing,
  cursor keys), noted by `src/host-vscode/keystrokes.ts`. VS Code reports it AFTER the change it
  causes, so a change that touches a cursor with no key seen yet stays pending
  (`page.pendingOutsideChange`) and is settled by the patch that shows it: a key seen since the change
  means typing, none means a foreign edit.
- "Touches" is by lines with one line of margin (`CURSOR_LAG_LINES`), because the extension host reports
  the cursor a character or a line behind the change while typing.
- A keystroke in the preview needs no feed: typing in the preview reaches the document as the
  store's own edit (`isApplying`), which never glows.
- No `type` command override (it would clash with other extensions such as Vim).
- Verified with real keys in a real window: typing gives selection kind Keyboard; Backspace gives no
  kind (see open points).
