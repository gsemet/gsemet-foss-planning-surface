## Changed assertions (intent unchanged, default behaviour identical)

All in capture.py `check_preview_toolbar` / `check_diff_toggle`, they assumed a default page:
1. Theme button label: expected label is "Preview theme: Dark theme" when `previewThemeMode` is dark (as already done for cream).
2. Edit button: a scenario with `render.readOnly` must have NO edit toggle (new failure message if present); every other scenario still requires it with the same label.
3. Diff toggle: starts pressed unless `render.incomingChanges` is false, then it must start unpressed; label, tooltip, switch and final restore follow that start state. Default scenarios run exactly the old checks.
4. Zoom limits check: the `finally` restores the zoom the page started with (was hard-coded 100). Identical for default pages, needed for the zoom scenarios.
