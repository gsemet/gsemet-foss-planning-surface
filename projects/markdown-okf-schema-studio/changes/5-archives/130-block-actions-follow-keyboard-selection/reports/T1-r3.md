# T1 round 3 (CR 130): CI failure "pointer moved last"

## CI evidence
Job log fetched with `gh api .../actions/jobs/122172513378/logs`, and the CI screenshots taken from
the `e2e-integration` artifact. In both themes the result was
`afterMouse {"selectedBar":0,"hoveredBar":0,"ring":false}`. The `pointer-moved-last` shot shows no
actions on any block and no ring. The layout matches the local one: same 571 px frame, no scroll.

## Root cause
This is a test-harness problem, not a product defect. `ring:false` means the page's `mousemove`
listener did see the test's pointer move (owner `keyboard` -> `pointer`), so the product code ran.
After that, no block was `:hover`. The old test measured each state after a fixed 300 ms and
after `page.screenshot(...)`. On the Linux/xvfb runner, the CDP capture resets the webview
frame's hover state (a leave, not a move, so the owner stays `pointer`). The test then read
"no bar anywhere". Phase 1 was not affected because its expected hover value is 0. This only
happens in the measurement: a real pointer on that block would keep it hovered.

Locally I found the reverse harness race. A CDP mouse move sent right after a screenshot can be
dropped: one run had owner still `keyboard` after the move, in cream only.

Scroll theory ruled out. Short viewports (500 and 330 px) and the CI order (checkbox ->
empty-column -> block-actions) both passed locally.

## Fix (test only; product code unchanged; assertion values unchanged)
`test/integration/blockActionsFollowSelection.test.ts`:
- Each state is read once it settles (polling for up to 5 s) and **before** its screenshot,
  instead of after a fixed 300 ms and after the shot.
- Phase 2 resends the real pointer move inside the hovered block while it polls, because a real
  pointer keeps moving. This covers a dropped CDP move.
- The log and the failure message now include what the page saw (`owner=` and the innermost
  `:hover` element), both before and after the pointer shot. If CI fails again, this tells the
  cause apart.
- The test still fails on the old code (the keyboard half: the hovered bar stays shown while the
  keyboard owns the actions).
