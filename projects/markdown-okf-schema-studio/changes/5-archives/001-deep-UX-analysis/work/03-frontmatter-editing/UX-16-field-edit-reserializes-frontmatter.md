# UX-16 — Editing one frontmatter field re-serializes the whole frontmatter

| Field | Value |
| --- | --- |
| Severity | High |
| Confidence | Reproduced (diff of buffer against the file on disk) |
| Area | Frontmatter properties table editing |
| Evidence | [r3-fm-title-saved.jpg](../../evidence/r3-fm-title-saved.jpg) |

## Use case

An author changes the `title` of an OKF requirement from the properties table. The file is
tracked in Git and some fields are generated by `okfreq` tooling.

## Steps to reproduce

1. Side preview on `okf/okfreq-examples/requirements/tiers/swrs/SwRS-CORE-001.md`, edit mode on.
2. Edit `title` and commit (blur).
3. Diff the buffer against the file on disk.

## Observed

```diff
-title: Write CSV output
-description: When export is requested, the service SHALL write the report as CSV
-  output.
+title: |
+  Write CSV output: with quotes "and" colons
+description: When export is requested, the service SHALL write the report as CSV output.
-- StRS-CORE-001
+  - StRS-CORE-001
-- src/export.py
+  - src/export.py
-- tests/test_export.py
+  - tests/test_export.py
```

Besides the edited field (see [UX-17](UX-17-enter-in-text-field-creates-block-scalar.md) for the
`|` block), the untouched folded `description` is flattened to one line and every sequence is
re-indented from `- x` to `  - x`. Every frontmatter edit from the table produces a diff over the
whole block.

## Impact

- Noisy diffs and review friction on every metadata change.
- Fights with the formatter used by the bundle's own tooling: `config.yml` declares
  `generated_fields: [derived_by, implemented_in_files, tested_in_files]`, so the next generator
  run re-indents everything back.
- Related to, but distinct from, STAB-01 in `../deep-analysis-review/07-stability-and-correctness.md`
  (fence detection truncating the block).

## Where it comes from

`src/frontmatter/okfFrontmatter.ts` `createFrontmatterDocumentPatch` (around L259-L272) returns
`document.toString({ lineWidth: 0 })` for the whole YAML document. `lineWidth: 0` disables folding
(flattening `description`), and the default `indentSeq` re-indents sequences. The unit tests use
fixtures already written in that canonical style
([QA-01](../08-test-campaign-gaps/QA-01-roundtrip-fixtures-match-serializer-style.md)).

## Suggested direction

Patch only the edited pair: use the CST/source token ranges (`keepSourceTokens: true` is already
set) to replace the value node's source range, and stringify only the new value with options that
match the existing style (sequence indentation detected from the document, `lineWidth` matching the
original folding). Fall back to whole-document stringify only for structural edits, and report it.

## Test to add

Unit: for a frontmatter with compact sequences and a folded scalar, edit another field; assert that
every other line is byte-identical. E2E: same through the properties table.

## Done when

Editing one field changes only that field's lines.
