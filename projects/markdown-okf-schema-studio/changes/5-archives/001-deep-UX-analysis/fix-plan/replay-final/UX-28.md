Every typing run passed its other checks: the text reached the buffer (one changed line) and the
preview, with 0 console errors.

- **Where the remaining navigations come from.** In run 2 the keys ran from 29.413 to 31.417 s and
  the navigations from 30.670 to 31.589 s: the first ~20 keystrokes (about 1.25 s) were patched in
  place, then the preview fell back to full loads until just after the last key. In run 1 they
  started 0.76 s into typing. Code reading, not verified: `updatePreview` patches only when the
  page has reported ready for the previous stage (`preview.readyRequestId ===
  previousStage.requestId`, `src/extension.ts:929–940`); a render that completes before the
  previous patch is acknowledged loads the full document, and the loaded document must report
  ready again before the next patch can apply.
- **Flicker probe** (2095 DOM samples while typing 21 characters): one `scrollY` value (836), one
  document height (52868), status "Preview ready" throughout, 0 transitions, 0 navigations.
- **Filmstrip** (24 frames, 12 distinct): every frame shows rendered content; no blank frame and
  no scroll jump. Coarse, as the skill warns.
- **Kill switch works**: with the setting off, 10 characters gave 6 navigations where the same run
  with it on gave 0. The setting applied live, without a window reload. The off value (0.56 per
  character) is lower than T40 (0.81), consistent with T43 (D-22: no reload while a render is
  pending).
