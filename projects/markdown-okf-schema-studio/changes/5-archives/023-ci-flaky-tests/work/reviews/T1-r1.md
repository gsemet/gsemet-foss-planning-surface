### 2. LOW/MEDIUM - save handler is broader than needed and can double-render
`src/extension.ts` ~4743-4746: `refreshReferencedPath` is called for every preview on every save of any
document. Cost is small (path compare + map scan) for unrelated files, but for a file in
`preview.queue.dependsOn` (an include saved in the editor) the function falls through to
`refreshOpenDocument(preview, true)` while the `**/*` watcher fires the same refresh again: a doubled
full render that did not exist before. It also runs for readOnly/untrusted previews (harmless: it only
re-reads and re-renders, gated by `sourceAvailable`).
Fix: restrict the save-time call to the linked-target branch only, i.e. in the handler (or via a small
helper) check `preview.linkedTargetWatchers` keys against the saved path (canonicalPath compare) and
call only `scheduleLinkEnrichment(preview, preview.documentUri, preview.document.version)`; leave the
dependency re-render to the watcher as before. Scheduling is debounced and clears the previous timer,
so no loop/double enrichment results. Also confirm the saved document being the preview's own document
is still skipped (it is: `documentKey(document) !== preview.documentUri`).
