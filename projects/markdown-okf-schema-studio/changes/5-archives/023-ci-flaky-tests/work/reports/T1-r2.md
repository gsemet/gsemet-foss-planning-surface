# T1 round 2 report (fixes for reviews/T1-r1.md)

1. F2 coverage restored. New test hook `linkedTargetEvents` (src/extension.ts: counter on the
   preview, incremented in the per-target watcher callback, exposed by `getActivePreviewForTests()`).
   Test flow in previewEditing.test.ts: (a) edit + save of the target in the editor, wait for
   "Saved target description"; (b) wait until `linkedTargetEvents > 0`: the per-target watcher
   delivered the real event of our own save, which is the deterministic "armed" signal (creating the
   watcher object is not proof, the OS arming is async; a delivered event is); (c) `fs.writeFileSync`
   external write with "Updated target description" (the text later steps already expect), wait for
   `linkedTargetEvents` to increase, then for the excerpt. Single waits of 10 s, no retry, no sleep.
   Residual: if the watcher never delivers on a runner, step (b) now fails with a precise message
   instead of a blind retry, which is the intended diagnosis. Limits: a fully quiet watcher cannot be
   told apart from a slow one beyond the 10 s.
2. Save handler narrowed: it only calls `scheduleLinkEnrichment` when the saved path (canonicalPath)
   is one of the preview's `linkedTargetWatchers` targets and the saved document is not the preview's
   own. It no longer goes through `refreshReferencedPath`, so an included file saved in the editor is
   not re-rendered twice (its watcher path is unchanged).
3. F3: comment added in `unlockPreviewGroup` on the TabGroup identity assumption and its failure mode.

Gates: `npx tsc -p .` clean; `just check` exit 0; `just visual` passed (255 scenarios, 150
