# Coder round 5: CR-343, RI-T16 click check measures the hidden edited paragraph

## What changed

`test/integration/realInput/editorWidgets.ts`, `scenarioEditModeNoReflow` (RI-T16) only:

- `heights()` now selects `p[data-sphinx-source-line]:not([data-sphinx-preview-editing="true"])`,
  with a comment on why: `blockEditor.ts` keeps the clicked paragraph in the DOM, marked
  `data-sphinx-preview-editing="true"`, and `editModeStyles.ts` hides it with `display: none`, so
  its height is 0 (heavy run 44283551410: "paragraph at line 3 changed height from 67.17 to 0").
- The count check (`clicked` length = `reading` length - 1) became a `deepEqual` of the line keys:
  the lines visible after the click are the reading lines minus the clicked one (the first
  paragraph, the smallest line key; numeric keys keep document order). Its message names the
  clicked line, the reading lines and the visible lines, so a failure shows what was left.

## Intent kept

- `reading` and `hovered` are taken while no paragraph is edited, so the new selector matches the
  same paragraphs there as before: the hover check (`deepEqual(hovered, reading)`) is unchanged.
- After the click, every visible paragraph is still compared with its reading height (within
  2 px), so the no-reflow proof still covers the same visible paragraphs; the clicked one leaves
  the comparison, and the key check proves that exactly it, and only it, became the editor.
- The earlier `measure()` (scrollHeight and third paragraph top, before/after edit mode) runs
  before any click and is untouched.

## Same flaw elsewhere

- RI-T16: no other selector measures paragraphs after the click (`nth(1).hover()` and
  `nth(0).click()` run before an editor opens).
- `tableInsertSlash.ts` (RI-T45): clicks `p` by text before the editor opens, then reads the text
  box and the buffer; it measures no hidden paragraph. Not the same cause: unchanged.
