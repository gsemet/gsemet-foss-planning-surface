Requirements viewer · step 0

A public-transport signage, not a sci-fi map.

The viewer borrows the language of transit signage: each area is a line with its own colour, each use case a station, and a use case's paths are drawn as a metro map. The metaphor stays in the signage; the pages stay calm documents a team can read every day.

PrinciplesWhat each page must and must not do

Do

  • One level of detail per page: areas, then use cases, then the map, then the behaviour.
  • Colour means one thing: the area. Path 1, path 2 and the scenario kinds are the only other colours.
  • Every number links to what it counts.
  • Motion only to show a direction or a change (a path being walked, a panel replacing another).
  • Works the same on a phone: lists stack, the map turns vertical.

Don't

  • No glow, neon, particles, starfields, 3D or glassmorphism.
  • No gradient text, no decorative blobs, no emoji as icons.
  • No metro map outside the use case page.
  • No animation that loops while the reader reads (except the pulse of a goal station).
  • No number without its unit in words.

Tone

Editorial serif for what people read (titles, needs, rules, scenarios); a plain sans for labels and controls; a monospace for identifiers and file paths. Sentences, not jargon: “4 use cases · 27 behaviours”, not “StRS: 4 / SwRS: 27”.
