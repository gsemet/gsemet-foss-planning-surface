## Item 1: what is true

A highlight that starts or ends where two sibling text nodes touch joins them. The wrap splits the
text, and removing the mark merges it with both text neighbours. The plan reads sibling text nodes as
one run only through a highlight. So a later list (the same list or a reply included) or a content
patch that keeps the block highlights a quote across that place, where a page that receives only that
list shows a badge. A thread whose words that highlight takes gets a badge. No code change: the
specification asks for the same result as before this change.

SwRS-MDOKFSTUDIO-REVIEW-224: the statement (description and Normative behavior) excepts a page where
an earlier highlight started or ended between two touching text nodes; S1 and S5 say it in their
GIVEN; S2 adds a condition for the earlier and the later lists; the criteria say the compared pages
are equal where no highlight starts or ends at such a place; one new Known issue says what happens and
what was checked; the older Known issue "A content patch or a new render removes every comment element
and places every thread again" lost the part that was false in this case. Log bullet under 2026-11-27.
`just requirements-update` rewrote one index line.
