## What changed

- New `src/page/modules/commentPlan.ts` (203 lines): read only. Computes where each thread belongs
  (highlight, badge, orphan) on the content as it would be without highlights, from one lazy read of
  the mapped blocks. The attribute names and the placement rules moved here (REVIEW-017 marker with
  them).
- New `src/page/modules/commentPlacements.ts` (283 lines): changes only what differs between the page
  and the plan; `update([])` removes everything and restores the text nodes. `update` returns true
  only when a badge below a block was added, moved or removed (REVIEW-028 and REVIEW-224 markers).
- `src/page/modules/commentThreads.ts` (800 to 566 lines): uses the placements. A posted list updates
  in place; a content patch or new render (`apply`) still removes and places everything. Popover
  reopen, draft, questions and traces as before. `setThreads` returns whether the page must be
  measured.
- `src/page/features/hostHandlers.ts`: `scroll.measure()` only when `setThreads` returns true (false
  with comments hidden); REVIEW-224 marker.
- Test `test/page/modules/commentThreadsUpdate.test.ts` (new, 20 tests): element identity, no write,
  one read (S1); explicit sequences and seeded random lists compared with a fresh page, text node
  boundaries included (S2); popover (S3); measure count through the real host handler (S4).
- Requirements: new SwRS-MDOKFSTUDIO-REVIEW-224 (`proposed`, four scenarios, from StRS REVIEW-001 and
  -003); REVIEW-028 verification note names `updateOrphans`; log entry 2026-11-27. The two StRS files
  differ only by the generated `derived_by` and link lines; REVIEW-017/028 `implemented_in_files` are
  generated from the moved markers. All markers of the base module are still present.
- `CHANGELOG.md` line (no timing claim); `.agents/glossary/common.md` "Orphaned thread" file pointer.
