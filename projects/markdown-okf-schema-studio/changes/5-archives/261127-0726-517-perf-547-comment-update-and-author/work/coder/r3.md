## Item 3: outcome

At `6c099bf` an update could move a mapped block while `update()` returned false, and the content's
size did not change, so the `ResizeObserver` did not measure either: the page kept stale block
positions where the base code measured them. Observed in headless Chromium 156.0.8078.4 with the real
render, stylesheet and page bundle (comments shown and hidden).

| Added, moved or removed element | Can the box of a mapped block change? | Observed at `6c099bf` | Now measured |
| --- | --- | --- | --- |
| Highlight | yes: its element unmatches `:last-child` (`li > p`), and its line can wrap anew | 2 unmeasured moves of 76 single highlights at each of 4 widths (list +4.19 px, content size unchanged); rewrap moves a paragraph by 22.39 px (seen where the content resized; in a short column it would not) | every highlight added or removed |
| Badge inside a block that holds another element (first added, last removed) | yes: it unmatches `:last-child` among those elements | 8 unmeasured moves shown and 8 hidden in a short grid column (`li` +1.39 px, admonition +14 px) | yes |
| Badge inside a block that holds text only | no | no unmeasured move at any place (widths 420, 900, edit mode) | no |
| Further badge inside a block, badges reordered, one fewer in a block that keeps one | no | 1660 cases on the fix, 0 moves (no `:nth-last-child` rule exists) | no |
| Badge below a block | yes: it is in the flow | already measured | yes, as before |
| Orphan box and entries | no: after the content element; a tall box only lengthens the scroll | 36 updates at widths 420, 670, 1500 on a settled page, hidden scrollbars, 0 moves | no |
| Resolved, reopened, reply | no: paint and label only | 0 moves (resolved and reopened badges; replies and highlight style by reading) | no |

With classic scrollbars the long probe page does not rest (open point 3), so the orphan runs that
count used hidden scrollbars. A scrollbar that appears narrows the content, which the observer

## Consequence to know

A highlight added or removed measures again, as the code before this CR did. So creating or deleting
a comment on selected words still measures the whole page; the saved measure applies to replies,
resolve and reopen, text-only badges, further badges in a badged block and orphan changes. The
real-window runs of issue 547 (comment creation) should not be expected to gain from the measure.
