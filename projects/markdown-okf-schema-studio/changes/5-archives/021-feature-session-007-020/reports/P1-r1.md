# P1 r1 - toc-column screenshots showed no TOC

## Root cause
Harness bug, not a product bug. `check_toc_column` (test/visual/capture.py) opened the TOC with the
real toolbar button and verified it, but its `finally` block closed it again, and the screenshot is
taken after all checks. So every `toc-column-*` PNG showed the column closed (confirmed on the old
`toc-column-dark-1600.png`: TOC button unpressed, no column). The product toggle works at 900 and
1600 (opens, no overlap, Auto/Full respected, all existing assertions passed). T12 r1 noted
"no screenshot of the open column is saved".

Narrow behaviour (documented, intended): under 760 px the column is hidden by CSS; the button only
records the preference (aria-pressed true). The 460 shots therefore correctly show no column.

## Files changed
- test/visual/capture.py: new `check_toc_shot` (registered after `check_toc_column`). Opens the TOC
  through the toolbar button, sets the scenario's width mode through the Width button, scrolls to
  top, then asserts: toc open + button pressed; wide pane: column displayed, width/height >= 100,
  inside the viewport, >= 8 entries, exactly one `aria-current` heading, top >= toolbar bottom + 7,
  content column and tables do not overlap it; narrow pane: column hidden, preference kept. The
  TOC stays open for the screenshot.
- test/visual/scenarios.ts: `tocShot` field; series now light-900, dark-1600 in margin/auto/full
  (`toc-column-<theme>-<w>[-auto|-full]`), plus light-460 and dark-460 (margin).

## Tests / pre-change failure
The pre-change failure is the screenshots themselves (column closed in all three). Not recorded as
a failing run: the new assertions are new scenarios, with no old-code equivalent.
