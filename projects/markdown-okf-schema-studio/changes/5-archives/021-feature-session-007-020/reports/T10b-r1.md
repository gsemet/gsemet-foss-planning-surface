## What was done
- `widthMode.ts`: Auto breakout now also sets `--sphinx-preview-breakout-shift` = centre of the
  available area ((pane - TOC reserve)/2) minus the column centre; CSS applies it to the start
  margin, so a wide element is centred on the available area, capped at available width.
  A table is measured uncapped (temporary `data-sphinx-preview-measuring`, CSS `max-width:none`),
  so its cells no longer wrap when the table could fit (width = what it needs).
  Paragraphs holding only an image get `data-sphinx-preview-figure` (all modes, top-level blocks
  only, difference-only writes); CSS centres them.
- CSS: top-level `table`/`.table-wrapper` get `margin-inline:auto` (centred, own width, in
  Margin/Auto/Full); figure was already centred (caption centred). Code blocks (`pre`) stay in the
  breakout list and are not centred when narrow (documented in the widthMode doc comment).
- README: new section "Wide Tables and Figures" with the cream screenshot; Width setting text
  updated. CHANGELOG bullet added.
- Screenshot: no script produces `images/readme/` from the visual harness (`scripts/generate-readme-images.py`
  crops E2E captures). I added scenario `readme-margin-break-cream` (cream, 1200x1000, Auto, new
  `widthModeShot: "auto"` + check `apply_width_shot` that also asserts table and figure break out
  centred), took `out/reports/e2e/screenshots/readme-margin-break-cream.png` (2400x2000, 2x),
  cropped to 2400x1800 and downscaled to 1200x900 with Pillow (`uv run --no-sync --group docs
  python`, optimize=True). Not wired into generate-readme-images.py (it only reads E2E captures).
- Found and fixed a latent product bug: `src/preview/webview.ts` injected the page script with
  `String.replace(re, string)`; the minified bundle uses `$` as identifier, so `$&` in the script
  was replaced by `</body>` and the whole page script failed to parse (this made test:scroll fail
  with the anchor button not disabled, as soon as my code changed the minifier's naming). All four
  inject helpers now use a function replacer.

## Deviations / open points
- Narrow centring of images alone in a paragraph is done by a runtime attribute, not pure CSS,
  because `:has(> img:only-child)` would also match "text ![x](y)".
- In the README capture one table cell ("OPS-1063") still wraps although the table is narrower than
  the available width (about 1px rounding of the measured width); cosmetic.
- RTL layouts are not handled by the shift (start margin is logical, shift is not mirrored).
- Debug edits to `out/` (compiled test JS) were overwritten by later compiles; `git stash` was used
  briefly and fully popped.
