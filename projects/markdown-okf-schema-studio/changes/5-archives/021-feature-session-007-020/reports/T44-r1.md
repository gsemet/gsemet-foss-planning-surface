## Behaviour
- Popover (writable previews only): Resolve / Reopen and Delete. Delete swaps the buttons for "Delete thread?" Yes / No
  inside the popover (no `window.confirm`). Both wait for `previewCommentResult`; nothing is assumed before ok:true;
  a refusal shows the reason via `textContent` in `[data-okf-comment-action-error][role=alert]`; 15 s without answer
  shows "No answer ..." and re-enables the buttons. No second send while waiting. The pending question survives the
  threads being re-posted; Escape/close forgets it. Read-only previews pass no hooks: no buttons (host refuses anyway).
- Host: deleting the last thread writes `threads: []` and keeps the file. Unknown thread -> ok:false "no longer exists".
- Orphans: a thread with no eligible block at its line now falls back to searching the quote in every eligible block
  (so a moved quote is still highlighted); only when that also fails, and no badge is possible, it is orphaned. The page
  renders `div[data-okf-orphans]` (title "Orphaned comments", one button per thread with quote, first comment, count,
  resolved state; all `textContent`) as the next sibling of `#sphinx-myst-preview-content` (outside the patched HTML),
  removed and re-created by every `apply()`. Entries open the same popover (resolve/delete possible). The page never
  writes for an orphan: file untouched.
- Scroll review focus: the box's top margin is `calc(-1 * <the content's bottom padding expression>)`, so it sits in the
  content's empty bottom padding and the document height only grows if the box is taller than that padding. The box is
  `pointer-events: none` (only entries take them), so clicking the empty area below the content behaves as before. It is
  outside the content element: `> :first-child` gap, insert points and the content ResizeObserver are untouched.
  A unit test (`previewStyles.test.ts`) pins that the margin repeats the padding exactly.
