## What
- Toolbar row 2: `data-sphinx-preview-width-toggle` after Zoom + (three inline icons, shown by `data-width-mode`;
  label/tooltip "Width: Margin|Auto|Full width").
- `installWidthMode` (self-contained, injected with `.toString()`): cycles modes, sets
  `<html data-sphinx-preview-width>`, saves `viewWidthMode` in the webview state, posts
  `previewViewPreferenceChanged` `widthMode` (already in the T03 registry/host handler, no registry change),
  calls `firstClearance.update()` + the shared reading-line routine (same as zoom).
  Initial: webview state, then `initialViewPreferences.widthMode` (T08 store), then margin.
- Auto: top-level `table, figure, img, pre, .myst-mermaid-diagram` (img via its image-only paragraph) wider than the
  column get `data-sphinx-preview-wide` + `--sphinx-preview-breakout` (via style.setProperty), capped at pane - 2x16 px.
  Natural width = max(scrollWidth, img width attribute, naturalWidth). Flags cleared before each measure. Re-measured in
  `initializeContent`, `stabilizeLayout` (resize, zoom, image load) and on `data-sphinx-preview-editing` mutations;
  elements being edited keep the column.
- CSS: Full sets `--sphinx-preview-column-width: 100000px` (not `none`, so the sticky band padding calc stays valid);
  Auto breakout rule centres with negative margin-inline and `width: calc(100% + breakout)`; tables still scroll in
  their own box when larger than the pane.
- firstClearance observes `data-sphinx-preview-width` too.
- CHANGELOG, README (Settings, maxContentWidth), glossary "Width mode".

## Deviations / open points
- Full uses a 100000px column width instead of `none` (sticky band padding math breaks with `none`; the existing
  maxContentWidth=0 path has that quirk already, unchanged).
- Wide breakout uses the figure/p wrapper, not the img itself; images inside list items or admonitions do not break out
  (top-level only, per brief).
- Cell-editor detection relies on `[data-sphinx-preview-editing="true"]` or a textarea inside the element.
