# T34 r1 - Colour picker and colour-code swatch

## Files changed
- src/webview/editActions.ts: `createEditActions(languages, tableTools, isSafeColor)` (third param is
  `isSafeOkfColor`, injected in scrollSync; without it the colour actions refuse). New actions `color`
  (strict, block+cell, popover `color`, 16 swatches) and `colorCode` (`available`/`current`). New
  optional EditAction fields `colors`, `validateColor`, `available`, `current`.
  Span rules: only `<span style="color:#x; background-color:#y">` (exact shape, no other attribute)
  is written; every value passes `isSafeOkfColor` and has no control character; a span is "generated"
  only if its tag matches that shape with safe values (others are never edited, nested instead).
  Caret/exact-content selection updates that span, adds the second property, Remove drops one
  property and unwraps when none is left; partial selection nests; hand-written spans with other
  properties are untouched. Code detection: `#rgb(a)`, `#rrggbb(aa)`, `rgb()/rgba()` at the caret
  (boundaries inclusive, not in a word, not `&#123;`), validated by the same grammar.
- src/webview/editPalette.ts: `buildColor` popover (tabs Text/Background, 16 swatches, hex field with
  live `aria-invalid`, Enter applies, Esc closes, Cmd/Ctrl+Enter done, Remove), `updateAvailability()`
  (shows/hides caret-dependent buttons, colours the swatch via CSSOM), hex field uses `trackFocus`
  (T22 blur relaxation: focus moves inside the frame do not save).
- src/webview/scrollSync.ts: passes `isSafeOkfColor` (declaration moved above `editActions`), calls
  `palette.updateAvailability()` on keyup, mouseup, select, input of the block text box.
- src/preview/previewStyles.ts: styles for the picker, `button[hidden]`, the swatch button.
- test/webview/editActions.test.ts, editPalette.test.ts, scrollSync.test.ts,
  test/rendering/mystFeatures.test.ts, test/visual/capture.py: tests (below).
- CHANGELOG.md (new top bullet under Unreleased; the user's TODO-wrapped link bullet untouched),
  README.md (feature list sentence; the user's edits untouched).

## Table cells
The renderer's span normalizer already runs on table-cell inline content (recursive over all
children), so no renderer change was needed. The new render test covers a picker-written span and
a hand-written one in cells of a pipe table; both render as data attributes.
