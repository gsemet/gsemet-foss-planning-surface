## Behaviour
- Page: `selectionchange` + `mouseup` show `button[data-okf-comment-create]` ("Comment") at the
  selection rect (fixed, CSSOM). Hidden while the mouse drags, while a block editor / frontmatter editor
  is open or blocks are selected (T39), when a selection end is in code, properties, editors, chips,
  included content, or outside mapped blocks. The button only cancels its own mousedown; no other mouse/key
  event is intercepted (Shift+click, Cmd/Ctrl+C untouched; tests). Keyboard: Cmd/Ctrl+Alt+M opens the box
  (`key` or `code` KeyM, because Option changes the character on macOS); the button also has
  `aria-keyshortcuts`. Box: quote (textContent), textarea (maxlength 10000), Save / Cancel, Cmd/Ctrl+Enter
  saves, Escape cancels; typing stays in the box (stopImmediatePropagation).
- Anchor: first block `data-line` .. last block `data-end-line`; a selection ending at offset 0 of the
  next block (triple click) stays in its own block; quote whitespace-collapsed <= 500; prefix/suffix <= 32.
- Reply: the T42 popover gets a reply box (same limits) only in writable previews.
- Host: `previewCommentCreate { anchor, body }`, `previewCommentReply { threadId, body }` validated in the
  registry (anchor limits, body 1-10000) and again in the handler. Read-only (untrusted / no folder) and
  non-file documents are refused with a warning, nothing is written. Author, ids (`t_`/`c_` + 8 hex from
  `crypto.randomBytes(4)`) and time are chosen by the host. An invalid existing sidecar is never overwritten.
  After the write the host re-reads and posts `previewComments`; a watcher event whose text hash equals the
  last handled text is skipped, and a read overtaken by a newer one posts nothing.
- Setting `markdownOkfSchemaStudio.comments.authorName`: string, default `""`, order 50. markdownDescription:
  "The name stored with the review comments you write in the preview. **Empty** (default): your Git
  `user.name` is used, and when Git has none, your operating system user name. **A name**: that name is used
  as it is, up to 100 characters."
- README Settings line: "`comments.authorName` (default empty): the name stored with the review comments you
  write in the preview. Empty uses your Git `user.name`, then your operating system user name."
- CHANGELOG bullet (top of Unreleased): "Review comments: select text in the preview and press the "Comment"
  button that appears next to it (or Cmd/Ctrl+Alt+M) to start a comment thread; open a thread to reply. ..."
  I also reworded the end of the T42 bullet (it said "This first version only shows threads; the file is
  read-only here", now false) to "Documents without such a file behave as before."; likewise the README
  sentence "never writes the file" was replaced.

## Deviations / open points
- Messages carry the usual document version envelope: a comment sent in the short window where the document
  changed but the preview has not re-rendered is dropped silently (same as other registered messages).
- A quote that crosses elements, or spans blocks, is shown as a badge on the first block (T42 matching).
- No UI feedback on a refused save except a VS Code warning message.
- The compose box keeps its draft when the page re-renders (it lives outside the content); an open thread popover
  loses an unsent reply draft when the threads are re-posted.
