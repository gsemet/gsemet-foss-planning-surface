# T09 — Same ~40 px gap above the first element

Backlog: bug-one-line-top-margin-missing · Phase 2 · Size S · Depends on: T08 · Gate: B S T
Commit (draft): `fix(render): keep the same space above the first element of every page`

## Goal

Every preview starts its first element about 40 px below the top, whatever it is: paragraph,
heading, table, properties table, image, admonition, empty document. In edit mode the first
block's frame and insert point only move down when 40 px would put them under the toolbar.

## Decisions

U6. Planner finding: row 1 of the toolbar ends at 50 px, two rows end near 84–96 px (T08), so a
40 px gap overlaps the toolbar whenever the column reaches under it (narrow panes, Full width).
Fix: fixed 40 px gap + runtime clearance only when an overlap is measured.

## Changes

1. CSS: `#sphinx-myst-preview-content` top padding 40 px; first child `margin-top: 0`
   (headings, tables, properties table, figures, admonitions, the empty-document hint).
2. Edit mode: replace the fixed 56 px/24 px `--first` offsets with
   `var(--sphinx-preview-first-clearance, 0px)` added to 40 px. Runtime computes the variable =
   `max(0, toolbarBottom + 8 − contentTop − 40)` only when the toolbar and the column overlap
   horizontally; recompute on resize, zoom, width-mode change, toolbar row changes, and in
   `initializeContent`. Apply it also when a properties table comes first.
3. CHANGELOG bullet.
