# T36 — Move a block with ↑/↓ on the insert bar

Backlog: move-block-up-down · Phase 5 · Size M · Depends on: T05, T03 · Gate: B T S
Commit (draft): `feat(editor): move a block up or down from the insert bar`

## Goal

In edit mode the "+" insert bar under each body block also shows ↑ and ↓ buttons that move the
block above the bar past its neighbour. One move = one undo step. The moved block stays under the
pointer so repeated clicks keep moving it.

## Decisions

D1 (refuse included blocks), D2 (whole top-level block; a list moves as one), D3 (refuse when
non-blank unmapped text sits between the two blocks), D4 (one WorkspaceEdit; disabled while a
block editor is open), R5, R11, R12.

## Changes

1. Pure `src/mapping/blockMove.ts`: `planBlockMove(text, first, second)` with 1-based inclusive
   ranges → `{ start, end, text, newStartLine }` or `{ refused: reason }`. Swap contents, keep the
   separator and the final line break where they are; keep each block's own EOLs; insert a blank
   line when the swap would glue a paragraph to the next block; refuse overlap, unordered ranges,
   non-blank separator, and anything inside the frontmatter.
2. Registered message `previewBlockMove { line, endLine, neighbourLine, neighbourEndLine,
   direction, pinViewportTop }`. Host: refuse read-only, active block edit, stale version,
   ranges that overlap, are unordered, out of bounds or inside the frontmatter, and ranges whose
   first line opens an `{include}` directive (after T05 an included group maps to its directive
   lines; D1 says refuse); apply one WorkspaceEdit; `storePendingPin` with `newStartLine` and the viewport top; status message on
   refusal (`previewBlockMoveResult { ok, reason? }`).
3. Page: two buttons in each body insert point (not after properties, not on the start point),
   `aria-label` "Move the block above up/down", disabled at the ends and for blocks with
   `data-sphinx-preview-included`; hidden while an editor is open; click stops propagation.
4. CHANGELOG bullet.
