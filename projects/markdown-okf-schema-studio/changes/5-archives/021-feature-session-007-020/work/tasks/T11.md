# T11 — Back / Next per preview panel

Backlog: block-edition-palette · Phase 2 · Size M · Depends on: T08 · Gate: B T S
Commit (draft): `feat(vscode): go back and forward through followed links in the preview`

## Goal

Back and Next buttons (start of toolbar row 2) return to the place before a followed link and
forward again: links to other documents and in-page anchors. External links are not recorded.
One history per preview panel; buttons are disabled when there is nowhere to go.

## Decisions

U16, O5 (a locked preview records only in-page anchor jumps). Host-owned history.

## Changes

1. Pure `src/state/navigationHistory.ts`: `{ entries: Entry[]; index }`, `Entry = { uri: string;
   line: number }`; `push` drops forward entries, cap 50, ignores a duplicate of the current
   entry; `back()`/`forward()` return the target or undefined; `canBack`/`canForward`.
2. Host: `WeakMap<vscode.WebviewPanel, NavigationHistory>`. In `handlePreviewLink`, after the
   target is resolved and before navigating, push the current place then the target (anchor and
   local-file kinds; not blocked/failed/external). Locked preview: anchors only.
3. Registered message `previewHistoryGo` `{ direction: "back"|"forward" }`: same document →
   post `navigateAnchor`-like scroll to the stored line; other document → open it as
   `handlePreviewLink` does, with a `navigatingFromHistory` flag so the switch does not push.
   Refuse while a block editor is open (status message), like other navigations.
4. Host→page `previewHistoryState { canBack, canForward }` after every change and on `previewReady`.
5. Toolbar row 2 buttons `data-sphinx-preview-back` / `-next` (tooltips "Back", "Next"),
   disabled until the state says otherwise.
6. CHANGELOG bullet.
