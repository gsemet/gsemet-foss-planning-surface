# T42 — Show comment threads from <name>.comments.json

Backlog: local-comment-mode · Phase 6 · Size M · Depends on: T03 · Gate: B T S
Commit (draft): `feat(vscode): show review comments stored next to the document`

## Goal

When `notes.comments.json` exists next to `notes.md`, the preview highlights each thread's quoted
text (or badges its block when the quote is not found) in preview and edit mode; clicking a
highlight opens a popover with the thread (author, date, plain-text bodies, resolved state).
Read-only in this task.

## Decisions

D25 (v1 scope, plain text, no native Comments API), O8, O10.

Sidecar format (version 1), stable JSON (2-space indent, trailing newline):
`{ "version": 1, "document": "notes.md", "threads": [ { "id", "anchor": { "line", "endLine",
"quote", "prefix", "suffix" }, "resolved": false, "createdAt", "comments": [ { "id", "author",
"createdAt", "body" } ] } ] }`.

## Changes

1. `src/comments/commentModel.ts` (pure): types, `parseSidecar(text)` with strict validation
   (≤ 2 MB, ≤ 1000 threads, ≤ 200 comments/thread, strings ≤ 10 000 chars, ISO dates), returns
   `{ threads, errors }`; `serializeSidecar(model)` stable; `sidecarNameFor("notes.md")`.
2. Host: read via `workspace.fs` on preview open/switch; watcher on the sidecar; post
   `previewComments { documentId, documentVersion, requestId, threads }` (anchors as stored) after
   renders and on `previewReady`; invalid file → one status warning, no threads.
3. Page `src/webview/commentThreads.ts` factory: for each thread find the mapped block covering
   `line`; wrap the first occurrence of `quote` in its text nodes with
   `mark[data-okf-comment-thread]` (never across element boundaries; skip code/mermaid/properties);
   else add a badge on the block; idempotent re-apply in `initializeContent`; popover built with
   `textContent` only; resolved threads dimmed. Not applied inside an open editor (O10).
4. README section "Review comments"; CHANGELOG bullet.
