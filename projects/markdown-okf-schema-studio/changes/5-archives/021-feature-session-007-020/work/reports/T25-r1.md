## What was done

- `createEditActions(languages, tableTools?)`: the table tools are injected (the factory is stringified);
  scrollSync passes `tableTools`. Without them `htmlTable` only inserts.
- `alert` (gfm, group `github`, `popoverAtCaret: true`): inserts `> [!NOTE]` + quoted touched lines
  (collapsed caret stays on its text; selection keeps the quoted lines selected). With the caret
  in an existing alert (head = first line of the quoted run) and an `arg` it changes only the type
  word; no arg or same type returns no edit. Unknown type refused.
- Palette: for `popoverAtCaret` the click first runs the action (guarded by `holding`, so the input
  event does not close the list), then opens the type list at the caret (`getCaretRect` dep, bar
  coordinates, `data-edit-popover-at="caret"`). Choosing runs `apply` again with the type, reading the
  live selection. Escape closes, keeps NOTE and always refocuses the text box. Option buttons now
  track focus (Escape gives it back, leaving the frame saves once). Arrow Up/Down light a type, Enter
  picks, Left/Right/Home/End/Page keys and typing/mousedown close the list (so a stale list never
  inserts a second alert).
- `checkbox`: plain line gets `- [ ] `, list item gets `[ ] ` after the marker, all-checkbox lines
  lose the box (item stays), blank lines skipped, single blank line gets the box.
- `htmlTable`: `toHtmlTable(model)` in markdownTable.ts (escape `&<>`, `\|` becomes `|`, align
  attribute, thead/tbody). Caret in a pipe table (found from header through last row of the run)
  replaces those lines; otherwise a new 2x2 table is inserted like the Table action (shared
  `insertBlockAfterSelection`, Table output unchanged).
- Strict mode shows none of them (`modes: ["gfm"]`, additive filter).
- Render contract tests: inserted alert -> admonition of chosen type, checkboxes -> `myst-checkbox`
  inputs, converted and new HTML tables -> table with same text (all render today, D13 superseded).

## Deviations / open points

- No shortcuts for the three actions (not asked; avoids key clashes).
- The alert dropdown is also keyboard-drivable (arrows/Enter), an addition.
- Checkbox "toggle off" leaves `- text`, per the brief; a plain line is therefore not restored
  exactly by two toggles (list items are).
- Alert titles after the marker (`> [!NOTE] Title`) are not recognized as the head by the type change.
