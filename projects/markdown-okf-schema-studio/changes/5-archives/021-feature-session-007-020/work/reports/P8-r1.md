## Follow-on product changes the taller toolbar forced (found by the trusted suite)
The toolbar bottom is now 114 px (was ~80). Real-input scenarios exposed two geometry assumptions:
1. RI-T18 (table toolbar): "selected cell moved 28 px". The table bar was scrolled into view because its
   whole box (wide, empty right part) counted as covered. `toolbarUsableTop(bar, content)` now counts only
   the visible items of the bar that share columns with the toolbar; an empty bar waits until filled, and
   `applyAnchor()` runs once after the table bar is populated.
2. RI-T32 (Save keeps block in place): "list moved 40.1 -> 67.6". The stuck palette (below the taller
   toolbar) covered the first text line and the caret reveal scrolled the page by 27.5 px, never undone.
   `keepTextInPlaceBelowPalette` now takes the palette's natural place (its host top) instead of its stuck
   rectangle, and scrolls up (negative `paletteShift`) when there is not enough room, as long as the frame
   stays in the viewport; close and pin use the signed shift. Drift is 0 again.
3. RI-T43: the pending overlay (fixed 96 px) sat under the taller toolbar: 128 px, 62 px when collapsed.
