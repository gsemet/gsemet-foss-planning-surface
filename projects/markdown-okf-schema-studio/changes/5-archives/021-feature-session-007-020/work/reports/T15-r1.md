## What was done
- `installChipToggle(document, vscode, context, onLayoutChange)` (injected with `.toString()`):
  delegated click and Enter/Space on `.okf-chip` whose parent `.okf-comment` has a body; toggles
  `aria-expanded` and the body `hidden`; a chip without a body (TODO word) is ignored. Key is
  "<data-line of the comment or its block>:<nth comment of that line>", kept in `vscode.setState`
  as `expandedChips` (also added to `stateSnapshot`, which rebuilds the state from scratch).
  `apply()` is called from `initializeContent` (reload and content patch); stale keys are pruned.
  `onLayoutChange` = `keepReadingLine`, so the reading line holds.
- Setting `markdownOkfSchemaStudio.preview.showComments` (boolean, default true, order 21,
  markdownDescription with On/Off effects). Reader field `showComments`. Page context gets
  `showComments`; the page sets `<html data-okf-show-comments>`. Live: host posts
  `previewShowComments` on `previewReady` and on configuration change (no re-render); not in
  `runtimeContextKey`. No webview-to-host message, so the registry is untouched.
- Click and keydown guards in scrollSync now cover every `.okf-chip` (inline too), so a chip click
  opens no block editor and does not reveal.
- CSS (stylesheet only): open body is an admonition-like box (accent bar, tinted panel, title
  "Comment" or "TODO" via `::before`, `pre-wrap`); `html[data-okf-show-comments="false"]` hides
  `.okf-comment[data-okf-comment-kind="comment"]`; TODO chips stay. Text stays a text node, so
  headings keep excluding `.okf-comment` (TOC and sticky labels unaffected).
- README Settings bullet, CHANGELOG bullet. No glossary change (no term to add or drop).
