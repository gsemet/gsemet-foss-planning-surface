## Behaviour
- `anchoring.ts` (pure): `shiftThreadLines` (reuses `shiftLineForEdits`, line and endLine; `toLineChanges` for contentChanges,
  all ranges in pre-event coordinates so multi-cursor/undo order is irrelevant), `reanchor`, `reanchorThreads`.
  Search runs on the plain text of the document (block markers, link targets, emphasis, pipes, tags removed, whitespace
  collapsed, code fences and front matter skipped). Rules: quote still inside old lines -> anchored; else exact candidates
  (max 200): narrowed by prefix/suffix, then only candidates within +-50 lines, nearest wins only if strictly nearer than the
  next; unique candidate anywhere only if quote >= 12 chars. No exact match: fuzzy (<= 20 % edit distance) only around
  occurrences (<= 20) of the quote's rarest present word, global budget of 20M DP cells, document <= 2M chars; same decision
  rules. Otherwise orphaned, old lines kept.
- Host: `preview.commentView` = live threads (from sidecar hash) re-anchored on open/new sidecar text, shifted in memory on
  change events (clean document change = reload -> re-anchor). Posted threads carry `orphaned`. After our own comment write
  the in-memory lines are the search start. `onDidSaveTextDocument` -> `persistCommentAnchors`: through the T43 queue, only
  writes when a non-orphan anchor differs; never creates a file (empty/no sidecar -> nothing); invalid sidecar silent
  (preview already warns); sidecar dirty in an editor -> one warning, no write. Read-only previews never write.
- Page: `orphaned: true` -> Orphaned box; `orphaned: false` with no block at the line -> no quote search by the page (trusts the
  host); no field -> T44 rules.
- Rename: `onDidRenameFiles` moves `<old>.comments.json` to `<new>.comments.json` and sets `document`; skipped for folders;
  refused with a warning when the target exists, the old file is invalid, belongs to another document name or is dirty in an
  editor. `overwrite:false`.
