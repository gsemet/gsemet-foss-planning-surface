## What
- Shift+click (edit mode, no Ctrl/Cmd/Alt) selects body blocks from the anchor (last clicked/opened block, kept
  as a source line) to the clicked one; no editor opens. Later Shift+clicks move the free end, anchor stays.
- Open editor: saved first (`postBlockEditSave(true)`); selection applied after the patch
  (`pendingBlockSelection`, kept across the patch, dropped on error/plain click/Escape/leaving edit mode).
  Editor without changes or still loading: closed (cancel) and selection is immediate.
- Shift+Up/Down on a focused block (or an insert-bar button of it) or on an existing selection extends/shrinks;
  the free-end block takes focus (tabindex -1, scrollIntoView nearest) so repeated presses and screen readers
  follow. Ignored in inputs/textarea/editor/property table; Alt, Ctrl, Cmd + Shift never match (no collision
  with T37 Alt+Arrow, whose handler already ignores Shift). Escape or a plain click clears; cleared on content
  patch, leaving edit mode, opening an editor.
- Attribute `data-sphinx-preview-block-selected="true"` (on the `pre` for code blocks, like the hover);
  CSS 2px focusBorder outline; off-screen live region `.sphinx-preview-selection-status`
  (role=status, aria-live=polite, "N block(s) selected") created lazily by the page script, no inline style.
- Properties table and included blocks excluded (D1); an include ends the range.
- Native selection: only Shift+mousedown on a body block is cancelled (edit mode) so the browser does not
  stretch a text range under the block selection; plain mousedown/drag and everything in preview mode untouched.
- Small refactor: Alt+Arrow block lookup extracted to `blockOfTarget()` (shared, behaviour unchanged).
- T41 hook: `blockSelection.range()` gives `{line, endLine}`; selection survives until a patch.
