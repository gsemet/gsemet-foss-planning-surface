# T33 r1 — restricted `<span style>` colours

## Files
- NEW src/webview/spanColors.ts: `isSafeOkfColor` (strict grammar) and `applySpanColors(document, isSafe)`,
  both self-contained, injected with `.toString()`.
- src/security/html-sanitizer.ts: on `span`, `style` is parsed; only `color` / `background-color` with a
  valid value become `data-okf-color` / `data-okf-background`; `style` is dropped; the existing
  diagnostic fires only when something was dropped. `data-okf-color/-background` are re-validated (span
  only, valid value) or removed with the diagnostic. Other elements keep the old removal.

  `applySpanColors(document, isSafeOkfColor)` (re-validates, then `style.setProperty`).
- src/render/mystRenderer.ts: inline raw `<span style="…">…</span>` was dropped entirely by the renderer
  (only `<kbd>`/`<details>` survived), so `normalizeRawDetailsAndKbd` now keeps a matched span (nested
  spans counted) as a span element carrying `style`, for the sanitizer to filter. Needed for the feature to work.

- Tests: test/webview/spanColors.test.ts (new), test/security/html-policy.test.ts,

## Grammar
`#rgb #rgba #rrggbb #rrggbbaa`; comma-separated `rgb()`/`rgba()`, channels 0-255 or 0-100%, alpha 0-1 or
0-100%, at most 3 decimals. No named colours, space syntax, hsl, comments, `!important`, var/url/expression.
Validated in sanitizer and runtime with the same function.
