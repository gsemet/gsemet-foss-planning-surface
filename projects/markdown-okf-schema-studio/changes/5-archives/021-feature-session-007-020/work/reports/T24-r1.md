## Behaviour
- Table: arg `"<rows>x<cols>"` (1-9 each, rows includes the header row, so 3x4 = header, `---`
  row, 2 empty rows). Output uses the serializer's cell style (`| a | b |`, empty cell `|  |`).
  Inserted after the selection (selection kept), blank lines added only as needed, the first
  header cell text "Column 1" is selected (typing replaces it). Invalid args return no edit.
- Grid: hover lights top-left to pointer and shows "3 × 4"; click inserts; arrows (from the text box)
  move the highlight (first arrow = 1×1), Enter inserts, Enter with nothing highlighted does nothing.
- Emoji: filter matches words of the English name; Enter inserts first match; ArrowDown goes to the
  buttons, arrows move, ArrowUp from the first row returns to the filter; Escape closes and focuses
  the text box; Shift+click keeps it open; plain click closes. Cmd/Ctrl+Enter in the filter = done.
- Lessons applied: the edit reads the live value/selection at click time (no captured selection;
  test "never a stale one"). Closing a popover that held focus returns focus to the text box and
  ignores the blur caused by its own removal (`closing`), so nothing saves and the editor is never
  stuck. Filter/buttons blur with a target outside the frame calls `onLeave` (one final save);
  moves inside the frame do not.
