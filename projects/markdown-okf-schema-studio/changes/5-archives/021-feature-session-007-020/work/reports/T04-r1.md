## What was done
- `installCodeCopy(document, window, post)` injected via `.toString()` after `installLinkNavigation`;
  `post(text)` in scrollSync adds the live ids and posts `previewCopyText`.
- Fixed-position 26 px button, 6 px inside the hovered pre's top right; hidden under the sticky
  band / when < 30 px visible / over the toolbar (moved below it); skipped for blocks being edited,
  inside a block editor, or inside Mermaid/PlantUML figures; repositioned on scroll/resize, hidden
  when scrolling stops with the pointer elsewhere; `codeCopy.hide()` called in the content patch.
- Text is `pre code` textContent (else pre text): filename label and line numbers are not in it.
- mousedown preventDefault, click stopPropagation (so the mapped-block / cell-commit click handler
  never sees it); check icon + `aria-label="Copied"` for 1500 ms.
- `previewCopyText` registered (text string <= 1_000_000) with host handler
  `vscode.env.clipboard.writeText` (no readOnly/trust refusal: it edits nothing).
- CSS (editorWidget background/border, icon foreground, z-index 1050), CHANGELOG bullet.

## Deviations
- The button is created lazily on the first hover, not at install: an eager element broke 7 existing
  scrollSync harness tests (pendingTimerCount, innerHTML/createdElements assertions) and the T33
  startup-sequence snapshot. No existing assertion was changed.
- A document click inside the hovered block hides the button until the next pointer move (so it
  cannot stay over a block editor that the click opened). No timers are used for this.
- Visual scenarios use height 900 (an identical-PNG guard flagged code-copy-button-dark vs
  code-dark-top, the final capture does not keep the hover).
