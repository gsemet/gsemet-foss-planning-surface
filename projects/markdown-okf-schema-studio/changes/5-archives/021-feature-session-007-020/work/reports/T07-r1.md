## What was done / which of the three cases failed before
1. Raw `<img>`: FAILED before. The HTML writer dropped the node entirely (nothing rendered, so no
   block, no click, no "+"). Now a top-level `html` node holding only `<img src=...>` (optionally in
   `<p>`) becomes a positioned paragraph with an mdast image (src, alt, title); the sanitizer still
   rewrites `src` (verified: `src="img.png"` relative, as for `![]()`).
2. Linked image: FAILED before in the integration run. The click opened the editor but the link
   navigation also fired (VS Code "open external website" dialog refused in tests = unhandled
   rejection). Now a plain click on an `img` inside an `a` in a mapped block stops navigation and
   opens the editor; Cmd/Ctrl+click is untouched (still follows the link); outside edit mode the
   listener returns immediately. editHoverTarget needed no change (the mapped element is the
   paragraph, not inside the `a`).
3. ArrowUp into properties: FAILED before (unit test): the editor closed. `adjacentMappedBlock` now
   skips properties blocks; no neighbour means native caret behaviour, no save, editor stays.
Plain `![]()` and `{image}` unchanged (existing tests green; scenario covers `![a]()`).
