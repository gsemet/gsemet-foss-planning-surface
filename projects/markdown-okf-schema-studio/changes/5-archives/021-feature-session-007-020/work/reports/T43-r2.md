## Fixes
1. Version check dropped for `previewCommentCreate` / `previewCommentReply` (`COMMENT_MESSAGE_TYPES` in
   `src/extension.ts`, applied in `handlePreviewSyncMessage`): the current stage version is substituted, so
   disposed / unknown preview, documentId and requestId are still checked. Integration test sends a create
   with `documentVersion - 1` and asserts it is written and answered ok; a wrong documentId is still dropped.
2. Host answers every create/reply with `previewCommentResult { ok, reason?, kind, threadId? }` (current
   context ids; handled in `scrollSync.ts` next to `previewComments`). Covers read-only, non-file document,
   invalid sidecar, too large, unknown thread / full, write error (exceptions caught), empty/too long body.
   The VS Code warning toast stays as well. Page: `commentCompose` keeps the box and text until ok:true
   (Save disabled while waiting, no double send); failure shows the reason in `div[role=alert]` via
   `textContent`; 15 s safety timeout re-enables Save with "No answer from the editor. Your text is kept"; a
   late ok still closes the box. `commentThreads` reply box does the same (text emptied only on ok and only if
   unchanged since sent; per-thread matching by `threadId`). Test hook: `comments.result` on the preview.
3. Reply draft (and pending/error state) survives threads being posted again while the thread exists.
4. Sidecar open in an editor with unsaved changes: write refused ("... has unsaved changes in an editor; save
   or close it first"), file on disk untouched, page told. Integration test edits the open sidecar, sends a
   create, asserts refusal and unchanged file, then reverts and closes.
