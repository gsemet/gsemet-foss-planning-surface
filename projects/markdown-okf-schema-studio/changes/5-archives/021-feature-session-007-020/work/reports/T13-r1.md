## What was done
- tocColumn: twisty button per parent entry (aria-expanded, native Enter/Space); fold keys
  (level|text|occurrence) kept in memory and in webview state `tocCollapsed`, so they survive
  rebuilds. Hidden entries get `hidden`. Current entry = last heading whose cached top is at or
  above scrollY + reading offset; `aria-current="location"` plus `data-sphinx-preview-toc-current`
  on the li; inside a folded parent the folded ancestor is highlighted. The nav scrolls itself
  (nav.scrollTop) to keep the entry visible; the page is not scrolled.
- Heading tops are cached per rebuild; `track()` (called from postScroll, i.e. one rAF per scroll
  frame) does no heading layout reads. `remeasure()` re-reads tops and is called from
  stabilizeLayout's rAF, which already runs after zoom (keepReadingLine), width mode, TOC toggle,
  resize, ResizeObserver and image loads; content patches go through refresh -> rebuild.
- Review item 1: stateSnapshot now adds `viewToc: tocColumn.open()` and `tocCollapsed`.
- Review item 2: the click handler re-collects the live headings and resolves the target by key at
  click time (falls back to the stored element), so a click before the post-patch rebuild frame
  scrolls to the live heading.
- CSS: flex rows, twisty glyphs via ::before, current highlight = 14 % currentColor tint, inset
  3px focus-colour bar, bold. No inline style= markup; no new webview->host message.
- installTocColumn got an optional 7th parameter `readingLine`; scrollSync passes
  `() => readingOffsetValue`.
