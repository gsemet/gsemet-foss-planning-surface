## What was done
Per brief. Zoom 70-200 in 10 steps sets `--sphinx-preview-zoom` and `data-sphinx-preview-zoom` on the root, disables the buttons at the limits, tooltips show the target percentage ("Zoom out (90 %)"), posts `previewViewPreferenceChanged`, mirrors in `vscode.setState` as `viewZoom` (saved state wins over `initialViewPreferences`), and calls the existing stabilizeLayout so the anchored source line stays at the reading line (recapturing the anchor first if none exists). No `runtimeContextKey` change. The handler writes only workspaceState (no document edit), so it is allowed in read-only previews; the view row is always rendered.

## Deviations / findings
- Taller toolbar (bottom ~82px) collided with the Description toggle of the properties table (previewEditing click intercepted) and with the first block editor. Fix: `[data-okf-properties]` margin-top 32px, first-block editor margin 96px. I first tried `padding-top: 32px` on `#sphinx-myst-preview-content`; that made RI-T31 case A fail (preview jumped from 1200 to 0 after typing in the editor). Reverted. This suggests a latent anchoring sensitivity to content-top offset when the document has no frontmatter, not investigated.
- The visual zoom check waits 150 ms after each click: a scroll issued in the same frame as a zoom click loses to the pending applyAnchor rAF (the scroll event handler runs after it). Real users are unaffected, but a scripted scroll right after a click is.
- "Back/Next at start of row 2" is T11, not done. Light/dark/cream coverage comes from the existing scenarios the check runs in.
