## Behaviour
- Document keydown (edit mode, no editor open): Alt+ArrowUp/Down, no Ctrl/Meta/Shift, target not an
  input/textarea/select/editor/properties, and either inside a top-level mapped body block or inside a "+" bar
  (its block) -> same `previewBlockMove` as the buttons. After the host's ok result (with `line`) and the render of
  the new version, the block gets tabindex -1 and focus (`preventScroll`), so Alt+Down can repeat.
- Text box: Cmd+Alt (macOS) / Ctrl+Alt (elsewhere) + ArrowUp/Down, `key` first then `code` when key is absent or
  "Unidentified". Plain Alt/Option+arrow and Ctrl+Alt on macOS are not touched. Changed text: final save, wait for
  the render (state `thenMove` in the webview state, like block navigation), then the move, then the editor
  reopens on the moved block (found by the returned line) with the caret offset restored. Unchanged text: the editor
  closes with a cancel (so the host drops the edit lock) and the move is sent at once. Handled chords are
  preventDefault + stopPropagation. Only for plain block text boxes (not table cells, insert editors).
- No double move (review focus): `blockMoveInFlight` is set when the move is posted and cleared only when the
  result is a refusal, when the new version's render has been resumed, or after a 5 s safety timer. While set,
  further Alt+Arrow keydowns (key repeat included) are consumed and ignored. In the text box, repeat is ignored
  and `edit.finishing` blocks a second chord during the save. A refusal clears the flight and restores the
  focus/editor on the original block.
- Mouse click on the arrow buttons is unchanged (not gated).

## CHANGELOG bullet (merged into T36's bullet)
"Alt+Up and Alt+Down move the focused block (or the block whose bar button has the focus); in the text box,
Cmd+Alt (Ctrl+Alt elsewhere) + Up or Down saves the edit, moves the block and reopens the editor with the caret
where it was. Option/Alt+arrow alone keeps word navigation."

## Manual check §9.2 (for the user)
1. Edit mode, three paragraphs. Tab to (or click then Escape and Tab to) a "+" bar arrow button, press Alt+Down:
   the block above moves down one place and keeps focus; hold Alt+Down: it moves one step per render, never
   twice for the same render, and stops at the last block. Alt+Up reverses. Cmd+Z undoes one move.
2. Open a block, type a character, press Cmd+Alt+Down (Ctrl+Alt+Down on Windows/Linux): the edit is saved, the
   block moves below its neighbour and the editor reopens on it with the caret at the same offset. Same with
   Cmd/Ctrl+Alt+Up. With no change typed it also works.
3. In the text box, Option+Arrow (macOS) still moves by word; Ctrl+Option+Arrow does nothing special.
4. Try an `{include}` block or a comment between blocks: the move is refused with the message, and the focus or
   editor comes back on the block.
