## Behaviour
- Page: each body insert point gets two buttons after "+": aria-labels "Move the block above up/down", disabled at the ends and when the block or the neighbour carries `data-sphinx-preview-included`. Not on the properties point or "Start writing". Hidden by CSS and ignored by the click handler while a block editor is open. Click stops propagation. The message carries the moved block's viewport top.
- Host: refuses read-only, active block edit, stale version (`currentPreviewDocument`), then `planBlockMove` (unordered, overlapping, out of bounds, frontmatter, blank block edges, non-blank separator), then any block whose first line opens an `{include}` directive. One edit (visible editor `edit` with undo stops, else WorkspaceEdit) = one undo step. `storePendingPin` uses the post-edit `document.version`, the new first line of the moved block (from the plan, not from the page) and the page viewport top. Result message `previewBlockMoveResult { ok, reason? }`; the page shows a refusal reason next to the bar for 6 s.
- Planner: swaps contents, keeps separator and final line break position, keeps each block's own EOLs (only the two boundary EOLs are exchanged). Adds a blank line where a swap would glue a block to a neighbour (empty separator, or a block that was glued to the line before/after the region). The replaced range is only from the first block's first line to the second block's last line; no byte outside changes.
