## Behaviour
- Copy: host writes exact span text (document EOLs, no final EOL) to the clipboard. Cut: copy, then one
  edit deleting the span plus one separator. Paste: `readText`, blank ends trimmed, `planInsertion` +
  `insertionText`, one edit. Pin: cut holds the next block at the cut position, paste holds the anchor block.
- Separators: middle/first block removes the following blanks; if the block above touched the span and a
  blank followed, that blank stays (no gluing); last block removes the blanks before it and keeps the
  previous line's EOL (a file without final newline stays without); only block empties the body.
  Never leaves 3 blank lines (asserted in unit and integration tests). Paste adds exactly one blank on
  each side, also before a block that follows without a blank line.
- Refused with a message (page announcer): read-only, open block editor, stale version, frontmatter,
  blank/out-of-range lines, range with an `{include}` directive line (D1), paste after an include line.
- Page: edit mode only, not in textarea/input/select/editor/property table; Cmd on macOS, Ctrl elsewhere,
  no Shift/Alt; `key` before `code`; copy/cut need a selection, paste needs a selection or a focused "+" bar;
  one request in flight; selection cleared on cut/paste success; copy shows "Copied as Markdown".

## Manual check 9.4 (user)
1. Edit mode, Shift+click two blocks, Cmd/Ctrl+C, paste in another app: exact Markdown of those lines.
2. Select a middle block, Cmd/Ctrl+X: block gone, exactly one blank line between neighbours; Cmd/Ctrl+Z
   restores in one step. Cut the last block: no trailing blank lines left.
3. Focus a "+" bar (Tab) or select blocks, Cmd/Ctrl+V: text inserted as new blocks after, one undo step.
4. In the block text box, a field, or the properties table, the keys stay native.
5. Selecting a block from an `{include}` or the frontmatter: refused / not selectable; screen stays put.
