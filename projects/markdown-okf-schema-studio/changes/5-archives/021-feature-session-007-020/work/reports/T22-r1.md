## What was done
- editActions: new `link` action (strict; block+cell; Cmd/Ctrl+K on `key` "k", code `KeyK` only as a
  fallback for non-Latin layouts; no shift), new `EditAction.panel`, and `linkDraft` / `linkEdit` on
  the registry. `linkDraft` reads back an existing `[a](b)` around the selection/caret (not images),
  fills the URL when the selection is a URL (http(s), mailto:, www.), otherwise the text. `linkEdit`
  writes `[text](url)`: empty text uses the URL, URL with spaces/unbalanced parens gets `<...>`,
  caret after the link, or inside `()` when the URL is empty (O13).
- linkPanel.ts (self-contained, injected with `.toString()`): `role="dialog"`, `aria-label="Insert
  link"`, labelled Text and URL inputs, Insert and Cancel. Enter in a field inserts, Escape cancels
  (stopPropagation, so the editor does not see it), Tab wraps Text -> URL -> Insert -> Cancel -> Text
  (Shift+Tab reverse). Mousedown on padding/buttons is cancelled (so focus does not blur), on a field not.
  Blur to something outside the frame calls `onLeave`; blur is ignored once the panel closed itself.
- scrollSync.ts: textarea `blur` no longer saves when `relatedTarget` is inside the frame.
  `openLinkPanel` (shortcut in `paletteShortcut`, and palette `openPanel`) remembers the selection,
  inserts the panel right under the palette, focuses the first empty field. Submit/cancel: destroy panel,
  refocus textarea, restore selection, then `applyTextEdit` (one native step, autosave via input).
  Focus leaving the frame from the panel runs the normal final save (`saveBlockEdit`). `closeBlockEdit`
  destroys the panel. Text stays in place: new helper `keepTextInPlace` (the T21 shift logic extracted,
  same behaviour) is used for the palette and the panel; the panel's shift is added to `paletteShift`
  and given back when the panel closes, so every `closeBlockEdit` path still restores the scroll.
- editPalette.ts: Link button (icon `link`, tooltip "Link (Ctrl+K)" / "Link (Cmd+K)"), `openPanel` dep.
- CSS only in the stylesheet (`.sphinx-preview-link-panel*`); no inline style; page shell unchanged.
- No new webview->host message.
