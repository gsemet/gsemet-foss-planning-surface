## What was done
- Pure `NavigationHistory` (push drops forward entries, cap 50, duplicate-of-current ignored,
  back/forward/canBack/canForward, `depart` updates the current entry's line or pushes the place).
- Host: `WeakMap<WebviewPanel, NavigationHistory>` (survives the ActivePreview recreation of
  switchPreviewDocument, freed with the panel). `handlePreviewLink` records the place being left
  plus the target for anchors (always) and local eligible documents (not for a locked preview,
  i.e. `!followsActiveEditor`); blocked/external/failed are not recorded.
- Registered message `previewHistoryGo {direction}`; handler walks the history: same document ->
  `sourceScroll` to the stored line; other document -> `vscode.open` at the line (shared
  `openLocalDocument` helper, extracted from handlePreviewLink). Refused with a status-bar message
  while a block editor is open.
- Host -> page `previewHistoryState {canBack, canForward}` after every change and on `previewReady`.
- Toolbar row 2 starts with Back / Next buttons (`data-sphinx-preview-back/-next`, disabled,
  tooltips in the markup); page module `installHistoryControls` injected via `.toString()`.
- CHANGELOG bullet, glossary "Navigation history".

## Deviations / notes
- `navigatingFromHistory` flag not added: the document switch (followActiveEditor /
  switchPreviewDocument) never pushes; only `handlePreviewLink` records, so no loop is possible.
- Current place = preview.anchor (same document) else lastSourceScrollLine else state.sourceLine;
  when the page never reported one the entry keeps its own line.
- Test hook `history` (entries, index, posted state) added to getActivePreviewForTests.
- External-link non-recording is tested with a stubbed `vscode.env.openExternal`.
