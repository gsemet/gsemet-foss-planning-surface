# P4 r1: edit palette on top of the edit box, sticky

## Design
A host element `div.sphinx-preview-block-editor-host` now wraps `[palette, frame]` (created when the
source arrives, in `placePaletteAboveFrame`). The palette is `position: sticky` (pure CSS) with
`inset-block-start: calc(max(--sphinx-preview-reading-offset, --sphinx-preview-toolbar-bottom) + 4px)`,
`z-index: 3`. The host bounds the sticky range: the palette follows a tall box, never goes below its
end, and leaves with it. `--sphinx-preview-toolbar-bottom` is new (published by
`installFirstClearance`, same horizontal-overlap test as the first-element clearance: toolbar bottom
+ 8 px while it overlaps the column, 0 otherwise); the band height is the existing reading offset.
The frame keeps its border, padding and background (existing frame tests untouched).
No layout jump: the frame stays the scroll anchor, so the text keeps its screen position (scroll
shift = palette height, limited so the bar is not under band/toolbar, none at scrollY 0), same
contract as T21; `paletteShift` still scrolls back on close. `pinFields` fallback uses the host.

## Deviations / open points
- Sticky range is bounded by the host; when the caret sits under the stuck bar (first lines of a
  tall box) the browser does not scroll it clear; not handled.
- `--sphinx-preview-toolbar-bottom` is measured against the column, not the palette; on very
  narrow overlaps the bar may sit a little lower than strictly needed.
- README unchanged ("above the text box" is still true).

## CHANGELOG bullet
- The edit palette now sits on top of the edit box, outside its border, instead of inside it. It
  sticks to the top of the viewport while you scroll a tall edit box (below the sticky heading
  band and the floating toolbar), and goes away with the box. The text stays where it was.
