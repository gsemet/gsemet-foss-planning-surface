## Findings

### 1. HIGH - Cancel / Done-without-change makes the page jump by the bar height
src/webview/scrollSync.ts `closeBlockEdit` (~line 927-976) and `postBlockEditSave` (~2387, the
`final && editedText === originalText && !hasAutosavedChange` branch that calls `closeBlockEdit()`).
On open, the page is scrolled by `paletteShift` so the text stays still. On close, the frame (bar
included) is removed, `editAnchor` is cleared, and nothing scrolls back. `overflow-anchor: none` is set,
so the browser does not help either. Measured on edit-palette-light (scrollY 629 -> 673 on open, text
moved 7 px = frame padding): after Escape the paragraph went from top 466.8 to 422.8, a 44 px jump
with scrollY unchanged at 673. The task says "reading-line stability on open, close, cancel, save" and
the review focus includes it. Saves with changes are covered by the pin (`paletteShift` in
`blockPinFields`), cancel-after-autosave goes through a re-render and is likewise unpinned.
Fix: in `closeBlockEdit`, before `edit.element.remove()`, if `edit.paletteShift > 0` scroll back by it
(`programmaticScroll(Math.max(0, window.scrollY - edit.paletteShift))`) after the frame is removed
(measure the rendered element top before/after removal and correct by the difference, clamped to
maxScrollTop). Cover the cancel-after-autosave re-render path too (pin or the same correction).
Add a visual assertion in `check_edit_palette` (open, Escape, check the paragraph top is within
~8 px of `before`) and a scrollSync unit test that closing restores scrollY.

### 2. MEDIUM - Clicking the bar background / padding / pill edge blurs the textarea and closes the editor
src/webview/editPalette.ts:62-65 (root). Only the buttons and the menu get `mousedown`
preventDefault; the root has just a click stopPropagation. Reproduced: a click 2 px inside the right
edge of the pill closed the editor (textarea count 0), which runs the final blur save. The gaps are
2 px, padding 3 px, plus the rounded corners and group separators, so a near-miss on a button is easy.
Fix: `root.addEventListener("mousedown", keepFocus)` (declare `keepFocus` before it). Then the
per-button listeners become redundant but harmless. Add a unit assertion that dispatching mousedown on
the palette element is default-prevented, and a visual click on the bar padding.

### 3. LOW - "Bold looks pressed" in edit-palette-cream-bar.png is hover, not an active state
The capture script clicks Bold, undoes, and screenshots with the mouse still over the button; the only
background rules are `:hover` and `[aria-expanded=true]`. There is no selection-driven active state, so
nothing misreports the selection. Acceptable. Optional: move the mouse away before the `-bar`
screenshot so the cream/light/dark images do not look like a toggled state.

### 4. INFO - existing-test changes (both acceptable)
- capture.py `check_edit_activation_scroll`: the old "no scroll change > 2 px" cannot hold now. The new
  version still requires positions[0] > 0, no overshoot or oscillation (all samples within 2 px of
  start/end), compensation within [-2, barHeight+2], and the text line itself moved <= 2 px. It is
  stricter on what matters. Note it never checks close, which is why finding 1 slipped through.
- scrollSync.test.ts harness: `insertBefore` gives an inserted DIV the parent's top (the fake has no
  layout) and a new `platform` option. Narrow, only affects DIVs at top 0, no assertion weakened.
  The editActions registry id-list test was extended by appended ids only.
