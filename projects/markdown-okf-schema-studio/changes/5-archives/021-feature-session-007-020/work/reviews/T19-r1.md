## Findings

1. LOW, src/extension.ts:3042 (`onConfFileEvent`): no debounce. A `git checkout` touching many
   conf.py files fires N events, each calling `invalidateConfCache()` and, per open preview, a
   forced `refreshOpenDocument(preview, true)`. Renders are funnelled through `preview.queue.refresh`
   (which supersedes pending work) and the `deferWhileEditing` key "render" dedupes while a block
   editor is open, so it is not a storm in practice. Optional fix: coalesce events with a 100-200 ms
   timer. Also every preview refreshes for any conf.py, even an unrelated one (spec says "refreshes
   active previews", so acceptable).
2. LOW, src/extension.ts:~3020 (`publishMystDiagnostics`): a failed re-render keeps the previous
   entries until the next success (implementer noted it). Closing the text document while its
   preview is open keeps the entries (correct: still has a preview). Acceptable.
3. INFO: `**/conf.py` only covers workspace folders. A conf.py outside every workspace folder is not
   watched. The old per-preview watcher was rooted at the workspace folder too (or the document
