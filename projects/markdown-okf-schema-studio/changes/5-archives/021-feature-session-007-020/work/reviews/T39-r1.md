## Required fixes

1. HIGH - pending selection keys on pre-patch source lines (scrollSync.ts selectBlocksTo ~3673,
   applyPendingBlockSelection ~3690). When the open editor is saved first, `pendingBlockSelection`
   stores `{ anchorLine, targetLine }` (lines of the clicked block before the save). If the saved text
   has more or fewer lines than before, every block below shifts, so after the patch `targetLine` either
   matches no block (nothing selected, silently) or matches a DIFFERENT block (wrong run selected; T41
   would then act on the wrong range). The existing test only passes because `patchMessage()` keeps all
   lines. Fix: store the target as an index among selectable blocks plus its line delta, or better,
   re-resolve it after the patch: remember the block's ordinal in `selectableBlocks()` (and the anchor's
   ordinal) before the save and resolve by ordinal when the number of body blocks is unchanged; if the
   block count changed, fall back to selecting the edited block only or drop the selection (never a
   different block). Add a scrollSync test where the edit adds two lines to the first block, then assert
   the selected lines are the shifted lines of the clicked block (and the edited block as anchor).
   Same concern for `selectionAnchorLine` in general (kept across patches), so the fallback "anchor line
   not found -> use clicked block" can silently pick a wrong anchor when the line now matches another
   block: reset `selectionAnchorLine` in the content-patch path or resolve it by ordinal too.

2. MEDIUM - stale `pendingBlockSelection` can fire later (scrollSync.ts ~3690, 3103). It is cleared on
   save error, plain click, Escape, edit mode off, but not when the save ends without a patch (host
   no-op) or when the patch arrives while `activeBlockEdit` is still set (then
   `applyPendingBlockSelection` drops it silently, selection lost). Fix: also drop it when
   `closeBlockEdit` runs with no patch following (e.g. clear it in the editor-cancel path) and after
   N-th unrelated patch is not acceptable: apply on the first patch only (already), and clear it in
   `closeBlockEdit(true)` called from other paths. Add a test: save acknowledged without patch, then a
   later patch must not select.

3. LOW - focus is moved to the free end only after Shift gestures; after Escape the focus stays on the
   (tabindex -1) block, fine, but Shift+Arrow with an active selection is also taken when the key target
   is any non-input element (toolbar buttons, menus), see keydown ~3699. Restrict the "selection is
   active" branch to targets inside a body block, the insert bar or `document.body`, so toolbar/menu
   keyboard use is unaffected.

4. LOW - Shift+mousedown cancel (~3735) excludes tag `A` but not descendants of a link (`<a><code>x</code></a>`,
   `<a><strong>`): the default is prevented there although the click handler then ignores links. Use
   `target.closest("a")` instead of the tag check so link drag-selection with Shift is untouched.

5. LOW - Shift+click on a body block while the property (frontmatter) editor is open selects blocks and
   leaves the frontmatter editor open (selectBlocksTo does not check `activeFrontmatterEdit`). Either
   return early (like the keyboard handler) or finalize it as a plain click does. Add a test line.
