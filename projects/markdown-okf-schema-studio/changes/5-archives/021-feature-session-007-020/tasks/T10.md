# T10 — Margin button: Margin → Auto → Full width

Backlog: clever-margin-break, block-edition-palette · Phase 2 · Size M · Depends on: T08 · Gate: B S T
Commit (draft): `feat(vscode): switch the preview between margin, auto and full width`

## Goal

A Margin button on toolbar row 2 cycles three states, remembered per workspace: **Margin** (the
`maxContentWidth` column), **Auto** (column kept; only tables, figures, images and code blocks
wider than the column break out to the pane width, centred), **Full width** (no column limit).

## Decisions

U5, O3 (Margin = the setting; with the setting at 0 all states look the same).

## Read first

- previewStyles.ts:2194 `previewContentWidthCss` (`--sphinx-preview-content-max-width`),
  423–424 sticky band, 1226–1229 content column, table/figure/pre rules.
- T08 module `src/state/previewViewPreferences.ts` (`widthMode`) and its runtime wiring.
- `docs/scroll-anchoring.md` (layout changes must keep the reading line).

## Changes

1. Toolbar row 2: `data-sphinx-preview-width-toggle` button after Zoom +; three icons;
   tooltip/aria-label "Width: Margin" / "Width: Auto" / "Width: Full width".
2. Runtime sets `<html data-sphinx-preview-width="margin|auto|full">`, posts
   `previewViewPreferenceChanged` `widthMode`, keeps the reading line, recomputes T09 clearance.
3. Full: CSS overrides the max-width variable to `none` (sticky band follows).
4. Auto: runtime measures top-level `table`, `figure`, `img`, `pre`, `.mermaid`/diagram wrappers:
   when content width > column width, set `data-sphinx-preview-wide` on the element (or its
   wrapper) and set `--sphinx-preview-breakout` via CSSOM to the extra width; CSS centres it on
   the pane with a 16 px gutter; never wider than the pane (no horizontal page scroll). Re-measure
   after `initializeContent`, resize, zoom; clear in other modes.
5. Edited elements (block/table-cell editor) keep the column width while edited.
6. CHANGELOG bullet; README mentions the button and its relation to `maxContentWidth`.

## Tests (fail before)

- Webview harness: three clicks cycle states and post `widthMode`; attribute set; wide flag only
  on elements wider than the column, only in Auto.
- Visual (new scenario, wide 12-column table + small table + wide image): Margin: all inside the
  column; Auto: wide table wider than the column, inside the pane, small table unchanged; Full:
  column equals pane minus gutters; no horizontal page scroll in any state; light/dark/cream.
- Scroll suite: reading line kept when cycling at mid-document.
