# T05 — Clamp included-block line ranges, mark included blocks

Backlog: move-block-up-down (prerequisite, D1) · Phase 1 · Size S · Depends on: — · Gate: B T
Commit (draft): `fix(editor): edit the include directive for blocks from included files`

## Goal

In edit mode, clicking a block that comes from an `{include}` opens the editor on the
`{include}` directive lines of the host document, never on unrelated host lines. Included
blocks carry a marker so block operations (T36, T39) can refuse them.

## Decisions

D1 (refuse moves/cuts/selection of included blocks; fix the end-line clamp first).

## Changes

1. Verify first: a rendering test with the directive on lines 3–4 of the host and a 20-line
   included file; record the bad `data-end-line` values in the report.
2. `setIncludedSourceLine(node, startLine, endLine)`: set both `start.line` and `end.line` to the
   directive's own range (from the `child.position` used at 751).
3. Mark included output: every element that receives source position properties from an
   included node also gets `data-sphinx-preview-included="true"` (e.g. a flag on the node set in
   `setIncludedSourceLine`, read in `sourcePositionProperties`). Check the sanitizer keeps it.
4. Nested includes keep the OUTER directive's lines (the host document's coordinates).
5. CHANGELOG bullet.
