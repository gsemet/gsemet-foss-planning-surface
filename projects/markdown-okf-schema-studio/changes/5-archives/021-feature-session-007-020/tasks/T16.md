# T16 — Incoming-change marks (HEAD, green bar, setting)

Backlog: show-incoming-diff · Phase 3 · Size M · Depends on: T03, T08, T02 · Gate: B T
Commit (draft): `feat(render): mark blocks changed since the last commit`

## Goal

Blocks whose source lines differ from the file at HEAD (unsaved edits included) show a green bar
on their left, like the editor gutter. Untracked files and folders without Git show nothing.
A setting turns the feature off.

## Decisions

U11, D18 (vscode.git API, no hard dependency, no spawn), D19 (block level, one green, no deleted
marks), O1 (setting false = off and toggle hidden), O10 (no marks inside an open editor).
Setting `markdownOkfSchemaStudio.preview.showIncomingChanges`, boolean, default `true`, order 22.

## Changes

1. `src/mapping/lineDiff.ts` (pure): `changedLineRanges(base, current): { start: number; end: number }[]`
   (1-based, in `current`), split on `\r\n|\n|\r` (EOL-insensitive), common prefix/suffix strip
   then Myers; above 20 000 middle lines or D > 2000 → whole middle changed.
2. `src/git/headBaseline.ts`: minimal local interfaces for the Git API v1
   (`getAPI(1)`, `getRepository(uri)`, `repo.show("HEAD", fsPath)`, `repo.state.HEAD?.commit`,
   `repo.state.onDidChange`); returns `undefined` when the extension, repository or HEAD blob is
   missing (untracked) or the document is not `file:`/is > 1 MB; cache per (path, commit).
3. Host: after each render/patch and on `previewReady`, when setting and preference are on and
   the workspace is trusted, post `previewIncomingChanges { documentId, documentVersion,
   requestId, ranges }` (debounced 300 ms on typing; re-fetch base when HEAD commit changes).
4. Page (`src/webview/incomingChanges.ts` factory): clear old marks, then set
   `data-sphinx-preview-changed` on the innermost mapped elements whose
   `[line, end-line]` intersects a range; re-apply in `initializeContent`; skip elements inside an
   open editor. CSS: inset 3 px green bar (`--vscode-editorGutter-addedBackground`, fallback
   `#2ea043`) without layout shift.
5. README "Settings", CHANGELOG bullet.
