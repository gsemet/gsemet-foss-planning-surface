## Changes

1. New `src/preview/previewMessages.ts` (no `vscode` import):
   - `type MessageValidator = (message: Readonly<Record<string, unknown>>) => boolean`.
   - `createPreviewMessageChecker(validators)` → `(value: unknown) => value is RegisteredPreviewMessage`:
     object, `type` is an OWN key of `validators` (reject `__proto__`, `toString`…),
     `documentId` string ≤ 4096, `documentVersion` and `requestId` safe integers, then the
     validator returns true.
   - `REGISTERED_PREVIEW_MESSAGES: Record<string, MessageValidator>` (empty object now;
     `Object.create(null)`-style or a plain literal checked with `Object.hasOwn`).
   - `isRegisteredPreviewMessage = createPreviewMessageChecker(REGISTERED_PREVIEW_MESSAGES)`.
   - Small exported field helpers: `isBoundedString(value, max)`, `isSourceLine(value)` (safe
     integer ≥ 1), `isOneOf(value, list)`.
2. extension.ts: `const registeredMessageHandlers = new Map<string, (preview: ActivePreview, message: RegisteredPreviewMessage) => Thenable<void> | void>()`.
   In `handlePreviewSyncMessage`, before `isPreviewSyncMessage`: if
   `isRegisteredPreviewMessage(value)`, apply the same staleness gate as `matchesCurrentPreview`
   (widen its parameter to `{ type; documentId; documentVersion; requestId; editId? }`), then call
   the handler (none registered yet → ignore). Registered types must never reach the generic
   path: make `isPreviewSyncMessage` return false for them.
3. Document the two-step recipe in a header comment of `previewMessages.ts`.
