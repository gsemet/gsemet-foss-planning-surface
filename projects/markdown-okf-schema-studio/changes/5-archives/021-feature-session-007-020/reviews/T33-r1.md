## 3. mystRenderer.ts span keep (normalizeRawDetailsAndKbd)
Narrow, same shape as the details/kbd normalizer. Opening tag must be exactly `<span style="..."|'...'>` (no other
attribute, no `<>` in the value); the node it produces is `span` with only a `style` hProperty. Content comes from the
already-parsed mdast siblings, so no raw HTML is passed through; unmatched open span falls through to the old
"dropped" path (close === -1), nothing swallowed. Nesting is counted (`<span ...>` +1, `</span>` -1) and inner
colour spans are normalised recursively; an inner non-style `<span>` stays a dropped html node. Minor imprecision:
the depth counter regex `<span(\s[^<>]*)?>` would also count a self-closing `<span />`, which could mis-pair in
pathological input; it only affects which close is chosen, never lets markup through. The result is still sanitised
afterwards (rewriteSphinxHtml is the only path to the page; end-to-end test in mystFeatures.test.ts goes
render -> sanitize and checks bad styles, bold child text preserved). It is an addition beyond the task text but
required: without it the renderer dropped the span before the sanitizer ever saw it. Accepted.
