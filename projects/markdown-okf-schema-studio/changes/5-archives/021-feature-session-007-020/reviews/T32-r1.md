## Findings by focus item

1. Parser tolerance / byte identity (src/webview/figureDirective.ts)
   I ran the compiled module on odd inputs. Identical after parse, valuesOf, applyValues and
   serialize with no edit: `:width:   60%` and `:class:    big  ` (odd spacing, trailing blanks),
   `:width:60%` (no space), two blank lines before the body, a 2-space-indented directive, and a
   `::::{figure}` with a nested `:::{note}` inside the legend. Editing only the width rewrites only
   that line (the new line is `:width: 40%`, the other lines unchanged). Editing only the legend keeps
   the options and the caption. Adding a width to a figure without options inserts the option and keeps a
   blank line before the body. Legend = paragraphs after the first body paragraph (O11): correct.
   Fence grows when the legend holds a fence. `---` YAML blocks return undefined, and the status
   message in openFigurePanel is acceptable (item 5).
   - L1 (low): an EMPTY known option that is untouched (`:alt:` with no value) is dropped on any
     Apply (serializeFigure: `if (known && option.value === "") continue;`). Fix: only skip when
     `option.raw === undefined` (it was cleared in the form), so untouched lines survive.
   - L2 (low): CRLF text (`\r` before `\n`) does not parse (`.` does not match `\r`), so the form
     would say "No figure at the caret". Not reachable in practice: textarea.value is always LF.
     Optional: strip a trailing `\r` per line, or leave as is.

2. "Cmd/Ctrl+A then typing loses the first character": NOT a product bug of T32.
   - The repo already documents the same host behaviour in RI-T06 and RI-T07
     (test/integration/realInput.test.ts ~444 and ~510): VS Code forwards Cmd/Ctrl+A to the
     workbench, which echoes `selectAll` asynchronously into the webview; a key typed before the echo is
     replaced. The existing tests wait 300 ms. This also reproduced on pre-T06 code and in
     frontmatter inputs, which T32 does not touch.
   - I checked every keydown listener that can see an event from a form field. The figure
     panel's own listener handles only Escape, Enter, Cmd/Ctrl+Enter and Tab (at the ends); it never
     handles or re-focuses on Cmd/Ctrl+A or a printable key. The document-level listeners
     (scrollSync ~2630, 2641, 3413, 3544, 4135, linkNavigation, chipToggle) are Escape/Enter/Space
     only, and the Enter/Space one returns early for INPUT/TEXTAREA/SELECT/BUTTON. The palette and T20
     shortcut handlers are attached to the text box and palette elements, not the form. The panel's
     mousedown handler lets INPUT/TEXTAREA/SELECT through, so focus and selection are not stolen.
   - The triple-click workaround in the scenario is therefore legitimate. No fix required.

3. scenarioParagraphBlurCommit failure (toolbar intercepts a click): unrelated.
   The log shows Playwright failing to click the `h1` "Smoke document" because the fixed preview
   controls toolbar overlaps it. That is the first step of a scenario with no figure and, in the
   failing frame, no edit mode. The figure button is created lazily on the first hover of a
   `figure` in edit mode, is `position: fixed; z-index: 20`, is hidden by default and hidden when
   edit mode is off (CSS rule). It cannot intercept a click on an h1, and the intercepting node was
   the toolbar itself. The scenario passed in T4 with no source change. Pre-existing layout flake
   (window size vs toolbar).

4. Mechanics (scrollSync.ts openFigurePanel / openFigureEditor, figurePanel.ts)
   - Apply = one `applyTextEdit` over [location.start, location.end]; when `written === slice` nothing
     is written and focus/selection are restored. A stale text (value changed without input event)
     closes the form without writing. Verified by the unit tests and by the realInput scenario
     (Cmd/Ctrl+Z restores the whole directive in one step).
   - Form closes on textarea mousedown and input, and with the editor (destroy in the editor teardown).
   - Browse uses `hostRequests.ask("previewPickImage", {}, {dialog: true}, ...)`, and onLeave
     checks `hostRequests.isDialogOpen()`, so the dialog does not close the editor. The
     previewPickImage handler already exists (T31), with the readOnly/untrusted refusal; no new host
     message type is added.
   - Hover button: mousedown preventDefault, click preventDefault/stopPropagation, child of body,
     placed with `style.setProperty` (CSP-safe), `owns()` prevents hover flicker, hidden on scroll
     (capture) and in non-edit mode. All styling is in the stylesheet (CSSOM).
   - Injected modules (createFigureTools, createFigurePanel, installFigureEditButton) use only
     their own bodies; `import type` is erased. No new "Sphinx" string in a user-facing file.
   - Form keeps the editor open: inputs blur to an inside-frame node is ignored; blur outside
     saves (same as the link panel). Text position kept via keepTextInPlace and the paletteShift
     bookkeeping.
   - L3 (low, optional): the hover button is positioned once per figure and not on resize/zoom;
     it hides on scroll but a zoom change leaves it misplaced until the mouse leaves the figure.
     Acceptable.
