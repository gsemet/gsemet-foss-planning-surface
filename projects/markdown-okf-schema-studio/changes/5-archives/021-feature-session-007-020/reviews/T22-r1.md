## Findings

1. MEDIUM - stale selection can corrupt text when focus returns to the text box with the panel open.
   src/webview/scrollSync.ts:2858-2905 (`openLinkPanel`), submit at ~2889.
   The selection is captured once at open and `linkEdit(selection, ...)` plus `applyTextEdit` use those
   offsets on submit. Nothing closes the panel when the textarea regains focus: its blur is ignored
   (relatedTarget inside frame) and the textarea `mousedown`/`input` handlers (~3027) only close the
   palette popover. Repro: open the panel, click back in the text box, type or delete text, then
   click Insert (or press Enter in the panel after re-focusing it): the link replaces the OLD offsets
   in the NEW text. Same for Cancel, which restores the old range.
   Fix: close the panel (cancel path, no restore) on textarea `input` and `mousedown`; or, minimal,
   in `onSubmit` compare `control.value` with `selection.value` and re-capture/abort if they differ.
   Add a unit test (open panel, change textarea value, submit).

2. LOW - link text is not escaped. src/webview/editActions.ts `linkEdit` (~545). Text containing `[` or
   `]` produces a broken link (`[a]b](u)`). Escape with a backslash, or leave as is and document.
   Also a URL containing `<` or `>` is wrapped in `<...>` only when it has whitespace or unbalanced
   parens, and a `>` inside then breaks it; rare. An existing title `"t"` is dropped when an existing
   link is replaced (`linkDraft` ignores it); acceptable but worth noting in the CHANGELOG or tests.

3. LOW - Ctrl/Cmd+K pressed while focus is inside a panel field is not handled (the key handlers
   are on the textarea only), so the workbench gets it. src/webview/linkPanel.ts keydown. Optional:
   on Cmd/Ctrl+K in a field, preventDefault/stopPropagation and re-select.

4. INFO - multi-line selections lose newlines when put in the single-line Text input (inherent to
   `<input>`); acceptable.
