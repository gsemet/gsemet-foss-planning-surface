## Findings (all minor, none blocking)

1. Focus and save safety: OK.
   - Textarea to filter: the textarea blur handler already ignores in-frame targets; the filter
     `popoverBlur` returns early when `relatedTarget` is inside the frame (editPalette.ts popoverBlur).
     No save. Leaving the frame from the filter or an emoji button calls `onLeave` once.
   - `closing` is set only around the synchronous `openMenu.remove()`, so it cannot swallow a later
     real exit: after close, focus is on the text box and its normal blur path applies. A click
     outside right after a close therefore saves exactly once.
   - `closePopover` focuses the text box only when `menuFocused`; `destroy()` uses `closePopover(false)`.
   - Edit reads live value/selection in `run()` (no captured selection). No stale selection.
   - Shift+click: `holding` makes the external `closePopover` (called from the text box `input`
     handler) a no-op only during the synchronous insertion. Internal Escape/toggle paths use the
     real function, so the picker cannot get stuck open.
2. Table grid: OK.
   - 81 cells built in `openPopover` only. Delegated mouseover/click. Label "r x c" counts the header
     as a row (3x4 = header, separator, 2 body rows). Acceptable reading of "first row = header";
     documented in CHANGELOG/tests.
   - `handleKey` acts on arrows/Enter only while `gridState` exists, so normal caret navigation is
     untouched when the grid is closed. Escape closes. Alt/Meta/Ctrl pass through.
   - Output goes through the pipe-table cell style; blank lines computed from the text before/after
     the caret (mid-paragraph gives "\n\n" before and after). Selection is kept and the table is
     inserted after it (documented). "Column 1" selected is a good choice (typing replaces the
     placeholder). Render test in mystFeatures present.
   - Nit (optional): Shift+Arrow with the grid open is consumed as a plain arrow, and Enter with
     nothing highlighted is swallowed (no newline). Consider `if (event.shiftKey) return false` for
     arrows. Not required.
3. Emoji: OK.
   - Unicode only; `insertEmoji` validates with an Extended_Pictographic/ZWJ/FE0F regex and length
     <= 16. Names go through `title`/`aria-label` via setAttribute and chars via `textContent`: no
     HTML injection. Filter matches words of the name; Enter inserts the first match; Shift+click keeps
     open. `cell` scope allowed for emoji, not for table. Insertion goes through `applyTextEdit`
     (one undo step).
   - Nit (optional): Tab from the filter moves focus to the next in-frame control and leaves the
     popover open (no save, no data loss). Escape closes it.
4. Existing assertions: the 9 to 11 count and the button list only gain "table" and "emoji";
   intent unchanged.
5. Screenshots (cream): the grid popover is clean, with a clear terracotta highlight of 12 cells and

6. Performance: grid and emoji DOM are built only when the popover opens (`buildGrid`/`buildEmoji`
