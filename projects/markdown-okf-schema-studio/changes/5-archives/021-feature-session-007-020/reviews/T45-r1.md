## Findings

1. HIGH - false orphans for threads that are exactly where they were. anchoring.ts `reanchorWith` (about line 355-365) +
   `plainInline`. The search runs on the markdown SOURCE, but the quote is the RENDERED text. When the rendered text is not a
   substring of the source line (MyST roles, citations, footnote markers, HTML entities, HTML comments, math with `^`, etc.)
   and fuzzy (20 %) cannot bridge it, the thread is reported "orphaned" although its block is untouched. Repros (thread line =
   the right line, nothing edited): quote "As shown in Smith, 2020 the result holds." on source
   "As shown in {cite}`smith2020` the result holds." -> orphaned; "Installation" on "See {ref}`install-label` now." ->
   orphaned; "Tom & Jerry" on "Tom &amp; Jerry ..." -> orphaned; "A claim1 here." on "A claim[^1] here." -> orphaned;
   "Text after." on "Text <!-- TODO fix --> after." -> orphaned. Because the host now posts `orphaned:true` and the page
   obeys it (commentThreads.ts apply: `thread.orphaned === true ||`), such a thread moves to the Orphaned box on first open,
   whereas at fea8ce5 the page highlighted it or badged its block. This is a regression for ordinary documents, not only
   after edits. Fix (conservative, keeps D30): in `reanchorWith`, before returning "orphaned" for a thread whose old lines
   exist, test whether the plain text of the old line range still resembles the quote (e.g. >= 60 % of the quote's words,
   lower-cased, occur in the plain text of lines line..endLine, or fuzzy distance against those lines only is <= 50 %);
   if so return "anchored" (keep the lines, host posts orphaned:false). Only a quote with no resemblance to the old lines
   (realInput t2 "not in the block") is orphaned. Also strip `{role}` prefixes, `&..;` entities, `<!-- -->` and `[^n]` in
   `plainInline`. Add tests with the five repros above (they must stay "anchored").

2. MEDIUM - prefix/suffix mismatch is ignored, so a short or weak candidate re-attaches to unrelated text.
   anchoring.ts `decide` (`if (matching.length > 0) pool = matching;` falls back to ALL candidates when none matches the
   stored context). Repro: thread on "Overview" (line 3, prefix "Intro: ", suffix "of the product") whose sentence was deleted;
   document has a different heading "## Overview" at line 7 -> "moved" to line 7. Same for a long unique quote: prefix
   "Warning: ", suffix "Do not do it." both disagree, still "moved". Fix: when the anchor has a non-empty prefix or suffix and
   NO candidate matches the context, accept a candidate only if the quote is >= MIN_FAR_QUOTE and unique (never for short
   quotes), i.e. in `decide`: `if (matching.length === 0 && short) return undefined;` and for multiple candidates with no
   context match return undefined. Add a test for the short-quote repro.

3. MEDIUM - the "still in its old lines" fast path ignores context, which attaches to the wrong duplicate after an external
   change. anchoring.ts `reanchorWith`: `exact.some(candidate in [line, endLine]) -> anchored`. Repro: the same sentence twice
   (copy A line 23, copy B line 27, thread belongs to B: prefix "between"); an external edit (git pull, other tool) inserts
   lines above A so that A now sits at B's old line; the thread is "anchored" on A. Fix: when there is more than one exact
   candidate in the document and the thread has a prefix/suffix, require `contextMatches` for the in-range candidate;
   if it fails and another candidate matches the context, prefer that one (go through `decide` with the full list).

4. LOW - `exactCandidates` stops at MAX_CANDIDATES = 200 in document order, so for a very common short quote the in-range
   occurrence can be missed and the thread moved to a window neighbour. Fix: check the in-range occurrence directly first
   (indexOf within the plain-text span of lines line..endLine) before applying the candidate cap.

5. LOW - fuzzy accepts semantically flipped sentences within 20 %: "You should enable the cache ..." re-attaches to "You should
   not enable the cache ...", "300 seconds" to "30 seconds" (both "moved"). This is inside the brief's 20 %, so not blocking;
   consider requiring the numbers/negations to match or lowering the ratio to 0.15 for quotes under 80 chars, and say so in
   the README if kept.

6. LOW - `warnAnchorsNotSaved` fires on every save of a document whose sidecar is open and dirty, even when no anchor would
   move or there are no threads (deduped only by message text, reset after any success). Fix: run the dirty-sidecar check
   after computing that something moved, or only warn when `previews` have a non-empty `commentView`.
