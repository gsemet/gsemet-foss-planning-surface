## 3. Renderer change (src/render/mystRenderer.ts normalizeRawDetailsAndKbd)
Ran the compiled renderer on hostile inputs; no injection path:
- Narrowly scoped: only exact `<details>` / `<details open>` (`open`, `open=""`, `open="open"`),
  optional `<summary>` with NO attributes and text without `<`, and exact attribute-less `<kbd>`.
  Anything else (`<details onclick=...>`, `<kbd class=..>`, `<summary>` with tags) is not matched
  and is dropped exactly as before (confirmed: only inner text remains).
- Summary text becomes an mdast text node (escaped on serialisation); `&lt;img onerror&gt;`
  cannot become markup. Only `hProperties` is `open: true`.
- Body of the "whole" form is re-parsed with mystParse; raw `<script>` in it is still an html node
  that gets dropped; `<kbd onclick>` becomes plain text `Z`; `<kbd><script>` gives `<kbd>alert(1)</kbd>`.
- The sanitizer (`rewriteSphinxHtml` in src/security/html-sanitizer.ts, called from
  src/preview/webview.ts) runs on the final HTML after rendering; the change sits before
  `mystToHtml` and does not touch it. Event/style attributes would still be stripped.
- Table cells, nested details (split form), unmatched `<kbd>` / `<details>` fall through safely.
- No "Sphinx" in the new strings (the only match in the file is a pre-existing comment at :40);
  "Details" is the only literal added.
- Justified by the task brief ("if stripped, allow kbd") and details was also dropped. Behaviour

Minor, not blocking: no security test pins the "attributes stay refused" behaviour (see N1).
