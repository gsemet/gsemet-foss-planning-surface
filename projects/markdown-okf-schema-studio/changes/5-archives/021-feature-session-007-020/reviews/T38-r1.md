## 1. Deviation: no host-side active-edit check -- acceptable (Low)
- A message only reaches `handlePasteImage` after `isRegisteredPreviewMessage` and `matchesCurrentPreview`
  (document id, version, request id). Rendered document content cannot post it: content is sanitized, the CSP
  blocks inline script, and the only code path that posts it is the textarea `paste` listener
  (scrollSync.ts, `installPasteImage`), which exists only while a block editor is open.
- A webview already compromised by script injection could call `previewEditSave` and rewrite the document
  anyway, so the paste message adds little. Its blast radius is bounded: only a valid png/jpeg/gif/webp
  (sniffed), at most 10 MB, host-chosen `image*.ext` name, only next to a saved file inside a workspace folder.
- A host `editId` check is not feasible without new state (`activeBlockEdit` is set at the first autosave, and
  the `editId` of `ask` is a fresh per-request id, not the edit id). Not required. Optional hardening (not
  blocking): a per-preview cap on pastes (e.g. 50) to stop a hostile page filling the disk with 1000 x 10 MB.

## 2. Validator -- OK
`previewMessages.ts:108`: mime allow-list, non-empty string, length <= 14 000 000, `isBase64` (alphabet, <= 2
padding chars, length % 4 == 0, linear regex). Host re-checks mime, charset, decoded size <= 10 MB, and the sniff
must equal the announced type (spoof test present). SVG excluded. Magic bytes correct (png 8 bytes, jpeg FFD8FF,
GIF87a/89a, RIFF....WEBP).
