## Real bug found in src by the visual run (fixed)

`targetIn` (lineMarkerPlacement.ts) returned a table cell (`td`/`th`, which carry the marker line of their row) as the target of a pipe table line, so `tableRowFor` searched inside the cell, found no row, and the marker drew one line high on the cell text instead of the row's full height. The fake-DOM page tests missed it because their rows had no cells. Fix: `targetIn` skips a row and its cells (`isRowPart`). The quoted-table page test now gives each row a `td` carrying the marker line, so it pins this. The renderer, tabs and front matter paths showed no other bug.
