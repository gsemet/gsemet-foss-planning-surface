## Findings

### Blocking

1. **New W002 prose warning on BLOCK-257.**
   `requirements/tiers/swrs/block-editing/SwRS-MDOKFSTUDIO-BLOCK-257.md:44` (normative paragraph).
   `okfreq lint --check --prose` now reports
   `W002 …SwRS-MDOKFSTUDIO-BLOCK-257.md: body has no filled EARS expression`.
   On a0ee07e4 it reports only CORE-071 and CORE-076, so this change introduced the warning.
   The cause is `body_is_unfilled` in okf_schema/okfreq/core.py:250: it treats any
   `<[a-z][^>\n]{3,}>` as a scaffold placeholder. The new text
   "(`:::{grid-item-card} <title>` or `:::{card} <title>`)" matches that pattern.
   Fix: drop the angle-bracket placeholders. Two options:
   - "on the directive line (the `:::{grid-item-card}` or `:::{card}` line that holds the title)"
   - use the concrete example `:::{grid-item-card} 2. Status projection`.

   Then re-run `just requirements-update` and confirm only CORE-071/076 remain.

### Non-blocking

2. **Missing `@implements_req` for the new BLOCK-257 behaviour.**
   `src/core/render/mystGridToctree.ts:254`. The title and option line mapping now lives in
   `buildCard`, `inlineContent` and `lineProperties`, but only MYST-100 is marked there. The only
   BLOCK-257 marker sits on `gridColumnCss` (l.616).
   Fix: add `// @implements_req SwRS-MDOKFSTUDIO-BLOCK-257` above `buildCard`, next to MYST-100.

3. **The MYST-100 row edit has no `@tests_req SwRS-MDOKFSTUDIO-MYST-100`.**
   `test/core/render/gridCardTitleSourceLine.test.ts:96`. The `:header:` behaviour changed in
   MYST-100's table, but no test tagged MYST-100 checks it.
   Fix: tag the header-option test with `// @tests_req SwRS-MDOKFSTUDIO-MYST-100` as well. Then let
   `just requirements-update` add the file to MYST-100 `tested_in_files`.

4. **Test coverage gaps for the index arithmetic.**
   `test/core/render/gridCardTitleSourceLine.test.ts`. Only `:header:` as the first option is
   tested. The `:footer:` path and an option that is not the first line are not. I checked both by
   hand and they are correct.
   Fix: extend the header test, or add one, with `:class-card: x` / `:header: 4. H` /
   `:footer: 5. F` and assert lines 4/4 and 5/5. That pins `raw.firstLine + index`.

5. **SwRS granularity.**
   BLOCK-257 is "a block editor in a grid card widens the card…" (layout of an open editor). It now
   also carries "a click on a title opens the directive line, and titles render inline-only", which
   is a different observable behaviour (requirements.guidelines.md "One SwRS is one observable
   behaviour"). The GO accepts BLOCK-257, so this does not block. A follow-up could move the
   click-target and inline-rendering part into its own SwRS, or into MYST-100. Also consider
   rewording the second normative sentence in EARS form ("When the writer clicks the title of a card
   without `:link:`, the preview SHALL …") rather than "A click … SHALL".

6. **Pre-existing bug, now also reachable from the title: wrong line for a grid inside a blockquote.**
   A `> ::::{grid}` (or any grid whose fences `directiveBody` cannot locate, so it falls back to
   the collapsed `value`) gets lines shifted by one. A card on line 5 renders `data-line="4"`. This
   is already true on a0ee07e4 for the card div itself (`sourceProperties(node)`, unchanged code).
   The title now inherits the same wrong line, so a title click there opens line 4 (`>`) instead of
   line 5. This is out of scope for #229.
   Fix: file a backlog item ("grid/card inside a blockquote maps every line one too early"), not in
   this CR.
