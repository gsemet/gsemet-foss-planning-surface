# T1 round 1: text shortcuts in the find bar fields

## Cause and fix

Cmd/Ctrl+A is already kept in text inputs by `selectAllKey.ts`, but VS Code's webview forwarding and
page key listeners still see the other native keys typed in the bar (undo/redo are forwarded to the
workbench history, Cmd/Ctrl+C/X/V reach the block-selection clipboard listener path in some states).
I could not reproduce the exact Ctrl+A symptom without a real VS Code window, so the fix is generic:
in `barKeydown`, a native text-editing key typed in the find or replace field now stops at the bar
(`stopPropagation`, no `preventDefault`), so the browser runs its default action on the field alone.
The bar's own keys are handled first and unchanged.

Keys covered: Cmd/Ctrl + A, C, X, V, Z, Y (with or without Shift); arrows, Home, End, Backspace,
Delete with any of Shift, Alt, Cmd/Ctrl (caret, word and line moves, delete a word). Not taken during
an IME composition, and not Ctrl+Alt+letter chords.
