   - User-visible change: a paste that loses a name race is now refused with the rename error

## Findings (non-blocking)

- **Low**, `test/integration/realWindowGaps.ts:272`. `pasteState` calls `fs.statSync` on each
  `readdirSync` entry. A hidden `.partial` file can be renamed or deleted between the two calls.
  `statSync` then throws ENOENT, and that error replaces the timeout or byte-assertion message the
  diagnostics were meant to add to. Fix: wrap the per-entry stat (for example
  `fs.statSync(p, { throwIfNoEntry: false })?.size ?? "gone"`).
- **Info**, `src/node-services/nodeFileSystem.ts:47`. The Node file system's no-overwrite rename
  is stat then rename, which is not atomic. That code is older than this change and is not used
  by the VS Code path. If a strict guarantee is ever needed, use `fs.link` plus `unlink`, or
  `copyFile` with `COPYFILE_EXCL`.
- **Info.** Losing the name race shows the page a raw EEXIST/FileExists message. That is
  acceptable for a rare race; a friendlier "try again" message is optional.
