## Candidate StRS (use cases)

- UC-LIFE-1: A writer opens the Studio preview beside the Markdown file they edit (command, key, title button, Explorer, Open With) and it follows the file they work on.
- UC-LIFE-2: A reader forces the preview to render the current text again, by command or toolbar button.
- UC-LIFE-3: A reader opens a Markdown file directly as a Studio preview (Open With) without blocking VS Code.
- UC-LIFE-4: A writer leaves a document with an editor open and nothing typed is lost or blocked.
- UC-LIFE-5: A reader sees that the source is missing and the preview recovers when it comes back.
- UC-LIFE-6: After reloading VS Code the reader finds their previews again, at the same place.
- UC-LIFE-7: Files opened from the preview or while it has focus do not bury it, and its group does not leak a lock.
- UC-LIFE-8: A hidden preview catches up with the editor when shown again.
- UC-LIFE-9: Closing a preview or removing a workspace folder frees its resources and never deletes files.
- UC-LIFE-10: The preview shows the unsaved text, the state of the render and its errors, and does not freeze while typing.
- UC-LIFE-11: A writer tunes the preview through settings that apply without reloading VS Code.
- UC-LIFE-12: Typing updates the preview in place, keeping scroll position, open sections and unchanged blocks.
- UC-LIFE-13: A reader sees which blocks another tool or an undo changed.
- UC-LIFE-14: The preview and the source editor scroll together, reveal each other's lines and mark the cursor block, as the reader configures.
- UC-LIFE-15: The Studio coexists with the built-in Markdown preview.
- UC-LIFE-16: (maintainer) The product runs on host ports with stable contracts.
- UC-LIFE-17: (maintainer/reviewer) A preview of an untrusted or outside file is read-only and says so.

## Notable findings

- **Docs out of date**: `docs/preview-lifecycle.md` still says switching to a non-Markdown editor
  shows a missing-source state (UX-25 changed it to keep the last Markdown preview);
  `docs/feasibility-dirty-snapshots.md` and `preview-lifecycle.md` describe a Sphinx build for the
  live preview; `docs/known-limitations.md` says the preview is "read-only" and that multiple
  simultaneous previews are not claimed, while the product edits and supports several panels.

  debounce, the 1.5 s pending overlay, the 2 s patch fallback, the group lock, the ignored-folder
  list for dependency changes, `.markdown` files not being previewable, all restore/refusal pages.

  the containing block (F-LIFE-068); an open preview stays read-only after the user grants trust
  (F-LIFE-085, cross-scope); any preview-setting change after an Anchor button override reloads the
  page (F-LIFE-040); `shiftAnchorsForEdits` counts `\n` only (F-LIFE-062).
- **Untested**: activation events / engine floor, non-Markdown command refusal, "Cannot open"
  error path, missing-source texts for delete/rename, source reappearing, multi-root session
