## Per-message refusal rule (decided for all C-MSG rows)

One rule, applied to all 72 C-MSG rows (57 page messages and host answers):

1. **trust-security owns the generic protocol rules**: envelope and identity validation (F-TRUST-059),
   silent drop of invalid messages (F-TRUST-060), the page-state family validation (F-TRUST-061),
   payload bounds as a table (F-TRUST-062), the gates and stale handling (F-TRUST-063, 064), the
   host-to-page filter (F-TRUST-065), the router (F-TRUST-067), and the generic read-only gate
   (F-TRUST-007, 009).
2. **Every message-specific refusal belongs to the owner scope of the C-MSG row** (the `Scope` column of
   `checklists/preview-messages.md`): the read-only refusal and its reason text, the stale or
   out-of-bounds payload of that message, its result message. In the SwRS of that message the owner
   writes one clause "refused (with this reason) when the preview is read-only, stale or invalid".
3. trust-security lists those per-message refusals only as a cross-reference in the matrix F-TRUST-008
   (no C-MSG id is cited there), so no message needs a second SwRS in this scope.

The 22 rows of this scope contain no C-MSG row; the rule moves nothing.

## Candidate StRS (use cases)

- UC-TRUST-1: A reader opens a document in Restricted Mode or a file outside the workspace and sees
  it rendered, clearly without any editing control, so nothing can be changed by accident.
- UC-TRUST-2: Whatever the preview is asked to do in a read-only preview, no file is written and the
  reader is told why (trusted workspace needed); read-only viewing actions (zoom, theme, links, copy)
  keep working.
- UC-TRUST-3: A file outside the workspace previews with its own folder as the only place it may
  read from, without schema, and switching to a workspace document gives the workspace back.
- UC-TRUST-4: Features that start processes or read outside the document's folder (JAR, diagnostics,
  incoming changes, includes, PlantUML files) are limited in Restricted Mode, while the built-in
  PlantUML engine still works.
- UC-TRUST-5: Whatever a Markdown document contains, the preview page runs no script of the
  document, loads nothing from the network and nothing outside its roots (CSP, nonce, roots).
- UC-TRUST-6: A document can show local images, media and linked files next to it, but never a file
  outside the allowed folders, through traversal, encoding or symlinks.
- UC-TRUST-7: Unsafe HTML in a document is removed or made inert (scripts, event handlers, frames,
  styles, bad links) and only a small set of styles and colours is kept.
- UC-TRUST-8: The extension and its preview page only accept well-formed messages of known types
  with bounded content.
- UC-TRUST-9: A message about an older version of the document or preview is ignored or refused, never
  applied to the new one.
- UC-TRUST-10: User-visible text speaks of the product, not of its internal build tool.
- UC-TRUST-11: The package is opt-in, pins its engine and dependencies, and describes its settings.

## Notable findings

- Read-only preview is two cases with one flag: the refusal text "Editing requires a trusted
  workspace." and the label "the standalone document directory" are wrong for the other case
  (a standalone file cannot be trusted; Restricted Mode documents are not "standalone").
- Trust granted while a preview is open does not make that preview writable (only the incoming bars
  refresh): suspected gap against the README sentence "read-only until the workspace is trusted".
- Documentation and code disagree on includes in Restricted Mode: `docs/known-limitations.md` says
  includes need trust; the code reads them from the document's folder.
- The sanitizer is a deny-list (not an allow-list), has dead code (`sanitizeCss`), a stylesheet branch
  whose comment says "refuses outright" while the link stays, a mislabelled diagnostic
  (`blocked-event-attribute` for span styles), and its diagnostics never reach the status area.
- Host-level tests are thin: no unit test of `PageMessageDispatcher` (gates, silent drop, central
  read-only refusal, stale-edit error); refusal matrix covered by integration only for 6 of ~14
  handlers; `userFacingText` scans three pre-refactor locations only.
- `package.json` has no `capabilities`; Restricted Mode is proven with the development host only, and
  no test asserts the absence.
