## Candidate use cases (StRS)

- UC-TABLE-1: A writer clicks a table cell in edit mode and edits its Markdown in place, with the
  cell growing to fit and the table keeping its layout.
- UC-TABLE-2: A writer's cell edits are saved automatically, committed on Done, Enter or leaving the
  cell, cancelled by Escape or Cancel, and never lost when the preview navigates away.
- UC-TABLE-3: A writer moves through the table with Tab, Shift+Tab and the arrow keys and adds a row
  with Tab in the last cell, with Home, End and the usual editing keys working in the cell.
- UC-TABLE-4: A writer adds and removes rows and columns from a labelled bar that sits above the table,
  stays in view for tall tables and tells where the cursor is.
- UC-TABLE-5: A writer converts a table between pipe, list-table and simple HTML forms without losing
  content, and is told when a conversion is refused.
- UC-TABLE-6: A writer formats text in a cell (bold, italic, link, colour, emoji) from the bar or by
  shortcut without breaking the table.
- UC-TABLE-7: A reviewer sees a one-line diff for a one-cell edit: the table's padding, alignment,
  quoting, indentation and line endings are preserved.
- UC-TABLE-8: A writer inserts a table of a chosen size, aligns a column and gives a table a caption
  from the palette or the slash menu.
- UC-TABLE-9: In a read-only or stale preview a table cell is never edited, and the refusal is
  explained.

## Notable findings

- Column operations break the minimal-diff promise: Col + and Col − rewrite every line in canonical
  style (padding, indentation and outer-pipe style of the whole table are lost). UX-12 and the docs
  only cover single-cell edits (F-TABLE-027).
- A line break pasted into a cell is not sanitised (no paste handler, `serialize` does not escape it),
  which splits the row; untested and undocumented (F-TABLE-041).
- A pipe inside a code span is treated as part of the cell by `splitRow` and `escapeCellPipes`
  (round-trip tested), but GFM splits there; renderer parity is untested (F-TABLE-035).
- No visual or unit check at 360 px for the cell bar: the width-at-most-400 assertion in
  `capture_edit_checks.py` can never fire, and a dangling separator after "Col −" is a known low
  finding (F-TABLE-050).
- Fallback from a cell editor to the raw block editor (list-table, HTML table, `{table}` wrapper) has
  no test; the refusal text of a failed conversion from the bar cannot occur for a pipe table
  (F-TABLE-052, 053).
- Tab and the arrow keys between cells, row creation with Tab, the bar labels and the one-line-diff
  guarantee are not documented in README or CHANGELOG (only "keyboard navigation, row creation"); the
  stale "four-action" wording and a stale comment in `RTC` ("Escape commits like blur") should be fixed
  with the requirements.
- C-CL-097 and C-CL-100 are now cited by rendering-core and layout-width; C-CL-058 is kept here (F-TABLE-054).
