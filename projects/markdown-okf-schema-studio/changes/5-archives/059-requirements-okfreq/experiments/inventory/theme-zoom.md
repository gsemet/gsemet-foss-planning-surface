## Candidate StRS (use cases)

- UC-THEME-1: A reader sees the preview in the colours of their VS Code theme or in a forced theme
  and the preview follows the host when it changes.
- UC-THEME-2: A reader's theme choice is remembered for the workspace, applies at the next opening
  and is ignored safely when invalid or unsavable.
- UC-THEME-3: A reader picks Dark, White or Cream and every part of the page (band, toolbar, code,
  admonitions, tables, editors) uses that palette with readable contrast.
- UC-THEME-4: A maintainer can map the page colours to another host without touching the
  stylesheet (neutral tokens).
- UC-THEME-5: A reader enlarges or shrinks the text and column between 70 % and 200 % with
  buttons, and the zoom is remembered per workspace.

## Notable findings

- Nothing reads `data-sphinx-preview-theme` (host theme kind): high-contrast hosts have no
  specific rule and no test (F-THEME-008, 032).
- Only Cream has a contrast check (4.5:1); White and Dark are untested for contrast.
- 001 UX-45 (white leaves band and toolbar dark) is fixed by the token layer and locked by
  `creamTheme.test.ts`, but is still `[ ]` in the 001 index and absent from `RESULTS.md`.
- Host handlers for `previewThemeModeChanged` and zoom `previewViewPreferenceChanged` have no
  session-level test (read-only acceptance, persistence failure, invalid message dropped silently).
- The protocol validator accepts any integer zoom 70-200 while storage rounds to a multiple of 10;
  README does not state the 70-200 % range or the 10 % step.
