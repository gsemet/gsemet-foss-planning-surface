## Candidate StRS (use cases)

- UC-GFM-1: A writer pastes plain URLs and gets working links, without breaking code or existing
  links.
- UC-GFM-2: A writer uses GitHub Flavored Markdown (alerts, strikethrough, footnotes, tables) and
  sees it as GitHub would show it, in LF and CRLF files.
- UC-GFM-3: A writer ticks a checkbox in the preview and the source changes by exactly that
  character, undoable, refused safely when the preview is stale or read-only.
- UC-GFM-4: A writer uses the small raw HTML subset GitHub documents rely on (details, kbd, HTML
  tables, coloured spans) and nothing unsafe is rendered.

## Notable findings

- Colour grammars disagree: raw table styles accept colour names and `hsl()`, colour spans only
  hex/rgb/rgba; a colour span inside a raw HTML table loses its colour.
- Span-style removal is logged with the code `blocked-event-attribute`.
- Checkbox refusal reasons appear only as a tooltip; a malformed toggle leaves the box busy (no
  result posted); standalone previews say "Editing requires a trusted workspace".
- Host refusal paths of `previewCheckboxToggle` (stale, marker gone, edit open, read-only) have no
  host-level test; only the page revert is unit-tested.
- An alert glued to the next block (no blank line) adds one line to the parsed text: later source
  lines may shift by one (untested).
