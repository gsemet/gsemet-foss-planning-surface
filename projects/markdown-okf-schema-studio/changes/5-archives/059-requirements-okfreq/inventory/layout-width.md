## Candidate StRS (use cases)

- UC-LAYOUT-1: A reader opens a document with a wide table and the preview never scrolls sideways:
  the table scrolls in its own box, short identifiers stay whole and a cue shows there is more.
- UC-LAYOUT-2: A reader or team sets the width of the text column (any value from 0 to 2400 px,
  default 960 px) and every preview follows it, centred.
- UC-LAYOUT-3: Whatever opens the document (text, heading, table, picture, admonition, properties,
  empty page), in read or edit mode, it starts 40 px below the top and nothing clickable hides
  under the floating toolbar, also in a narrow pane.
- UC-LAYOUT-4: A reader switches between Margin, Auto and Full width with one button and the choice
  is remembered for the workspace.
- UC-LAYOUT-5: In Auto, tables, figures, images and code blocks wider than the text break out and
  stay centred and readable within the pane (and the TOC), narrower ones stay centred in the column.

## Notable findings

- `widthMode.ts` has no direct unit test file: all width logic is tested through the fake-DOM
  harness of `test/page/runtimePageControls.test.ts` (T10, T10b) and only in `scrollWidth` terms.
  Untested paths: `%`/`em`/`rem` figures, declared pixel widths, Mermaid wrapper, 1 px tolerance,
  reading-line preservation on a mode change, TOC open together with Auto in a real layout.
- The setting change on an open preview (F-LAYOUT-004) and `negative` or decimal inputs of
  `normalizePreviewContentWidth` are untested; the settings description states the 0 to 2400 range.
- Stale docs: README places the Width button on row 3, `widthMode.ts` header and CHANGELOG 0.1 say
  row 2; README "with the setting at 0 all three look the same" is not exact (Full keeps a 16 px
  gutter, the other modes up to 78 px).
- The 85 visual rows are mostly one assertion repeated across a fixture matrix (`v10..v65` are the
  first-gap rule, `v66..v83` three width-mode assertions); the distinct assertions are about a dozen.
  Several `v` titles (`v05`, `v06` "full") do not match what they assert.
- Narrow-pane exception (480 px) is a visual-test rule only; in code the decision is overlap with
  the toolbar plus a 320 px minimum frame width, so a 481 px pane with a long toolbar row could
  push too (not exercised).
- 001 UX-15 (wide tables wrap short identifiers) is fixed and locked by F-LAYOUT-027.
