`plantuml` command), on only with `plantuml.useJar` and a trusted workspace.

## Candidate use cases (StRS)

- UC-DIAG-1: A writer adds a Mermaid diagram to a document and sees it drawn in the preview, with
  its source one click away and the document otherwise unaffected.
- UC-DIAG-2: A writer sees diagrams in the colours of the active preview theme, readable in dark,
  light, white and cream, and still readable when the host gives no colours.
- UC-DIAG-3: A writer keeps typing without diagrams flickering or being redrawn when they did not
  change.
- UC-DIAG-4: A writer who makes a Mermaid syntax error sees one clear message and the reason, keeps
  the source, and the rest of the document continues.
- UC-DIAG-5: A writer inserts a Mermaid starter diagram from the palette or the slash menu and edits
  its source.
- UC-DIAG-6: A writer adds a PlantUML diagram as a fence or a directive and sees it drawn.
- UC-DIAG-7: PlantUML works out of the box, in Restricted Mode too, with no Java and no network, and
  the writer can switch to their own JAR or `plantuml` command in a trusted workspace.
- UC-DIAG-8: When the built-in engine cannot draw a diagram, the writer is told which directive and
  line, and what to do about it.
- UC-DIAG-9: A writer splits a diagram over local `.puml` files with `!include`, and the preview
  stays correct when those files change, within safe limits.
- UC-DIAG-10: A writer keeps a diagram in its own file with `{uml}` and sees helpful messages when
  the file is missing or out of bounds.
- UC-DIAG-11: In JAR mode, a failing, hanging, cancelled, missing or oversized PlantUML process
  never freezes or crashes the editor and always ends in a clear message.

## Notable findings

- `src/page/modules/mermaidPreview.ts` and `src/page/modules/plantumlPreview.ts` (the browser entry
  points) have no unit test. Theme colours, fallback colours, the draw queue, cache wiring, content
  patch handling and theme switches rest on the visual campaign (v01 to v16) and the real-VS Code
  scenario RI-T34 only (F-DIAG-005, 009, 019, 021, 027).
- Host-side PlantUML controller `src/session/features/plantUml.ts` has no test: the include answer
  (`handleInclude`), the deferred diagram injection (`apply`, code `plantuml-render`), the watcher
  notification and the settings change re-render are untested (F-DIAG-031, 034 host half, 050, 052).
- JAR pipeline gaps: a missing Java gives the `plantuml`-style message ("Set ... jarPath"), which is
  misleading; no code or message mentions Graphviz (non-sequence diagrams in JAR mode need `dot`);
  the 1 MiB source and 8 MiB output limits, a directory as `jarPath`, parallel diagrams and Windows
  kill are untested (F-DIAG-039, 042, 045, 047, 049).
- Visual v04/v05 (JAR success) fail unless `plantuml` is installed on the machine and are not
  driven through `useJar`; v06 "unconfigured" actually exercises a missing PATH executable. There is
  no Restricted Mode PlantUML visual scenario.
- UX-36 (diagram hidden while edited) and UX-46 (wide Mermaid scaled until unreadable) from the 001
  analysis are still open and absent from `docs/known-limitations.md` (F-DIAG-014, 015). The
  width-mode breakout list names `.myst-mermaid-diagram` but not `.myst-plantuml-diagram`.
- Diagram failures drawn in the page (Mermaid errors, built-in PlantUML messages) post no diagnostic
  to the status line or Problems; only JAR failures and `{uml}` file refusals do (F-DIAG-010, 024,
  036, 050).
- A previously configured `plantuml.jarPath` is ignored after the upgrade until `useJar` is ticked;
  documented in README and CHANGELOG, but no test checks the in-product hint beyond the setting
  description (F-DIAG-018, 053).
