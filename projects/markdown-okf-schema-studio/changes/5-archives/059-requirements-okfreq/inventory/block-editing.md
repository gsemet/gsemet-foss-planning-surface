## Candidate StRS (use cases)

- UC-BLOCK-1: A writer turns edit mode on and off from the preview, finds it as they left it, and cannot turn it on in a preview that cannot be edited (F-BLOCK-001, 002, 003, 077).
- UC-BLOCK-2: A writer edits the raw Markdown of any block in place, sees what a click will edit, keeps what they typed with autosave, and finishes with Done or Cmd/Ctrl+Enter or abandons with Cancel or Escape (F-BLOCK-004..021, 071, 073).
- UC-BLOCK-3: A writer types Markdown with the keys of a text editor: lists continue, Tab indents, selections wrap, Home and End, arrows between wrapped lines and neighbouring blocks, undo and redo stay in the editor, rich text pastes as Markdown (F-BLOCK-022..032).
- UC-BLOCK-4: A writer adds a new block between blocks or after the last one, and starts an empty document, from the preview alone (F-BLOCK-033..038).

## Notable findings

- **UX-35 (CRLF inline edits) looks still open.** The page cannot send CRLF from a `textarea`; the host keeps the
  LF `lastSavedText` and compares it with the CRLF slice VS Code writes, so the second autosave of a multi-line block
  of a CRLF document is refused. No test opens an inline editor on a CRLF block (F-BLOCK-071). Archive 001 lists it
  `approved [ ]`.
- **A refused open leaves a dead frame.** When the host refuses `previewEditOpen` (stale preview, read-only, another
  edit) the page shows the message but builds no text box, so Escape, Done and Cancel do not exist, and Refresh is
  disabled; only a later render or toggling edit mode off closes it. Untested (F-BLOCK-014).
- **Stale moves and clipboard requests get no answer.** The `render` gate drops them silently; the page only clears its
  flight after 5 s and shows nothing (F-BLOCK-041, 051). The host refusal text "out of date" is only for bad ranges.
- **Docs contradict the product.** `docs/known-limitations.md` and `docs/interaction-parity-evidence.md` still say the
  preview is read-only and that rendered-block editing is not claimed (F-BLOCK-076). README and CHANGELOG do not mention that
  edit mode is remembered per workspace, the 400 ms autosave, the typed-wrap of `*`/`_`/backtick/`~`, the stale and
  conflict messages, or the Enter-continuation rules.
- **Host controller paths without unit tests:** `trackOutsideChange` (STAB-06) through host events, `reportStaleEdit`,
  the apply-failure and "Another block is already being edited" messages, cut/paste "document changed meanwhile"
  refusals, and the block-editor variant of Home/End. The integration test `blockMove.test.ts` runs only when the
  screen is unlocked.
- Escape semantic changed: UX-01 (keep autosaved text) was replaced by archive 002/003 T3 (Escape = Cancel, restores
  the original). `RESULTS.md` of archive 001 still shows the old meaning.
- Visual locks v06, v07, v08 share one text (hover outline and editor layout) although v08 is named "insert point hover":
  the "+" button hover itself is only a step of the scenario, not a separate assertion.
