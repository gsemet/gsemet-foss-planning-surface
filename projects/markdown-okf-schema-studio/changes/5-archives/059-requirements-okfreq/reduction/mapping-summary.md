## How markers and tests follow each action

okfreq allows one marker per id per file, so merging tiles reduces marker *lines*. It never
reduces tests.

| Action | `@implements_req` | `@tests_req` | Test code |
| --- | --- | --- | --- |
| keep | Stays. If the survivor's marker sits at a file head (completeness audit D6), move it to the function. | Stays. | Unchanged. |
| fold-as-scenario, merge-into | Replaced by the survivor id. If the survivor already has a marker in that file, the line is deleted. Otherwise it stays, renamed, at its implementation point: one marker per implementation point of the tile. | Same: renamed, or deleted when the survivor is already marked in the file. The test becomes a named scenario of the tile, listed in its verification notes. | Unchanged. No test is merged or removed. |
| replace-by-crosscutting | Renamed to the cross-cutting id at the shared gate (`pageMessages.ts`, `pageToHost.ts`, `hostToPage.ts`, the handler preamble). Deleted where the gate is not in that file. | Renamed to the cross-cutting id, one per test file. The test is a row of the cross-cutting tile's table. | Unchanged. |
| drop-implementation-detail | Deleted. | Deleted. The test stays as a plain unit test. | Unchanged. |
| supersede (main) | Renamed to the survivor id, or deleted when already present. The superseded file gets `annotation_exemption: true` and `exemption_reason: "Superseded by <id>; no marker expected."` (precedent: commit c19ae3e). | Same. | Unchanged. |
| StRS merge / supersede | n/a | `@tests_req StRS-…` on integration, real-input and visual tests is renamed to the survivor and deduplicated per file. | Unchanged. |
