   - Cause: the edited `li` gets `display: none` from `[data-sphinx-preview-editing="true"]`, so it
     drops out of the list's numbering. Chromium numbers the items of an `ol` itself (its
     list-item ordinal), and it does not count a `counter-increment: list-item` on the editor
     host, which is a `div` and not a list item. So round 1's rule had no effect.
   - Fix, in `src/core/preview/styles/editModeStyles.ts`: `ol > li[data-sphinx-preview-editing="true"]`
     keeps `display: list-item`. It is collapsed instead (`visibility: hidden`, `height: 0`, no block
     margin, padding or border, `overflow: hidden`, all `!important`). The more specific selector
     wins over the generic `display: none !important`. The item still counts, and nothing of it
     shows: not its marker, not its content, and nothing in it can take the focus. `ul` items and
     every other edited block still get `display: none`. The ineffective counter-increment rule is
     removed, and the doc comment explains why.
