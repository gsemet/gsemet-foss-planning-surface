## Open points

1. LIFE-171 has no `@implements_req`: the brief asked to follow TRUST-001, but TRUST-001's manifest
   marker sits on the settings registry because that registry generates
   `restrictedConfigurations`; nothing in `src/` produces `agentsWindow`. An exemption with its
   reason was used instead of a marker on unrelated code. The reviewer may prefer another anchor.
2. Behaviour in the main window changes too: removing a workspace folder keeps the tab (read-only).
   The PR must say so for an external reader.
3. Edge cases deduced from the code, not tested: a preview with no document in a removed folder is
   still closed with its panel; a file of a removed folder that another workspace folder still
   holds moves to a session of that folder.
4. `onFoldersChanged` does not schedule the incoming-changes read for promoted sessions (as
   `onTrustGranted` does after a grant, when an untrusted workspace could not read them). In the
   Agents window the workspace is trusted, so it was not added; not verified with a test.
5. The integration change in `workspaceDisposal.test.ts` has not run in a real VS Code yet.
