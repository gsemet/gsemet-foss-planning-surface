## Findings

1. Non-blocking, tests: `test/host/lifeReq.requirements.test.ts` (new LIFE-143 test, ~line 528)
   removes the folder only after the render settled, and re-adds it after another 300 ms. Two
   claims of the spec/SwRS stay unproven by a test: "no late result reaches the panel" for a removal
   during a render, and a remove/add race. The code is correct by reading (guards above), but a
   regression would go unnoticed. Fix (follow-up acceptable): add a test that removes the folder
   while a render is held (the delayed-render pattern of `test/host/previewTiming.test.ts`) and
   asserts no post from the old session; and one that calls `setFolders([])` then
   `setFolders([workspaceRoot])` without advancing, asserting one live session, writable, same
   panel, panel not disposed, intermediate read-only session disposed. Optionally assert the
   Problems entry of the old session is cleared and re-published by the new one.
2. Non-blocking, untested LIFE-143 rows: "a file another folder still holds" and "a preview with no
   document" are documented as deduced from the code (honest, per guideline). A cheap test for the
   first (two folders, nested or duplicate, remove one) would turn them into tested rows.
3. Non-blocking, pre-existing but now frequent: `switchAfterFlush` (`src/session/previewManager.ts`
   ~line 385–392) captures the session; if a folder change replaces it while a follow-the-editor
   switch is flushing, the chain sees `session.disposed` and drops the switch target, so the side
   preview keeps the previous file until the next editor change. Likewise `demoteSessionsOf` does
   not flush open page editors before replacing (the old code closed the panel, so no regression).
   With the Agents window a session switch can coincide with an editor switch. Suggest a backlog
   item (re-dispatch the pending target on the replacement panel), not a fix in this CR.
4. Non-blocking, PR text: removing a folder in the main window now keeps the tab read-only instead
   of closing it (coder's open point 2); the PR description must state this for an outside reader.
