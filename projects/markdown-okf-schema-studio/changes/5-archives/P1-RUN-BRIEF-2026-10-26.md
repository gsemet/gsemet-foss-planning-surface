## Run rules (deviations from the guideline)

1. **At most 4 live drivers.** Start them in stack order; start the next CR when a driver returns.
2. **Drivers stop at step 7 + push.** A driver runs coder/reviewer rounds, commits (one commit,
   Conventional Commit, explicit paths, trailer `Assisted-by: Claude:Sonnet-5.5`, never
   Co-Authored-By), pushes its branch (`git push -u origin <branch>`), writes the PR body draft to
   `reports/PR-BODY.md` (external reader, Summary, Deliverables with before/after screenshots for UI
   changes, Autonomous decisions, Internal references last, ends with
   "🤖 Generated with [Claude Code](https://claude.com/claude-code)"), sets
   `status: ready · step: 7 Commit` and returns. It opens no PR.
3. **Stack driver** (one Sonnet agent, started when every CR is ready or blocked): in stack order,
   skipping blocked CRs, rebase each branch onto the previous one (first onto origin/main), resolve
   conflicts (same files adjacent by design), run `just check` on each rebased branch, then
   `gh stack init -b main <first>` / `gh stack add` adoption or open PRs and `gh stack link --base
   main <prs bottom→top>`. PRs are **ready, not draft**, body from `reports/PR-BODY.md`,
   screenshots pushed to `<branch>-assets` and linked by raw URL. Then watch CI in ≤5-minute
   slices; a product failure goes back to that CR as a new round (round limit 3 counts all causes),
   then `gh stack rebase` + `gh stack push` (`--force-with-lease` only after a rebase).
   Finally run heavy CI on the top branch: `gh workflow run ci.yml --ref <top branch> -f heavy=true`
   and wait for it. Never rename a branch of an open stacked PR.
4. **Never merge.** Never `git add -A` / `.`. No installs. `\rm \cp \mv`. Never touch
   `/Users/az02065/Projects/DevTools/agentic-planning-surface` nor the main checkout's untracked
   `.agents/skills/crf/` and `.claude/`.
5. **Window tests**: one CR at a time under `WINDOW-TESTS.lock`; caffeinate per guideline step 4.
6. **Blocked CR** (round 3 failed, or CR 121 not reproduced): `status: blocked` with diagnosis and
   a recommended answer; it stays out of the stack; continue the others.
