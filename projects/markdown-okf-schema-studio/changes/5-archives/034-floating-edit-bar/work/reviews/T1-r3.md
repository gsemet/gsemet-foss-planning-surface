## Platform notes (low, not blocking)
- Low, linkedTargetWatch.ts:24: on case-insensitive file systems (macOS default, Windows), a link resolved with
  a different case than the file on disk never matches `filename`. The VS Code watcher covers it. Optional fix:
  compare with `toLowerCase()` when `process.platform` is darwin or win32.
- Low: a target reached through a symlink is watched in the link's folder, not the real one, so a write to the
  real file is not seen directly. The fallback covers it. No action needed.
- Low: on Linux, if the folder is deleted and recreated (e.g. a git checkout), the inotify watch dies silently
  and is not re-armed until the target set changes. Same fallback. Acceptable for this fix.
- Windows: ReadDirectoryChangesW reports names and libuv opens the folder with FILE_SHARE_DELETE, so the
  folder can still be renamed or deleted. Each target gets its own fs.watch, and libuv shares the inotify
  watch per path on Linux, so many targets in one folder are cheap.
