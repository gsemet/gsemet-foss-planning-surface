# After source undos the preview table stays on the old shape while a cell editor is open

Severity Medium · Reproduced (twice, trigger not isolated) · Verdict Gap · Requirements: none found · Area Tables · Side preview · c3-2 · Replay `scenarios/271-c3-2-undo-after-column-deletes-leaves-preview-table-stale.json`

## Currently / Expected

| Currently | Expected |
| --- | --- |
| ![currently](../evidence/c3-2-currently.jpg) | The preview shows the buffer: the alignment table has 3 columns after the undos (no screenshot: same table, 3 columns, as in the Alignment block of the fixture; source: invariant, the preview mirrors the buffer). |
| Buffer is back to `| Left | Center | Right |` (diff against mark empty) but the preview shows a 1-column table with its cell editor still open, and the toolbar says column 1 of 1. | After Cancel it catches up (3 cols). |

## Why this is wrong

The author deletes columns with the toolbar, undoes from the source, and the preview keeps showing the old structure. Committing the open editor (Done) would act on a table that no longer matches the buffer; nothing says the view is stale. A second undo test with only two undos rendered correctly, so the trigger is the extra undo that reaches an edit outside the table while the editor is open.

## Steps to reproduce

1. Fixture `synth/structure-tables.md`, side preview, edit mode on.
2. Click cell `c1` of the Alignment table, click Col − twice (the third is disabled).
3. Meta+1, then Meta+z three times (the third also reverts a change elsewhere). Buffer equals the mark; the preview table stays at 1 column until Cancel is pressed.
Observed in two runs; the replay needs a prior edit elsewhere in the undo stack, otherwise it passes.

## Suggested direction

Re-render the table (and close or re-bind the cell editor) whenever the buffer changes under an open cell editor, not only on Cancel; or show a stale marker.
