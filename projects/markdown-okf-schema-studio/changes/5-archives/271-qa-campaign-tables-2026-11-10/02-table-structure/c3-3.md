| --- | --- |

| Clicking cell `qa` of a quoted table (or `na` in a Note) opens a raw block editor with the `>` prefixes; no toolbar, no handles. | A top-level table of the same page has handles and the cell editor (shot; source: in-product working case). |

## Why this is wrong

An author who documents data inside a quote or an admonition cannot add or move a row with the tools used everywhere else, and must edit pipes by hand with the `> ` prefix on each line. The tables look identical to the editable ones. It may be a known limit, but nothing says so and no requirement covers it.

## Steps to reproduce

1. Fixture `synth/structure-tables.md`, side preview, edit mode on.
2. Click cell `qa` (blockquote table) and `nb` (Note table).

## Suggested direction

Strip and restore the container prefix around the table model, as the list-table move already keeps container indentation (TABLE-002), or document the limit in the writing skill.
