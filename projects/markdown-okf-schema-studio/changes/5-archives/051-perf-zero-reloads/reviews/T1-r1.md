## Findings

### 1. major: a document switch with an unchanged page editor open freezes the preview

- **Where:** `src/extension.ts:4411-4447` (`switchPreviewDocument`, same-root branch), together
  with `src/extension.ts:1584-1596` (result deferral), `src/extension.ts:4487-4497`
  (`deferPageWork`) and the page's watch handler in `src/webview/scrollSync.ts:5287-5292`.
- **Scenario:**
  1. The preview follows the active editor. The reader opens an inline block editor, so
     `previewEditOpen` sets `editLock.pageEditorId`.
  2. The reader types nothing and switches to another Markdown file in the same workspace (or
     follows a preview link to one).
  3. `switchPreviewDocumentAfterFlush` calls `flushPageEdits`. The page's `postBlockEditSave(true)`
     sees unchanged text and runs `closeBlockEdit()` silently (`scrollSync.ts:2838-2840`). No
     watch was ever sent, so `reportClose` is unset and the host is not told.
  4. `switchPreviewDocument` sets `documentUri = B` and renders B. In `handleQueueState`,
     `shouldDeferResult()` is still true, so the result is deferred. `deferPageWork` posts
     `previewEditorWatch {documentId: B}`. The page still has `context.documentId = A` and
     ignores it (a new unit test even asserts "a watch for another document is ignored"). Any
     `previewEditClosed` would carry `documentId: A`, and the host gate at `extension.ts:4135`
     drops it.
- **Result:** the preview stays on document A behind the "Following the active Markdown editor."
  pending overlay until the reader presses Refresh. That is a user-visible regression (decision
  4). An editor opened and left unchanged is a common case.
- **Fix:**
  - Once the flush completed, every page editor is closed. In `switchPreviewDocument`, before
    `refreshPreviewDocument`, forget the page editor: drop the deferred `render-result` of the old
    document (`preview.editLock.drop("render-result")`), then
    `preview.editLock.closePageEditor()`, run the queued work, and clear `watchedPageEditorId`.
  - Belt and braces: in the `previewEditFlushed` handler, call `closePageEditor(preview)` when
    the page answers, because after a flush the page has no block editor open.
  - Add a unit or real-window test: open an editor, change nothing, switch the document, and
    expect the new document's content to reach the page.

### 2. minor: real-window typing still redraws 8 Mermaid diagrams once (coder's open point)

- **Where:** `src/webview/contentMorph.ts:47-52` and `:66`.
- **Problem:** the first page records its keys from the live document's `outerHTML`. Incoming keys
  come from a `<template>` parse of the patch HTML. When the host's diagram markup for the first
  patch differs from the initial page (for example a deferred enrichment pass or a resource URI),
  the blocks miss their key once. The result is still correct; this only costs speed.
- **Fix (round 2, optional):** log which attribute differs in the real-window probe, and normalise
  it or key on the host-sent block HTML for the first page as well.

### 3. nit: in-flight Mermaid renders under an older theme can overwrite a newer one

- **Where:** `src/webview/mermaidPreview.ts:98-125`.
- **Problem:** this predates the round. Two `renderDiagrams` passes (theme A, then B) can race,
  and A's `showImage` lands last. The cache now records B's key on the node, so the stale image is
  never corrected.
- **Fix:** before `showImage`, check `drawnKeys.get(diagram) === key`.

## Checked and fine

- **Edit lock release paths:**
  - `release` (assignment, final save, dispose) forgets the page editor.
  - `releaseHostEdit` (drain error, rebase conflict) keeps work queued while the editor shows the
    error.
  - Replaced and dropped deferred results dispose their stage.
  - A deferred result older than the page's stage is dropped.
  - `renderFollows` drops `render-result`.
  - Missing-source and dispose drop it too.
- **STAB-06:**
  - `rebaseBlockRange` is correct: changes ending at or before the start shift the block,
    overlaps conflict, and changes after the end are ignored.
  - A conflict posts an explicit error and the editor stays open.
  - A save that `matchesCurrentPreview` rejects now gets `reportStaleEdit` instead of being
    silently dropped.
  - An unsaved editor after an outside change gets "The preview is stale" from
    `currentSourceEdit`, which is an explicit error.
- **Keyed morph:**
  - `planKeyedMorph` pairs equal keys in order, at most once each.
  - New nodes record their key, and the fallback path re-records.
- **Mermaid cache:**
  - The key is `JSON.stringify([themeVariables, source])`.
  - `initialize` runs only on a theme-key change.
  - The LRU is bounded at 64.
- **Throttled state:**
  - A trailing timer writes the last state.
  - The pending state is flushed on `pagehide`/`visibilitychange`.
  - `getState` reads the pending state.
  - An unthrottled `setState` cancels the pending one.
  - `previewScroll` is never throttled.
  - The new test asserts the final `scrollTop` (35).
- **Changed existing tests:**
  - `scrollSync.test.ts` "caps sticky heading convergence at three passes" keeps its assertion

  - `sourceMapping.test.ts` replaces the inline-text check with three stricter checks: the
