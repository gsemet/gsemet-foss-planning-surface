## Round-1 findings

1. **major (document switch freezes the preview): fixed.**
   - `switchPreviewDocument` (`src/extension.ts:4443-4448`) calls `editLock.forgetPage()` and
     clears `watchedPageEditorId` before it renders the new document. `forgetPage`
     (`src/state/editLock.ts:64-69`) discards the queued work and runs each `discard`, so a deferred
     `render-result` frees its stage. It keeps `held`. Every deferred key (`render`, `theme-render`,
     `links`, `plantuml`, `plantuml-includes`, `render-result`) belongs to the old document. The
     new document renders with the current theme and config, so dropping them loses nothing.
   - **An edit the user is still typing in.** `forgetPage` runs only on a same-root switch, after
     the flush. That branch then calls `showPending(…, true)`, which assigns a status page and so
     destroys any editor on the page anyway. That was already true on a256ef9
     (`assignWebviewHtml` → `closePageEditor`). `forgetPage` drops no edit that would otherwise
     survive.
   - **A→B→A.** When the reader comes back before the switch runs (`extension.ts:4408-4414`), the
     host re-posts the watch by editor id. The page answers at once if the editor is gone. If the
     editor is still open (a refused-save error), it sets `reportClose` and answers when the editor
     closes, so that editor stays protected.
   - **Close by editor id only** (`extension.ts:4135-4139`). Edit ids embed the page's
     `context.requestId`, which comes from a monotonic `BuildQueue` counter, plus a per-page
     sequence. `closePageEditor` ignores an id that does not match. A stale close from an old page
     therefore cannot release a newer editor.
2. **minor (Mermaid redrawn once): fixed, and the root cause was found.**
   - `morphKey` (`src/webview/contentMorph.ts:44-53`) strips an `<a>` `title` only when it equals
     the `href`, which is exactly what VS Code's loader adds. It is applied to both the recorded
     key and the incoming key.
   - It cannot merge two different blocks. Serialised attributes always have the form
     `name="…"` with `"` escaped, so ` title="`/` href="` cannot match inside another value, and
     `data-title`/`data-href` cannot match either. `<abbr>`/`<area>` do not match `<a(\s…)?>`. A
     `>` inside a value only stops the strip, which costs speed and is not a wrong merge.
   - A title the host wrote that differs from the `href` stays in the key, so a genuine change of
     title is still seen (test at `test/webview/contentMorph.test.ts:31-38`).
3. **nit (Mermaid race): fixed.** Both `showImage` and `showMermaidError` are guarded by
   `drawnKeys.get(diagram) === key` (`src/webview/mermaidPreview.ts:121-126`). Passes are already
   serialised by `renderQueue`, so having no test for this is acceptable.

  round 1 and encodes the behaviour finding 1 removes. The replacement test
  (`test/webview/scrollSync.test.ts:3068-3083`) asserts the opposite, both for an open editor and
  for a closed one. This changes coverage to match the spec; it does not weaken a test.
- **Probe.** `asLoadedByVsCode` mirrors the loader's title insertion. `snapshotBlocks` /
  `rebuiltBlocks` are self-contained. The new `onlyTypedBlockRebuilt` criterion is stricter than
  before.
- **Caret loop** (`test/integration/performanceProbe.ts:147-153`). It runs inside `waitFor`, with a
  10 s deadline and a 25 ms poll, which is the harness's standard poll. It returns only when the
  extension host reports `selection.active` at the end. It presses the key again on each poll, and
  that press is idempotent at the end. This is a state wait, not a fixed sleep. The new
  `endsWith(TYPED)` assertion catches the round-1 probe bug.
- No inline `style=`, no new fixed sleeps, and no changes outside the task's files.
